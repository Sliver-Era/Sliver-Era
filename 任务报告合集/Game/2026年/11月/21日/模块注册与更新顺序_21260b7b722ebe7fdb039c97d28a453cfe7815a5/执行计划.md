# 执行计划 · 模块注册与更新顺序（第 4 轮）

> 工作区：`Application/Game/Sliver-Era` ｜ 分支：main ｜ 计划时间：2026-11-21

## 一、开发任务

为游戏应用建立最小模块契约与注册表，把输入、世界、实体、资源四个后续方向的空壳接上，固定「输入 → 世界 → 实体 → 渲染」的更新顺序。

- `src/框架/模块注册表.h`
- `src/框架/core/模块注册表.cpp`

修改：

- `src/框架/游戏应用.h`、`src/框架/core/游戏应用.cpp`

## 三、实现方式

1. `游戏模块` 接口：名称 / init / update / shutdown。
2. `模块注册表`：容量 8，正序初始化/更新、逆序关闭、重名拒绝、初始化失败逆序回滚。
3. 四个空壳模块：输入、世界、实体、资源；`new (std::nothrow)` 分配，应用持有所有权。
4. `游戏应用`：模块注册、固定顺序调度；`update` 转交注册表；`shutdown` 先关模块再回收渲染资源。
5. 渲染器初始化成功后即置就绪位，后续失败统一走 `shutdown`。
6. `--module-test`：校验初始化正序、更新正序、重名拒绝、关闭逆序。

## 四、分段执行

1. 接口与注册表。
2. 空壳模块与游戏应用接线。
3. 失败回收路径修正。
4. 模块自检。
5. Debug / Release 构建与四条自检。
6. 提交与文档同步。

## 五、验收口径

- 双配置构建零错误。
- `--module-test`、`--self-test`、`--state-test`、`--updates 120 --hidden` 均返回 0。
- 主循环不出现具体业务模块分支。
- 不修改 `external/Engine` 版本锁，不新增外部库。
