# 执行计划：依赖方向修正（方案 B）

- 分支：main
- 日期：2026-11-07
- 目标：移除 EngineSystem 对 EngineRenderer 的全部依赖（库、头快照、对外接口、`/FI` 锚点），
  改为 **EngineRenderer → EngineSystem** 单向依赖；把资源生命周期 / 粒子宿主 / 场景装配归还渲染层。

## 一、问题定位

当前 `Engine/EngineSystem/CMakeLists.txt` 通过 `byjy_jieru_xiaceng()` 接入 EngineRenderer
（库 + 头快照 + 版本锚点 `/FI`），源码中仅 7 个文件真正依赖渲染层：

| 文件 | 依赖内容 | 归属判断 |
| --- | --- | --- |
| `src/assets/资产缓存.h/.cpp` | `Renderer&`、`Mesh_Handle`、mesh/texture 加载卸载 | 资源生命周期 → 渲染层 |
| `src/effect/Particle/粒子模拟.h` | `Renderer&`、`粒子数据` | 粒子宿主 → 渲染层 |
| `src/effect/Particle/粒子GPU推进.h/.cpp` | `Renderer::impl`（friend） | GPU 推进 → 渲染层 |
| `src/scene/装配/场景装配.h/.cpp` | `Renderer&`、`Asset_Scene`、`scene_apply`、`mesh_draw_sections` | 资源创建 + 绘制登记 → 渲染层 |
| `src/scene/Level/关卡数据.h` | `Camera_Data / Light_Data / Fog_Data` | 纯数据 → 下沉系统层（见二） |

## 二、中立数据契约

- `Camera_Data / Light_Data / Fog_Data / Point_Light_State / Scene_Data` 由渲染层迁到
  `Engine/EngineSystem/src/scene/Level/场景数据.h`（纯数据，零图形 API），
  系统层 `Level_Data` 直接持有该系统层类型，不再 include 渲染层。
- 渲染层在原路径 `src/render/Scene/场景数据.h` 留**转发头**（承接系统层头，与
  `src/render/Mesh/网格数据.h` 的下沉承接方式同构），使 `渲染器.h`、`局部命名空间使用.h`
  与全部既有调用方零改动。
- 场景装配的中立面 = `Level_Data`（相机/光照/雾 ＋ 资产段落 ＋ 材质实例声明）＋
  `Scene_Manifest`（网格/材质库/摆放）＋ `level_transform_build`，全部由系统层产出、
  不含任何渲染层类型；渲染层消费它们并创建 `Asset_Scene`。

## 三、文件搬迁（系统层 → 渲染层）

| 原位置（Engine/EngineSystem） | 新位置（Engine/EngineRenderer） | 处理 |
| --- | --- | --- |
| `src/scene/Level/场景数据.h`（新） | `src/render/Scene/场景数据.h` | 原文件迁入系统层，渲染层留转发头 |
| `src/assets/资产缓存.h/.cpp` | `src/render/Asset/资产缓存.h/.cpp` | 整体搬迁，接口与语义不变 |
| `src/effect/Particle/粒子模拟.h` | `src/render/Particle/粒子宿主.h` | 整体搬迁，类名 `Particle_Host` 不变 |
| `src/effect/Particle/粒子GPU推进.h/.cpp` | `src/render/Particle/粒子GPU推进.h/.cpp` | 整体搬迁，`particle_gpu` 入口与 `friend` 留在渲染层内部 |
| `src/scene/装配/场景装配.h/.cpp` | `src/render/Scene/场景装配.h/.cpp` | 整体搬迁，函数名与语义不变（`level_bridge_*` / `scene_bundle_load`） |

搬迁后系统层删除空目录 `src/assets/`、`src/effect/Particle/`、`src/scene/装配/`。

## 四、构建脚本

1. `Engine/EngineSystem/CMakeLists.txt`
   - 删除 1.2 渲染层接入段（库映射、`byjy_jieru_xiaceng`、多配置库分配）；
   - 删除渲染层头快照段（调试/发布校验与 `BYJY_RENDERER_SNAPSHOT`）；
   - `BYJY_ENGINE_SYSTEM_INC` 只留 `[EngineFoundation 快照, 项目根]`；
   - `target_link_libraries` 去掉 `EngineRenderer`；
   - 顶部注释同步为「只依赖 EngineFoundation」。
2. `Engine/EngineRenderer/CMakeLists.txt`
   - 新增 1.6 系统层接入段：`BYJY_ENGINE_SYSTEM_LIB_PATH` 覆盖变量 ＋
     双配置映射（优先 `下层依赖/EngineSystem/x64-<配置>`，缺失回退
     `Engine/EngineSystem/out/build/x64-<配置>`）；
   - `BYJY_RENDERER_INC` 增加系统层头快照根（排在项目根之前）；
   - `target_link_libraries` 增加 `EngineSystem`。
3. `Engine/EngineRenderer/cmake/对外接口.cmake`
   - 并入 `EngineSystem/cmake/对外接口.cmake`（其内部已并入 Foundation）；
   - `OUT_INC` 改用系统层对外面，保留 Vulkan / SDL3 / VMA 追加项。
4. `Engine/EngineRenderer/CMakeLists.txt` 顶部注释更新依赖链为
   `EngineFoundation → EngineSystem → EngineRenderer → 应用层`。
5. 工作站 `构建双配置.ps1` 层顺序改为 Foundation → System → Renderer → Test；
   `刷新渲染层下层快照.ps1` 增加 EngineSystem 的快照同步（Debug / Release）。
6. `Engine/EngineSystem/README.md` 依赖链、链接面、版本锚点段落同步。

## 七、风险与对策

- **循环依赖**：Renderer 需要 System 的场景数据与关卡文本，System 不再需要 Renderer 任何符号；
  搬迁后不存在反向引用。
- **双配置混链**：Renderer 按 `CMAKE_BUILD_TYPE` 取同名类型的 System 库，跨配置由版次锚点拦截。
- **冻结快照陈旧**：首次构建时 `下层依赖/EngineSystem` 不存在，直接取 System 构建树（最新）；
  用户后续运行 `刷新渲染层下层快照.ps1` 即可冻结。
- **历史文档**：不改动既有任务报告与旧版项目导航。
