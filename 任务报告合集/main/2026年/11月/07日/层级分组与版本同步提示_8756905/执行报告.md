## 三、机制

### 3.1 层级归类

`TestInfo::file()` 返回 gtest 注册时记录的 `__FILE__`；CMake 以绝对路径传给编译器，故按路径片段归类：
`/tests/foundation/` → Foundation，`/tests/system/` → System，`/tests/renderer/` → Renderer，
`src/单元测试/` → 本层自测，其余 → Unknown（界面兜底分组，仍可运行）。

### 3.2 版本新鲜度

| 环节 | 来源 |
| --- | --- |
| 该层级构建时用的下层版本 | `tests/<子工程>/out/build/x64-<配置>/依赖版本.cmake`（本层自测为 `Application/Test/out/build/x64-<配置>/`） |
| 当前可用版本 | `Engine/版本锁.cmake` 的锁值优先；锁空则读 `Engine/<层>/out/build/x64-<配置>/include/Engine/<层>/版本锚点.h` 的 12 位哈希 |
| 判定 | 逐层比对：哈希不同或记录缺该层 → 待更新；当前版本未知（空）→ 该层不参与判定 |
| 记录缺失 | 直接按待更新处理（提示「缺少构建记录，请先重建 …」） |

`<配置>` 取本可执行文件的构建配置（`_DEBUG` → Debug，否则 Release）。

### 3.3 界面行为

- 待更新层级**单独置顶**，带「待更新」徽标与逐条原因（形如 `EngineSystem：测试库用 2f8c78abcabf，当前可用 9d9d9d9d9d9d`）；
- 首次读到待更新时**整层默认取消勾选**（隔离，避免误跑）；用户仍可手动勾选运行；
- 顶部常驻提示「N 个测试层级的下层库已更新，已在左栏隔离」；
- 「重新检测」按钮重读构建记录（重建子工程后点一次即可恢复）。
