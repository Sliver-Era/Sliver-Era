# 执行计划 · 渲染层独立与 EngineCore → EngineFoundation

> 用户裁定：渲染层目录与目标都叫 `EngineRenderer`；`EngineCore` 全局替换为 `EngineFoundation`（含测试层目录）；
> Game 的 `silver_era` 冻结快照同步改名；工作站只改活动脚本与项目内文档，历史报告不动。

## 一、目标结构

```
Engine/
├── EngineFoundation/        ← 原 Engine/EngineCore（含自身 .git）
├── EngineRenderer/          ← 原 Engine/EngineSystem/src/core/Renderer（含自身 .git）
├── EngineSystem/
├── cmake/
└── CMakeLists.txt / CMakePresets.json
```

依赖方向不变：`EngineFoundation → EngineRenderer → EngineSystem → (Engine 聚合) → Test / Game`。

## 二、分段

### 段 A：清理失效构建树

删除 `EngineFoundation`、`EngineRenderer`、`EngineSystem`、`Engine`、`Test` 的 `out/build`（缓存记录旧源码路径，迁移后不可复用；体积约 2.7 GB）。

### 段 B：目录搬迁与改名

1. `Engine/EngineCore` → `Engine/EngineFoundation`；
2. `Engine/EngineSystem/src/core/Renderer` → `Engine/EngineRenderer`，删除空的 `src/core`；
3. `Application/Test/src/单元测试/EngineCore` → `.../EngineFoundation`；
4. Game `external/silver_era`：
   - `include/Engine/EngineCore` → `EngineFoundation`
   - `include/Engine/EngineSystem/src/core/Renderer` → `include/Engine/EngineRenderer`
   - `lib/EngineCore.lib` → `EngineFoundation.lib`
   - `lib/RendererCore.lib` → `EngineRenderer.lib`
5. Renderer `下层依赖/EngineCore` → `EngineFoundation`，其内 `include/Engine/EngineCore` → `EngineFoundation`、`lib/EngineCore.lib` 改名。

### 段 C：全量文本替换

范围：项目内文本文件（`.cmake/.txt/.h/.hpp/.cpp/.c/.json/.md/.ps1/.py/.in` 与 `.gitignore`），
排除 `out/`、`build/`、`.git/`、`.vs/`、`third_party/`、`Dear_ImGui/`、`googletest/`。

替换顺序：

1. `Engine/EngineSystem/src/core/Renderer` → `Engine/EngineRenderer`
2. `Application/Renderer` → `Engine/EngineRenderer`（仅注释/文档）
3. `RendererCore` → `EngineRenderer`
4. `project(Renderer` → `project(EngineRenderer`
5. `BYJY_ENGINE_CORE` → `BYJY_ENGINE_FOUNDATION`
6. `ENGINE_CORE` → `ENGINE_FOUNDATION`
7. `engine_core` → `engine_foundation`（锚点符号与局部变量）
8. `EngineCore` → `EngineFoundation`

### 段 D：路径深度与相对路径手改

| 文件 | 改动 |
| --- | --- |
| `EngineRenderer/CMakeLists.txt` | 项目根上溯 5 级 → 2 级；归档包装器路径；下层依赖路径；锚点相对路径与镜像目录（已由替换覆盖，需复核） |
| `EngineRenderer/cmake/对外接口.cmake` | include EngineFoundation 接口的相对深度 6 级 → 3 级 |
| `EngineSystem/CMakeLists.txt` | Renderer 库/快照路径改为 `../EngineRenderer/...`、接口路径改为 `../EngineRenderer/cmake/对外接口.cmake`，并更新“迁入本层”的注释 |
| `Engine/cmake/对外接口.cmake` | `OUT_LIB` 与 `OUT_LIBDIR` 随替换更新（复核） |
| `Application/Test/CMakeLists.txt` | Renderer 路径/目标名随替换更新（复核） |
| 五层 `CMakePresets.json` | 无路径内容，无需改 |
| 工作站活动脚本 | `构建双配置.ps1` 层目录；`刷新渲染层下层快照.ps1` 路径 |

### 段 E：构建验证

按 `EngineFoundation → EngineRenderer → EngineSystem` 顺序构建 Debug + Release，再配置 Test 并构建 `TestGui`。
验收：零错误；库名 `EngineFoundation.lib` / `EngineRenderer.lib`；锚点符号为 `byjy_stamp_engine_foundation_*` / `byjy_stamp_renderer_*`；消费方 `/FI` 指向新路径。

### 段 F：残留检查

全仓 grep：`EngineCore`、`RendererCore`、`EngineSystem/src/core/Renderer`、`Application/Renderer` 均应为 0（排除 `out/.git` 与工作站历史报告）。

## 三、风险与已知项

- Test 全量构建仍受陈旧碰撞用例阻塞：改名后它们指向 `Engine/EngineFoundation/src/core/spatial/collision/...`，该目录不存在（碰撞模块在 EngineSystem）。属既有问题，本轮不修。
- Game 的快照二进制不重建，仅改名与改文本；其 `EngineFoundation.lib` 仍是无锚点的旧库。
- 各嵌套仓库的历史通过目录整体移动保留；不自动提交、不推送。
