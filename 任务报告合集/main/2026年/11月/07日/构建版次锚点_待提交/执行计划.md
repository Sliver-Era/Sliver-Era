# 执行计划 · 构建版次锚点（A2）

> 目标：把「头文件与静态库同版次」从人工约定升级为链接期强制约束；顺手清掉为弥补无版本标识而存在的猜测式机制。

## 一、方案要点（A2）

- 每层在构建期对**对外头集合**（与其头快照镜像范围完全一致）求内容哈希，哈希含构建配置与运行库口径。
- 由哈希生成两个产物：`版本锚点.h`（声明 `extern "C" void byjy_stamp_<层>_<哈希>(void)` 并强制引用）与 `版本锚点.cpp`（定义该符号）。
- `版本锚点.cpp` 编入本层静态库；`版本锚点.h` 随头快照发布。
- 上层通过导入目标自动 `#include` 该头（MSVC `/FI`，GCC/Clang `-include`），任何 TU 都会引用锚点符号。
- 结果：头集合或构建配置与库不一致 → 链接期 `LNK2019`，不需要运行期比较。

## 二、分段与验收

### 段 A：共享脚本

| 文件 | 改动 |
| --- | --- |
| `Engine/EngineCore/cmake/生成版本锚点.cmake`（新增） | 遍历镜像目录的 `.h/.hpp/.inl`，按相对路径排序后与内容、构建类型、运行库口径一起求 SHA256；生成 `版本锚点.h/.cpp`；内容未变时不写盘（保时间戳） |
| `Engine/EngineCore/cmake/导出头快照.cmake` | 新增可选参数 `ANCHOR_SRC` / `ANCHOR_REL`：把生成头复制进快照并纳入「有效头集合」，避免被失效清理删掉 |

验收：单独以 `cmake -P` 运行脚本两次，第二次不改变文件时间戳；改任一公共头后哈希变化。

### 段 B：EngineCore 接入

- 新增 `add_custom_command` 生成锚点（`DEPENDS` 全部公共头 + 脚本）。
- `版本锚点.cpp` 以 `GENERATED` 源加入 `EngineCore`。
- 快照目标 `add_dependencies(EngineCoreIncludeSnapshot EngineCore)`，并携带锚点头到 `Engine/EngineCore/版本锚点.h`。
- `cmake/对外接口.cmake` 新增 `BYJY_ENGINE_CORE_OUT_ANCHOR`。

验收：`EngineCore.lib` 中存在 `byjy_stamp_engine_core_*` 符号；快照根存在 `版本锚点.h`。

### 段 C：Renderer 接入

- 同一套生成 / 编入 / 快照携带流程，锚点相对路径 `Engine/EngineSystem/src/core/Renderer/版本锚点.h`。
- 对外接口新增 `BYJY_RENDERER_OUT_ANCHOR`。

验收：`RendererCore.lib` 含 `byjy_stamp_renderer_*`；编译日志中能看到 `/FI .../EngineCore/版本锚点.h`。

### 段 D：EngineSystem 接入

- 同一套流程，锚点相对路径 `Engine/EngineSystem/版本锚点.h`。
- 对外接口新增 `BYJY_ENGINE_SYSTEM_OUT_ANCHOR`；聚合层 `Engine/对外接口.cmake` 透传。

验收：`EngineSystem.lib` 含 `byjy_stamp_engine_system_*`；Test 编译日志中三条 `/FI` 齐备。

### 段 E：清理落后机制

| 项 | 位置 | 处理 |
| --- | --- | --- |
| 自动探测「时间戳最新」回退 | 四份 `cmake/接入下层.cmake` | 删除扫描与时间戳比较，改为「按当前配置的固定路径；缺失即 `FATAL_ERROR`」 |
| 跨配置快照回退 | EngineSystem L276-288、Renderer L268-288、Test L208-233 | 删除「用另一配置补齐」，两台配置都缺才失败 → 改为**同配置缺失即失败** |

验收：故意删除某配置快照时配置期直接报错，且报错信息指向「先构建对应配置」。

### 段 F：验证

1. `EngineCore` Debug + Release 构建零错误。
2. `Renderer` Debug + Release 构建零错误。
3. `EngineSystem` Debug + Release 构建零错误。
4. Test 层重新配置 + Debug 构建零错误。
5. 错配试验：手工把快照中的 `版本锚点.h` 改成错误哈希，重编任一下游目标 → 期望 `LNK2019`；试验后还原。
6. 受影响套件回归（Test 层）。

## 三、回退口径

- 所有改动仅涉及构建脚本与生成物，无业务源码改动。
- 若某层构建异常，删除对应 `add_custom_command` / `target_sources` 两段即可恢复原状；锚点头不参与业务编译语义。
- 覆盖变量 `BYJY_*_LIB_PATH` 保留，用于手工接另一棵树。
