## 二、关键设计

1. **静态库 + WHOLE_ARCHIVE**：跨构建树不能用 OBJECT 库；`$<LINK_LIBRARY:WHOLE_ARCHIVE,...>` 在 MSVC 下展开为 `/WHOLEARCHIVE`，保证全部用例 `.obj` 被链接。
2. **注册锚**：每个测试库提供 `extern "C" byjy_test_anchor_<层>()`，薄入口与主入口都调用；漏链测试库时链接期失败，而不是少跑用例。
3. **gtest 每 exe 一份**：子工程各自 `add_subdirectory(external/googletest)`；测试库只以 PRIVATE 链接 gtest（静态库的 PRIVATE 以 `$<LINK_ONLY:...>` 传递），不会把 gtest 目标编进库里。
4. **版本锁只读**：子工程只 `include` 版本锁，不写；锁空跟随构建树，锁非空取版本缓存；锁变化必须整套（三层 × 两配置）。
5. **薄 exe 落点**：产物落在 `Application/Test/` 根目录，与 `assets/`、`shaders/` 同级 —— 引擎环境按 exe 目录解析资源。

## 四、重开发要点（给后来者）

1. 先按依赖顺序构建 `EngineFoundation → EngineSystem → EngineRenderer`（Debug/Release 各自）。
2. 各测试子工程只读 `Engine/版本锁.cmake`；若锁非空，先用 `升级测试锁.ps1` 成套升级，或清空锁跟随最新。
3. 子工程配置必须显式给 `-DCMAKE_BUILD_TYPE=Debug|Release`（或用 presets）；空配置会导致无 `/O2` 且版本按 Debug 解析。
4. 主层配置前三个 `Test<层>.lib` 必须已存在；缺失时配置期报错并给出子工程构建命令。
5. 新增用例放进对应 `tests/<层>/src/` 即自动收编；若新用例需要新依赖，改对应子工程 CMakeLists 的链接行。
6. 改动 `引擎日志屏蔽` 仍改 `src/主调/引擎日志屏蔽.{h,cpp}`，但只由 TestFoundation 子工程编译。
