# 执行计划：测试层按被测层拆分（子工程 + 版本锁）

- 分支：main（Test 层）/ 2026-11-07
- 目标：把「唯一测试可执行」拆成「每个被测层一个独立测试子工程」，子工程只读全链版本锁、只链版本缓存里的同版次库；主测试层只链接子工程产出的静态库。
- 验收：下层改坏或未升锁时，其它层的测试子工程仍能独立构建并跑测；主全量入口仍可一次跑全部用例。

## 一、目录与目标图

```
Application/Test/
├── CMakeLists.txt                 主层：运行器 + 图形界面；链 3 个测试库 + gtest
├── cmake/                         主层构建片段（接入 / 资源 / 测试注册）
├── external/                      既有：Dear_ImGui、googletest
└── tests/
    ├── Foundation/                独立 CMake 工程
    │   ├── CMakeLists.txt         链 Foundation(锁版) → TestFoundation.lib + TestFoundation.exe
    │   ├── cmake/对外接口.cmake    自描述（OUT_LIB=TestFoundation）
    │   └── src/                   原 src/单元测试/EngineFoundation/** 迁入
    ├── System/                    链 System+Foundation(锁版) → TestSystem.lib + TestSystem.exe
    └── Renderer/                  链 Renderer+System+Foundation(锁版) → TestRenderer.lib + TestRenderer.exe
```

- 子工程**不是独立 git 仓库**，共用 Test 仓库；各自 `CMakePresets.json` 与 `out/build/x64-<配置>`。
- 用例迁移用 `git mv` 保持历史：`src/单元测试/<Layer>/** → tests/<Layer>/src/**`。
- 渲染层用例依赖窗口/资产，只放在 `tests/Renderer`；Foundation/System 用例不再接触 Vulkan/SDL。

## 二、子工程契约（每个子工程相同）

1. 包含 `Engine/EngineFoundation/cmake/版本工具.cmake`，用 `byjy_banben_jiexi_shuang()` 解析依赖：
   - 锁空 → 跟随最新构建树（开发期）；
   - 锁非空 → `Engine/版本缓存/<层>/x64-<配置>/<哈希>/{include,lib}`；
   - **只读** `Engine/版本锁.cmake`，不得改写。
2. 用 `byjy_jieru_xiaceng()` 链接依赖库，并传分配置库路径与分配置头快照根（与现有 Test 一致）。
3. 逐配置 `byjy_banben_hedui()`：被锁层构建时用的下层版本必须与本次解析一致（锁必须成套）。
4. 逐配置 `byjy_jiaoyan_xiacengtou()`：测试源码引用的下层头必须在快照里。
5. 产出：
   - `Test<Layer>.lib`（静态库，用例 + 注册锚）；
   - `Test<Layer>.exe`（薄入口，复用同一份测试库）。
6. 注册锚（解决静态库丢弃用例）：每个测试库提供 `extern "C" void byjy_test_anchor_<layer>();`，
   薄 exe 的 `main` 与主 exe 启动时都调用；漏链即链接期报错。
7. gtest 由各子工程自行 `add_subdirectory(external/googletest EXCLUDE_FROM_ALL)`（每个 exe 只链一份，避免重复符号；构建期重复编译可接受）。
8. 编译选项与 CRT 与各层一致（`/MP /utf-8`、`_CRT_SECURE_NO_WARNINGS`）。

## 三、主层改动

1. 删除 `src/单元测试/` 与 `EngineTestObjects`/`TestLauncher` 的测试编排块；主层只保留运行器、图形界面、资源。
2. 通过子工程的 `cmake/对外接口.cmake` + `byjy_jieru_xiaceng()` 链接 `TestFoundation/TestSystem/TestRenderer` 三个静态库（自动按配置定位）。
3. 主 exe 启动时调用三个注册锚（在用例外表枚举前），保证用例全部注册。
4. 保留版本锁解析（主层自己也要链引擎库）；主层与子工程读同一份锁。
5. 拆分 600 行 CMakeLists 为 `cmake/接入.cmake`、`cmake/资源.cmake`、`cmake/测试注册.cmake`，顶层只留参数与 include 顺序。

## 四、锁的成套升级与滞后告警

1. 新增工作站脚本 `升级测试锁.ps1`：读三层当前构建树的版本哈希，写入 `Engine/版本锁.cmake`（Debug/Release 各一套），打印 diff。
2. 各层配置期增加滞后告警：锁值 ≠ 当前构建树版本时 `message(WARNING "测试锁在旧版 …，当前最新 …")`，不阻断。
3. 文档：`Engine/版本锁.cmake` 头部与 Test README 写明「锁必须成套、只读、升级用脚本」。

## 六、风险与对策

- **静态库用例被丢**：注册锚强制引用；主 exe 与薄 exe 都必须调用。
- **gtest 重复符号**：每个 exe 只链自己的一份 gtest；测试库不内嵌 gtest 目标。
- **锁不成套**：依赖版本一致性校验会 `FATAL_ERROR`；脚本统一成套升级。
- **路径/资源**：渲染层用例仍按「exe 目录」找 assets/shaders，产物目录改造（P0）本轮不做，留给下一阶段。
- **构建顺序**：上层测试子工程需先构建被测层；缓存版本缺失时按现有错误提示处理。
