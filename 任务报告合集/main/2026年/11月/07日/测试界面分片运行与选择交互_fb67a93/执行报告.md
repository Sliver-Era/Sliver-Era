## 一、问题与根因

界面里勾选套件后点「运行」会"卡死"，根因有三层：

1. **整轮测试同步跑在渲染主线程**：主循环是"先跑测、再渲染"
   （`图形操作界面.cpp` 每帧 `poll_on_caller()` → `frame_render()`），
   而 `Test_Runner::poll_on_caller` 原先一次执行完整轮 `RUN_ALL_TESTS()`，
   跑完才返回。整轮期间不渲染、不抽事件、不重绘 → 系统判"未响应"，进度条也不动。
2. **默认全选被误读**：选择树建树时全部用例即勾选（1415/1415），
   点套件复选框实际是"取消勾选"，于是"勾选后运行"仍是近乎全量回归；
   且"全不选"被 `filter_string_build()` 兜底成 `"*"`，同样隐式全跑。
3. **碰撞用例的临时文件路径**：临时网格写到 exe 目录，却把相对路径交给网格加载器按 CWD 打开，
   CWD 不是 exe 目录时 3 条边界用例稳定失败（不是卡死，但同属排查中发现的缺陷）。

碰撞用例本身不慢：58 例约 100 ms，全量回归中 4 个碰撞套件合计 88 ms。

## 三、关键实现要点

### 3.1 为什么按"用例"分片而不是"按套件"或"开工作线程"

- 渲染用例必须回主线程：SDL3 要求事件泵在主线程，故不能整体丢到工作线程；
- 按套件分片仍会出现单套件（如 `Renderer_Scene_Test` 77 例、30 s+）长时间冻结；
- 按用例分片后，除**单条用例自身耗时**（如 `Renderer_Asset_Load_Test.异步加载失败` 约 35 s）外，
  界面保持逐帧可交互、进度逐帧前进。

### 3.2 分片执行与 gtest 语义

每条用例单独一次 `RUN_ALL_TESTS()`，即一次 gtest 迭代。已核对 gtest 源码（`UnitTestImpl::RunAllTests`
每次调用都会重新 `FilterTests`），可安全多次调用；全局测试环境每片 SetUp/TearDown 一次，
与"每条用例独立"语义一致，不引入顺序依赖。

实测迭代开销：`Particle_Data_Test.*` 5 例 × `--gtest_repeat=200`（共 1000 次迭代）总耗时 1013 ms，
含进程启动 → 约 **0.9 ms/次**，全量 1415 例约 **+1.3 s**，换取全程可交互，接受。

### 3.3 输出镜像

| 事件 | 处理 |
| --- | --- |
| 轮首 | `round_begin` 打印 `[==========] Running N tests from M test suites.` |
| 用例 | `[ RUN ]` / `[ OK ]` / `[ FAILED ]` / `[ SKIPPED ]` 保持控制台风格 |
| 套件 | 该套件首个用例处打印一次 `[----------] 套件名` |
| 轮末 | `round_end` 打印 `[==========] N tests from M test suites ran. (T ms total)`、`[ PASSED ]`、`[ FAILED ]` 及失败清单 |
| gtest 迭代 | `OnTestIterationStart/End`、`OnTestSuiteStart/End` 不再输出 |
