## 一、背景与问题

图形操作界面的「运行选中」把整轮 `RUN_ALL_TESTS()` 同步跑在渲染主线程上，
跑完才回到渲染循环：整轮期间窗口不重绘、不抽事件、进度条不动，Windows 判定「未响应」。
叠加两个交互缺陷后极易被当成死机：

1. 选择树默认全部勾选（1415/1415），点套件复选框是「取消勾选」而不是「选中」，
   于是「勾选后运行」实际仍是近乎全量回归（实测全量 10 分钟以上）；
2. 「全不选」被 `filter_string_build()` 兜底成 `"*"`，同样会全跑。

附带缺陷：碰撞用例把临时网格写到 exe 目录，却把相对路径交给网格加载器按 CWD 读取，
CWD ≠ exe 目录时稳定失败 3 条。

## 二、修正范围

### A. 运行器改为分片执行（核心）

- `Test_Runner::request_run` 的入参由「过滤串」改为「用例清单」（`套件.用例` 的字符串数组）；
- `poll_on_caller` 每帧只跑一个时间片（预算 8 ms，至少跑 1 条），跑完一个时间片即返回，
  渲染循环照常推进 —— 窗口保持响应、进度条逐帧前进；
- 每条用例单独一次 `RUN_ALL_TESTS()`（`GTEST_FLAG(filter)` 设为该用例全名，
  `GTEST_FLAG(repeat)=1`），退出码按「任一条失败即失败」聚合；
- 「停止」在分片之间生效：跑完当前用例即收尾本轮，不再排队；
- 保留「整轮」语义：本轮开始时清空本轮记录、结束时写入轮次历史。

### B. 输出镜像适配多次迭代

- 一轮内会调用多次 `RUN_ALL_TESTS()`，故迭代横幅由运行器经镜像显式打印：
  轮首打印 `[==========] Running N tests from M test suites.`，
  轮末打印 `[==========] N tests from M test suites ran.`、`[  PASSED  ] ...`、失败清单；
- `OnTestIterationStart/End` 不再打印（避免每条用例一行横幅）；
- 用例级输出（`[ RUN ]` / `[ OK ]` / `[ FAILED ]` / 套件分隔）保持原样。

### C. 选择交互修正

- 新增 `Test_Selection_Model::selected_cases()`：按勾选态输出用例全名清单；
- `filter_string_build()` 的全不选语义由 `"*"` 改为**空串**（不再隐式全跑），
  控制台菜单仍走自己的解析路径，不受影响；
- 「运行选中」与 Enter 快捷键：用例清单为空时不启动，界面给出红字提示；
- 套件行右键菜单：`只选此项` / `全选此项` / `清空此项`（解决「默认全选、点一下变取消」的歧义）；
- 「重跑失败」由失败用例构造清单。

### D. 碰撞用例临时文件路径

- `碰撞测试辅助.h` 的 `temp_mesh_write` / `temp_boundary_write` 返回值改为**绝对路径**（UTF-8），
  写入边界配置的 `mesh_path` 也用绝对路径；用例末尾清理同样按绝对路径删除。
- 效果：无论 CWD 是否为 exe 目录，3 条边界用例都成立。

### E. 用例

- 更新 `src/单元测试/Test/测试选择模型测试.cpp`：全不选改为断言空串；
- 新增 `selected_cases` 覆盖：整组全选、部分勾选、全不选。

## 五、风险与取舍

- 每条用例一次 `RUN_ALL_TESTS()` 会增加 gtest 迭代开销（估计 0.2～1 ms/条，
  1415 条约 0.3～1.5 s），换取界面全程可交互；接受该开销。
- 单条用例本身很长时（如 `Renderer_Asset_Load_Test.异步加载失败` 约 35 s），
  该条执行期间仍会冻结，属 gtest 单用例不可分割的固有粒度。
- 分片后全局测试环境每片都会 SetUp/TearDown 一次，与「每条用例独立」语义一致，不引入顺序依赖。
