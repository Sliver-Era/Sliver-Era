## 三、三后端职责与接口草案

### 3.1 Collider_Backend（几何与身份）

持有：堆上的 `Impl`（内含 `btCollisionObject`、部件集合、复合形状、身份标签、所属 Region 反向指针）。

**userPointer 定案**：指向**堆上的 `Impl`**（不是 `Collider_Backend` 对象本身）。
`unique_ptr<Impl>` 搬移后 Impl 地址不变，userPointer 天然稳定；反查走
`static_cast<Impl*>(object.getUserPointer())`，标签（编号 / 是否空间边界）存在 Impl 里。
移动构造即 `impl = std::move(other.impl)`，**不需要重设 userPointer**；移后源对象 impl 为空，析构需判空。

**生命周期定案（后端兜底 + 双向失效）**：
- `Impl` 存 `Region_Backend* owner = nullptr`。
- `Region_Backend::object_attach` 写入 owner 并登记到 `attached` 集合；
  `object_detach` 从世界摘除、清空 owner、移出集合。
- `Collider_Backend` 析构时若 owner 非空，自动调用 `owner->object_detach(*this)`，杜绝悬空。
- `Region_Backend` 析构先对 `attached` 全体摘除并清空 owner，再销毁世界。
- 由此两种析构顺序都安全；前端“先卸载再销毁”的旧契约保留，但不再依赖它。

接口草案（前端可见，全部为自有类型）：

```cpp
class Collider_Backend
{
public:
    Collider_Backend();
    ~Collider_Backend();
    Collider_Backend(Collider_Backend&&) noexcept;
    Collider_Backend& operator=(Collider_Backend&&) noexcept;
    Collider_Backend(const Collider_Backend&) = delete;

    //身份
    void tag_set(uint64_t collider_ID, bool is_boundary);
    uint64_t tag_ID() const;
    bool boundary_check() const;
    //几何
    bool geometry_build(const nlohmann::json& geometry_config, const Transform& base_transform);
    void geometry_clear();
    bool geometry_mounted() const;
    //空间
    void world_transform_set(const Transform& transform);
    Transform world_transform_get() const;
    void origin_advance(const Vector3& segment);
    void aabb_get(Vector3& aabb_min, Vector3& aabb_max) const;
    void static_flag_set(bool is_static);
private:
    struct Impl;
    std::unique_ptr<Impl> impl;
    //仅允许内部访问器结构接触 Impl
    friend struct Collider_Backend_Access;
};
```

**friend 收窄定案**：公共头只 friend 一个不透明结构 `Collider_Backend_Access`
（在 `Collider/backend/碰撞体后端_内部.h` 中定义），由它提供 `Impl&` / `btCollisionObject&` 访问器；
Region 后端 include 内部头即可。公共头不出现任何后端类名。

### 3.2 Region_Backend（世界与检测能力）

持有：配置 / 窄阶段调度器 / 宽阶段 / 碰撞世界、空间边界对象、`attached` 集合。

接口草案：

```cpp
//分段描述：由前端构造，后端据其内部循环推进
struct Collider_Move
{
    uint64_t ID;                 //碰撞体编号（用于输出碰撞对）
    Collider_Backend* backend;   //碰撞体后端句柄（前向声明即可，无需包含其头）
    Vector3 step;                //本帧总位移
    uint32_t step_count;         //分段段数
};

class Region_Backend
{
public:
    Region_Backend();
    ~Region_Backend();
    Region_Backend(Region_Backend&&) noexcept;
    Region_Backend& operator=(Region_Backend&&) noexcept;
    Region_Backend(const Region_Backend&) = delete;

    bool valid() const;

    //空间边界
    bool boundary_build(const std::string& mesh_path);
    void boundary_unload();
    bool boundary_mounted() const;

    //对象挂载（自动维护 owner 与 attached）
    void object_attach(Collider_Backend& backend);
    void object_detach(Collider_Backend& backend);
    void aabbs_refresh();
    bool object_contains(const Collider_Backend& backend) const;

    //扫掠：后端内部按 step_count 分段，返回命中标签编号（不含自身与边界）
    void swept_collect(const std::vector<Collider_Move>& moves, std::vector<uint64_t>& hit_IDs) const;
    //离散：后端内部按最大段数循环（逐段平移 + 检测），输出原始碰撞对与边界接触编号
    void discrete_run(const std::vector<Collider_Move>& moves,
        std::vector<Collision_Result>& pairs, std::vector<uint64_t>& boundary_contacts);
    //包含性：射线奇偶
    bool point_inside(const Vector3& point) const;
};
```

**依赖方向定案**：`Collider_Move` 只定义在 `Collision_Region/backend/空间后端.h`，
该头只前向声明 `Collider_Backend`，**不放进 Common**，不存在 `Common → Collider` 反向依赖；
也不使用 `void*`/`uintptr_t` 之类的隐式载荷。

**分段归属定案**：`swept_collect` 与 `discrete_run` 的循环在**后端内部**；前端只传 `Collider_Move` 列表。
前端保留：位移频率门控（决定哪些编号进入列表、`step` 与 `step_count` 如何算）、豁免过滤、跨越状态机。

## 五、数学类型方案

`Common/几何类型.h`（头文件内联，零 Bullet）：

- `using Scalar = float;`（段 A 以 `static_assert(sizeof(Scalar) == sizeof(btScalar))` 锁定前提）
- `class Vector3`：`x()/y()/z()`、`getX()/getY()/getZ()`、`setValue`、`operator + - * /`、`+=`、`length()`、`length2()`、`normalized()`、默认零向量。
- `class Quaternion`：`setValue(x,y,z,w)`、`x()/y()/z()/w()`、默认单位四元数。
- `class Transform`：`getIdentity()`、`setOrigin/getOrigin`、`setRotation/getRotation`、`operator*(Transform)`。

命名保持与现有 Bullet 别名一致（`engine::Vector3` 等），使 Region/Proxy 与测试调用点几乎零改动。

**转换函数过渡口径（避免与门禁冲突）**：

- 段 A：转换函数暂放 `Common/依赖库封装.h`（豁免文件），前端 core cpp 继续包含它，先保证编译与行为不变；
- 段 B：`Collider` 侧转换调用全部移入 `Collider/backend/core/`，前端不再出现转换调用；
- 段 C：`Region` 侧转换调用全部移入 `Region/backend/core/`；
- 段 E：把转换函数从 `依赖库封装.h` 拆到 `Common/数学转换.h`，`依赖库封装.h` 只剩头与别名；
  此时门禁只对 `*/backend/**`、`依赖库封装.h`、`数学转换.h` 豁免。

## 八、风险与对策

1. **检测语义回归**：后端拆分按“逐行对照 + 原注释保留”迁移；每段都跑碰撞套件，先立行为基线再动结构。
2. **对象生命周期（已定案）**：userPointer 指向堆上 Impl；Collider_Backend 析构兜底 detach；
   Region_Backend 析构先清 owner 再销毁世界，两种析构顺序均安全。
3. **头文件泄漏**：三后端 PIMPL；`*_内部.h` 只允许后端 cpp 包含；转换函数段 E 前暂留豁免文件。
4. **测试改写成本**：拆成段 B（碰撞体测试）与段 C（碰撞测试）两次，避免段 B 依赖尚未存在的 Region 后端。
5. **精度前提**：`static_assert(sizeof(Scalar) == sizeof(btScalar))` 锁定；若将来开 double，先改 `Scalar` 再谈转换。
6. **移动语义变化**：三后端 PIMPL 后，`Collision_Region` 移动只是 `unique_ptr` 搬移，边界对象地址稳定；
   现有“按值搬移后须重建边界”的注释将失效，需同步修正。目前无移动调用方。
7. **构建生成物**：两个 `源文件列表*.cmake` 是自动生成物，不手改；若配置未刷新，以 GLOB 结果为准核对。

## 九、不做的事

- 不改事件分类/标签、配置 JSON 字段与检测行为；
- 不改 CMake 结构，bullet3 仍编入 `EngineSystem.lib`；
- 不引入新第三方库；
- 不动 `effect/`、`entity/` 等其他未提交改动；
- 不提交、不建分支（提交时机等用户验收后决定）。

## 十、假设与待确认

1. 已确认 `collision` 公共头在 `EngineSystem` 内无其他模块引用（仅测试与自动生成的文件列表引用）；
   `碰撞系统运行包.h` 无任何源码消费方。
2. `Collider` 删除 `object/parts/compound/mounted_shape/recover` 是本次唯一的公共面破坏性变更；
   若工作区外还有其他仓库引用这些成员，需在动工前补充告知。
3. `Collision_Region` 的公开移动构造保留（安全化），不改为删除；若要求“禁止移动”，需另行裁定。
