## 一、任务目标与范围

### 1.1 目标

在 `EngineSystem` 新增一套 ECS（Entity-Component-System）基础设施，提供：

1. **实体**：轻量句柄（index + generation），可创建、销毁、存活校验；
2. **组件**：按实体编号存放/查询/删除，同一实体同一组件类型唯一；
3. **世界**：实体表 + 组件注册表 + 组件级遍历，销毁实体时级联清理组件；
4. **查询**：单组件遍历（阶段 1）与多组件交集遍历（阶段 2）；
5. **结构变更安全**：命令缓冲，允许在遍历中延迟销毁实体与增删组件（阶段 2）。

### 1.2 非目标（本期不做）

- Archetype / Chunk / SoA 存储（性能上限方案，另行立项）；
- 多线程 System 调度、依赖图、作业系统；
- 组件序列化、编辑器、网络同步；
- 替换现有输入/碰撞/世界模块，或改动 `EngineFoundation`；
- 游戏层 `星屑弹幕` 的迁移（其仍链接外部 SDK）。

## 二、设计基线（已确认）

> 已确认（2026-11-08）：模块位置、组件形态、交付范围按下表首列采用。

| 设计点 | 采用方案 | 备选 |
| --- | --- | --- |
| 模块位置 | `Engine/EngineSystem/src/world/ecs/` | 顶层 `src/ecs/` |
| 实体句柄 | `uint64`：低 32 位 index，高 32 位 generation，0 为无效 | `struct Entity{variant}` |
| 实体表 | 自持 `std::vector<Entity_Record>` + `Number_Pool<uint32_t>`（`set(1)` 预留 0） | 复用 `Object_Pool` |
| 组件池 | `Object_Pool<C, uint32_t>`，构造注入 `owner` 投影器（键 = 实体 index） | 自研 sparse-set |
| 组件约束 | 必须派生 `engine::Object`，含 `uint32_t owner`，可移动、可默认构造 | 去掉继承（需新存储） |
| 类型擦除 | `Component_Storage` 抽象基类 + `Component_Storage_Impl<C>`，注册表 `type_index → unique_ptr` | `std::function` 擦除 |
| 组件掩码 | `uint64` 位掩码，最多 64 种组件类型，首次注册分配 bit | `bitset` / archetype |
| 单组件遍历 | 遍历组件池有效区（`begin()/end()`） | 遍历实体表再查池 |
| 多组件查询 | 阶段 2：`ECS_Store::each` 双组件重载，遍历较小池 + 其余池 `find(owner)`（N 组件后续扩展） | archetype 匹配 |
| 结构变更 | 阶段 2：命令缓冲（延迟 destroy / component_add / component_remove；entity_create 立即执行），帧末 `flush` | 帧边界约定（无缓冲） |
| 系统调度 | 不提供（纯数据层；行为由普通函数/独立模块承担） | 命名系统 + `order` 调度（后续可选） |
| 错误处理 | 全链路无异常；返回 `bool` / 裸指针 + `logger` 告警 | — |
| 线程模型 | 非线程安全，单线程逻辑帧内使用 | — |

依赖边界：只依赖 `EngineFoundation`（`Object_Pool`、`Number_Pool`、`Log`），不依赖 `EngineRenderer`。

## 四、接口草案

### 4.1 `Entity`（`Entity/实体.h`）

```cpp
namespace engine
{
    struct Entity
    {
        uint64_t value = 0;                       // 高32位 generation / 低32位 index
        uint32_t index(void) const;               // 实体槽位
        uint32_t generation(void) const;          // 代际
        bool empty(void) const;                   // value == 0
    };
    Entity entity_make(uint32_t index, uint32_t generation);
}
```

### 4.2 `Entity_Table`（`Entity_Table/实体表.h`）

```cpp
struct Entity_Record
{
    uint32_t generation = 1;   // 代际，销毁后自增
    uint64_t mask = 0;         // 组件掩码（≤64 种）
    bool alive = false;        // 存活
};

class Entity_Table
{
public:
    Entity entity_create(void);                 // 复用或新增 index；generation 保留并自增
    bool entity_destroy(Entity e);              // 校验代际；清 mask；index 回收
    bool entity_alive(Entity e) const;          // alive && generation 相等
    uint64_t mask_get(Entity e) const;
    uint64_t& mask_ref(Entity e);
private:
    std::vector<Entity_Record> records;
    Number_Pool<uint32_t> index_allocator;      // set(1)，0 预留为无效
};
```

### 4.3 `Component_Storage`（`Component/组件存储.h`）

```cpp
class Component_Storage
{
public:
    virtual ~Component_Storage() = default;
    virtual bool erase(uint32_t entity_index) = 0;       // 内部 pool.try_unload
    virtual void clear(void) = 0;
    virtual std::size_t size(void) const = 0;
    virtual uint64_t bit_get(void) const = 0;            // 该组件在掩码中的位
};

template <typename C>
class Component_Storage_Impl final : public Component_Storage
{
    // 构造时注入投影器：[](const C& c){ return c.owner; }
    Object_Pool<C, uint32_t> pool;
public:
    C* find(uint32_t entity_index);
    C& emplace(uint32_t entity_index, C component);      // 已存在则失败
    bool erase(uint32_t entity_index) override;          // pool.try_unload
    void clear(void) override;
    std::size_t size(void) const override;
    // 遍历由 ECS_Store::component_each 通过 pool.begin()/end() 完成
};
```

### 4.4 `ECS_Store`（`Store/存储.h`）

```cpp
class ECS_Store
{
public:
    ECS_Store(void);
    ~ECS_Store(void);
    ECS_Store(const ECS_Store&) = delete;
    ECS_Store& operator=(const ECS_Store&) = delete;

    // 实体
    Entity entity_create(void);
    bool entity_destroy(Entity e);               // 级联：遍历注册表 erase，再回收 index
    bool entity_alive(Entity e) const;
    std::size_t entity_size(void) const;
    void clear(void);                            // 全部实体与组件清空

    // 组件
    template <typename C, typename... Args> C* component_add(Entity e, Args&&... args);
    template <typename C> C* component_get(Entity e);              // 非 const
    template <typename C> const C* component_get(Entity e) const;
    template <typename C> bool component_has(Entity e) const;
    template <typename C> bool component_remove(Entity e);         // 内部 try_unload

    // 遍历
    template <typename C, typename Fn> void component_each(Fn&& fn);      // 阶段 1
    template <typename C1, typename C2, typename Fn> void each(Fn&& fn);  // 阶段 2

private:
    Entity_Table entities;
    std::unordered_map<std::type_index, std::unique_ptr<Component_Storage>> storages;
    std::unordered_map<std::type_index, uint32_t> bits;   // 组件类型 → 掩码位
    uint32_t next_bit = 0;                                // ≥64 时注册失败
};
```

约束：`C` 必须满足 `std::is_base_of_v<Object, C>`、含 `uint32_t owner`、可移动、可默认构造；`component_add` 在未注册时分配掩码位，超过 64 种返回 `nullptr` 并 `logger.error`。

### 4.5 `View` / `Command_Buffer`（阶段 2）

```cpp
// 视图：迭代较小池，按 owner 查其余池
template <typename C1, typename C2>
class View { /* begin()/end() 或 each(fn) */ };

// 命令缓冲：遍历中只记录，帧末统一提交
class Command_Buffer
{
public:

    template <typename C> void component_add(Entity e, C component);
    template <typename C> void component_remove(Entity e);
```

## 八、风险与回滚

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 组件引用失效 | `Object_Pool::build` 可能扩容、`unload` 会 swap，指针/引用跨帧不可靠 | 文档约束“句柄跨帧、引用帧内”；阶段 2 命令缓冲 |
| 组件固定开销 | 16B `Object` 基类 + 4B owner（对齐后约 24B）+ 哈希表节点 | 接受现状；规模超限再上 archetype |
| 掩码上限 | 最多 64 种组件 | 注册时检测并告警；超限另案 |
| 代际溢出 | 同一 index 复用 2^32 次后回绕 | 概率极低，暂不处理 |
| 类型约束 | 组件必须派生 `Object`、含 `owner` | 模板 `static_assert` + 注释说明 |
| 单线程假设 | 注册表与池均非线程安全 | 注释明确“逻辑帧单线程” |
| `owner` 冲突 | 同一实体同一类型重复添加 | `component_add` 先查后建 |

回滚：本任务只新增 `src/world/ecs/` 与测试目录，不改任何既有文件；回滚即删除这两处目录并重建。
