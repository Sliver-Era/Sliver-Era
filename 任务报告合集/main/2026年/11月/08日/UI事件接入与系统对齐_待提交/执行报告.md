## 二、事件接入实现

### 新增：`src/render/UI/UI事件桥.h` + `core/UI事件桥.cpp`

`Ui_Event_Bridge` 是渲染层/UI 与系统输入体系的唯一事件接触面，持有 `Event_Terminal`：

出站（`frame_publish`）：

| 事件 | 时机 | 载荷 |
| --- | --- | --- |
| `Input/Raw` | 每帧 | 既有帧快照（位域键、`held`、指针、滚轮、文本、`text_mode`） |
| `Input/MouseFocus` | 左键按下沿 | `object` = 命中控件输入名 / UI 根名 / UI 外部目标名 |
| `Input/ModalPush` | UI 模态根变化 | `object` = 模态根输入名 |
| `Input/ModalPop` | 模态根清空或切换 | 空载荷，sender 固定 `Renderer_UI` |
| `Input/TextSession` | 系统文本模式 + 焦点文本框 | `text` 提交串、`preedit` 预编辑、`commit` |

入站（`frame_apply`）：

| 事件 | 处理 |
| --- | --- |
| `Input/FocusChanged` | 缓存 `main / child / modal / text`，映射为控件系统焦点环 |
| `Input/TextMode` | 缓存 `active`，决定 `text_route` 与平台文本输入启停 |
| `Input/Command` | 已绑定命令直接激活控件；未绑定入队供应用层 `ui_command_pop` |
| `Input/Text` | 焦点文本框消费；未消费入队供 `ui_text_pop` |

接入流程（`Renderer::input_system_attach` 委托）：

1. 事件桥在构造时自行绑定 `Port_ID::Evt_Receiver`；
2. 生成权限密钥，`Event_Terminal::attach("Renderer_UI")`；
3. 发送 `Subscribed_Events/Add`，订阅上述四类事件；
4. 应用层只需绑定 `Broker_Attacher` 与 `Evt_Sender`。

## 三、UI 控件树扩展

`用户界面.h` / `控件树.cpp` / `交互.cpp`：

| 能力 | API |
| --- | --- |
| 控件 ↔ 系统输入对象名 | `input_name_set / input_name_get` |
| UI 主对象 / 外部目标 | `input_root_name_set / input_outside_name_set` |
| 模态根 | `modal_set / modal_clear / modal_input_name_get` |
| 命令绑定 | `command_bind / command_unbind / command_dispatch` |
| 系统焦点映射 | `system_focus_apply / system_focused_get` |
| 系统文本落盘 | `system_text_apply` |
| 文本路由 | `text_route_set / text_route_get` |
| 本帧命中信息 | `pressed_input_name_get / press_any_get / press_outside_get` |

行为约定：

- `frame_begin` 在左键按下沿记录命中控件的输入名；未命中任何控件记为“按在 UI 外部”。
- 焦点文本框且已绑定输入名、系统文本模式开启时，`text_route` 为真；`text_edit` 跳过本地拼接，改由系统 `Input/Text` 回传落盘。
- 命令分发只激活 `Button`（点击回调）与 `Checkbox`（切换回调），不可用控件忽略。

## 六、已知边界

1. UI 输入对象需应用层 `Input/Create`；渲染层不自动创建，避免与游戏输入配置争夺所有权。
2. `Raw` 的 `text_mode` 会被焦点系统以自身状态覆盖；UI 文本模式以系统 `text_sink` 焦点为准，切换存在一帧延迟。
3. 模态仅单层；由 A 切 B 时先 `ModalPop` 再 `ModalPush`。
4. 未订阅 `Input/AxisState`；UI 暂不消费轴语义。
5. 系统焦点环与 UI 本地焦点环已收敛（见第八节）；未绑定 `input_name` 的控件只有本地焦点环，不参与系统焦点。
6. 焦点系统由应用层驱动 `frame_begin`；渲染层只收发事件，不持有焦点系统实例。

## 七、重开发指引

- 事件契约集中在 `UI事件桥.h` 的类注释；扩展事件只需在 `event_process` 与 `frame_publish` 两处增补。
- 控件级系统语义全部落在 `Ui_Context`，不依赖 Vulkan/GPU，可直接用于无 GPU 用例。
- 若系统新增输入事件，先在 `UI事件桥` 订阅表与 `event_process` 补分支，再补 `UI事件桥测试` 用例。
- 若调整帧顺序，必须保持「publish 在 apply 之前」，否则同帧命令/文本会延迟一帧。

## 八、双焦点收敛（系统焦点权威化）

### 问题

`MouseFocus` 是唯一的系统焦点写入口，只在左键按下时发送；Tab / 键盘导航只改控件本地焦点，不上报系统，导致：

1. 系统子焦点停在旧控件，橙色系统环与蓝色本地环分离；
2. 系统文本模式随旧焦点常开，切到按钮后平台文本输入未关闭；
3. UI 不在系统焦点时仍消费 Tab / 回车，与游戏对象争夺按键。

### 方案（单向写，系统权威）

```
UI 本地焦点变化 → ChildFocus(host=UI根名, child=控件输入名) → 焦点系统
焦点系统 FocusChanged → 回写本地焦点（同名可聚焦控件）/ 离开 UI 时清除本地焦点
```

关键约束：

| 约束 | 实现 |
| --- | --- |
| 只有命名控件参与系统焦点 | `ChildFocus.child` 取 `focused_input_name_get()`，无名控件返回空 |
| 请求在途时不跟随系统回写 | `pending_active` 期间跳过 `system_focus_sync`，防止系统一帧延迟把 Tab 结果顶回 |
| 系统超过两帧未确认视为拒绝 | `pending_age >= 2` 自动解除 `pending_active` |
| 鼠标帧不重复上报 | `press_any` 帧只同步记录 `last_focus_name`，焦点意图由 `MouseFocus` 承担 |
| 防止回声 | `frame_apply` 末尾把 `last_focus_name` 同步为当前焦点名 |
| 键盘总闸 | `keyboard_gate = (未配置根名 || focus_main == 根名)`，在 `frame_begin` 前由 `text_route_prepare` 设置 |

### 新增用例

1. `键盘总闸由系统焦点控制` —— 焦点在 Game 时 Tab 不动控件焦点，点击 UI 后总闸开启；
2. `Tab焦点上报系统子焦点` —— Tab 后系统 `current_child` 变为新控件；
3. `系统子焦点回写本地焦点` —— 外部 `ChildFocus` 使本地焦点跟随；
4. `系统焦点离开UI清除本地焦点` —— `MouseFocus(Game)` 后本地焦点清空且总闸关闭；
5. `未命名控件不参与系统焦点` —— 点击无名按钮只产生 UI 根级焦点，`current_child` 为空；
6. `焦点切到按钮关闭文本模式` —— 文本框 → 按钮切换后 `TextMode` 关闭。

### 验证

EngineRenderer Debug / Release 均 0 错误；`Ui_Event_Bridge_Test` 10 / 10；Renderer 全量 796 / 796。

### 仍存在的边界

1. 应用层若不创建对应 `Input/Create` 子对象，`ChildFocus` 会被焦点系统判为未知目标丢弃（属系统侧契约，非本层缺陷）；
2. 焦点系统确认延迟一帧，双环在切换瞬间仍会短暂错位一帧；
3. 系统拒绝请求时本层最多等待两帧才恢复跟随，其间本地焦点与系统焦点可能短暂不一致。
