# UI 事件接入与系统输入对齐 · 执行计划

## 目标

1. 对齐 EngineSystem 最新输入契约补强（位域键常量、repeat 边沿、指针滚轮、held 权威快照、模态归属）。
2. 渲染核心与 UI 系统正式接入事件系统：
   - 出站：`Input/Raw`、`Input/MouseFocus`、`Input/ModalPush/Pop`、`Input/TextSession`；
   - 入站：`Input/FocusChanged`、`Input/TextMode`、`Input/Command`、`Input/Text`。
3. 通过事件与 `Focus_System`、`Input_Manager` 交互，而不是直接持有其运行时对象。

## 阶段

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 复核系统桥与最新 `输入类型/事件` 契约 | Renderer Debug/Release 构建通过 |
| 2 | 新增 `Ui_Event_Bridge`（终端、订阅、出站/入站、状态缓存） | 无 GPU 用例可接入中转站 |
| 3 | UI 控件树扩展（输入对象名、模态、命令绑定、系统焦点、文本路由） | 控件级用例通过 |
| 4 | 渲染器接线（帧顺序、公共查询 API、退出清理） | 全量回归通过 |
| 5 | 事件桥端到端用例（焦点、模态、命令、文本会话） | 新增用例全绿 |

## 帧顺序约定

```
input.frame_advance
→ ui_event.text_route_prepare(ui)          // 按上一帧焦点 + 系统文本模式决定路由
→ ui.frame_begin(frame)                    // 命中 / 焦点 / 本地编辑
→ input.text_input_enable(ui文本焦点 || 系统文本模式)
→ ui_event.frame_publish(frame, ui)        // Raw / MouseFocus / Modal / TextSession
→ ui_event.frame_apply(ui)                 // FocusChanged / Command / Text 同帧生效
→ ui.draw
```

## 风险与约束

- UI 输入对象（`UI`、`UI.Text` 等）由应用层通过 `Input/Create` 创建；渲染层只负责绑定名与事件发布。
- `Input/Raw` 的 `text_mode` 由焦点系统以自身状态覆盖，UI 文本模式以系统 `text_sink` 焦点为准，存在一帧延迟。
- 模态归属固定为订阅者名 `Renderer_UI`，保证 `ModalPop` 校验通过。
- 事件桥含系统层头与 JSON，仅作为实现细节，不进入公共主头。
