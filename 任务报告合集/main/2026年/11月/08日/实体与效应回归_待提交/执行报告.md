## 四、关键实现细节

1. **演员 = ECS 实体 + 组件**：`actor_build` 立即创建实体并装配 `Actor_Info`（含事件终端与 `acl_key`），可选装配脚本；`actor_unload` 先解除碰撞体映射再 `entity_destroy` 级联清理组件。
2. **生命周期归调用者**：碰撞链路只产生通知与效应，技能实体销毁仅写入 `Command_Buffer`，由 `collision_step` 帧末 `flush`，与“碰撞系统从不销毁碰撞体”的既有约定一致。
3. **碰撞方向**：`collision_apply` 对同一碰撞对按 `A→B` 与 `B→A` 双向查表，避免碰撞体 A/B 顺序影响命中；未映射或已失效的碰撞体跳过并告警。
4. **效应唯一的属性通道**：`Effect_Dispatcher` 按属性键分派到类型化组件；未登记键回落到 `Attributes`（`string→double`）。`structural` 操作显式拒绝，要求玩法层经命令缓冲执行。
5. **持续效应**：`Effect_Instance` 以集合组件承载多条实例（ECS 单组件槽限制）；按 `tick` 累加结算，`remaining` 到期后清除记录，集合为空时移除组件。
6. **效应表**：JSON `pairs` → 32 位源/目标类型拼 64 位键；单条定义校验失败只跳过该条，`pairs` 非法时整体拒绝且不破坏旧表。
7. **Lua 事件出口**：脚本内 `send` 只把事件写入 `Script_State::outbox`；`script_step` 三遍执行（决策 → 收集 → 投递），投递阶段已脱离组件遍历，订阅方可在回调中安全创建技能实体。
8. **命名**：新增接口一律用 `build/load/unload`，不使用 `create/destroy`；ECS 既有 `entity_create/entity_destroy` 未改动。

## 五、与执行计划的差异（均为实现期必要调整）

| 计划 | 实际 | 原因 |
| --- | --- | --- |
| `effect_apply(ECS_Store&, Effect_Request)` | 增加 `Effect_Dispatcher` 参数 | 引擎核心不应硬编码具体属性组件，改由玩法层登记写入规则 |
| `Effect_Instance` 单条字段 | 改为“实例集合组件” | ECS 组件槽对同一类型每实体仅一份，无法直接承载多条持续效应 |
| `collision_step` 单函数 | 拆出 `collision_apply` | 便于用例直接注入 `Collision_Detail`，不依赖碰撞空间配置 |
| `Effect_Table` 经 `Config_Loader/Data_Validator` | 直接接收 `nlohmann::json` 并内部校验 | 保持模块无事件依赖，加载渠道由调用者决定 |
| 脚本绑定仅文件路径 | 增加 `script_source_bind` | 用例避免落盘脚本文件与中文路径编码问题，同时支持内嵌脚本 |

## 七、遗留与风险

1. `Collider_Index` 的反向映射只由 `actor_unload` / `link` 维护；若调用者绕过 `actor_unload` 直接 `entity_destroy`，索引会残留失效句柄。`collision_apply` 已用 `entity_alive` 兜底跳过。
2. `Effect_Instance` 到期后移除组件发生在遍历结束后，不会破坏遍历；若同帧内再次挂载同目标效应，需在 `effect_step` 之后执行。
3. 脚本 `send` 的 `std::function` 由调用者注入，引擎不持有 `Event_Terminal` 的接入状态；演员事件终端已随 `Actor_Info` 建立并生成 `acl_key`，接入中转站仍由调用者完成。
4. 效应叠加、冷却、驱散、优先级语义未实现，按计划归玩法层。
5. 尚未提交 git；任务目录保持 `_待提交` 命名，提交后可按规则改名为“功能_哈希值”。
