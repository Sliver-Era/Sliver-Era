## 一、任务目标

把历史的 `Entity` / `Effect` 两个概念从“垃圾堆”拉回来，落在新的 `ECS_Store` 数据层上：

1. **Actor（原 Entity，改名）**：一切可交互对象的统一身份；持有事件终端、脚本状态、组件数据；
2. **Effect（效应）**：一切属性修改的唯一通道；由碰撞/装备/技能/时间产生，可瞬时也可持续；
3. **Prop 不再回归**：属性由 ECS 组件承载，`Prop` 的 `string→double` 面板降级为可选的 `Attributes` 组件；
4. **AI 暂不重构**：继续使用 Lua（Sol2），每个 Actor 一份脚本状态，决策树仍写在 Lua 里；
5. **生命周期归调用者**：引擎只提供创建/销毁原语与通知，不自动销毁任何逻辑对象。

### 非目标

- 不做新的 AI 框架/行为树/GOAP；
- 不在引擎核心实现效应叠加、冷却、驱散、优先级等语义（归玩法层）；
- 不改碰撞模块的检测机制，只消费其 `Collision_Detail` / `DetectResult`；
- 不做 Archetype/SoA 性能改造。

## 二、与旧设计的对应关系

| 旧概念 | 新落点 | 说明 |
| --- | --- | --- |
| `Entity` | **`Actor`**（ECS 实体 + 组件） | 改名避免与 ECS 句柄 `engine::Entity` 冲突 |
| `Prop` | 属性组件（`Health` / `Position` / …）+ 可选 `Attributes` 组件 | `Prop` 类不回归 |
| `Prop_Effect` | `Effect_Instance` 组件 | 持续效应；瞬时效应用 `Effect_Request` 记录 |
| `Effect_Manager` | 普通函数 `effect_step(...)` + `Effect_Table` | 不设管理器类 |
| `Entity_Manager` | `actor_system`（普通函数/注册表） | 创建/销毁由调用者触发 |
| `LuaState` 决策树 | `Script_State` 组件（`std::shared_ptr<LuaState>`） | 保留现有 Sol2 基建 |
| `acl_key` / `distribute_key` | 模块边界的权限约定，不进 ECS 核心 | 组件访问由玩法层约定 |

## 三、设计基线（已确认）

> 已确认（2026-11-08）：原 Entity 改名 `Actor`；Actor = ECS 实体 + `Actor_Info` 组件；模块路径 `src/world/object/`；效应采用“瞬时 `Effect_Request` + 持续 `Effect_Instance` 组件”。

| 设计点 | 推荐方案 | 备选 |
| --- | --- | --- |
| 原 Entity 新名 | `Actor` | `Game_Object` / `Interactive_Object` / `Entity_Object` |
| Actor 形态 | **ECS 实体 + `Actor_Info` 组件**（单一身份） | 池化 `Actor` 类再持有 `engine::Entity` 句柄（双身份） |
| Actor 必备组件 | `Actor_Info`（类型/名称/事件终端）、`Script_State`（Lua）、`Attributes`（可选） | 事件终端放侧表 |
| 效应持久形态 | `Effect_Instance` 组件（source/target/kind/amount/remaining/tick/phase） | 只用瞬时 `Effect_Request` |
| 瞬时效应 | `Effect_Request` + 结算函数直接应用 | 也转成 1 帧组件 |
| 属性模型 | 类型化组件为主 + `Attributes`（string→double）为脚本补充 | 全字符串面板 |
| 效应表 | JSON：`[源 Actor 类型 × 目标 Actor 类型] → 效应定义列表`，经 Config_Loader/Data_Validator 加载 | 代码内注册表 |
| 碰撞接入 | 每帧 `Collision_Proxy::region_detect` 取 `Collision_Detail` | 订阅 `DetectResult` JSON 事件（简略） |
| 碰撞体映射 | 组件 `Collider_Link{ collider_ID }` + 反向表 | 全局侧表 |
| AI 执行 | `script_step` 遍历脚本组件，调用 Lua `decision` | 事件驱动脚本 tick |
| 销毁 | **调用者显式** `entity_destroy` / `collider_unload`；碰撞只发通知 | — |
| 结构变更 | 碰撞回调内只记录，帧末 `Command_Buffer::flush` | 直接改（禁止） |

## 四、核心接口草案

### 4.1 Actor

```cpp
// Actor_Info：Actor 的元数据与事件入口
struct Actor_Info : engine::Object
{
    uint32_t owner = 0;                 // 归属实体槽位
    uint32_t type_id = 0;               // 配置中的 Actor 类型
    std::string name{};
    engine::Event_Terminal event_terminal;
    int64_t acl_key = 0;
};

// 创建（立即执行，不进命令缓冲）
engine::Entity actor_create(ECS_Store& store, const Actor_Desc& desc);
bool actor_destroy(ECS_Store& store, Entity actor);
```

### 4.2 Script

```cpp
struct Script_State : engine::Object
{
    uint32_t owner = 0;
    std::shared_ptr<LuaState> state;    // 共享以支持拷贝/命令缓冲
    std::string entry = "decision";     // Lua 入口函数名
};
bool script_bind(ECS_Store& store, Entity actor, const std::string& path);
void script_step(ECS_Store& store, float dt);   // 普通函数，不是系统
```

### 4.3 Effect

```cpp
enum class Effect_Op { Add, Mul, Set, Toggle, Structural };

struct Effect_Request
{
    Entity source{};
    Entity target{};
    uint32_t effect_id = 0;             // 配置中的效应编号
    Effect_Op op = Effect_Op::Add;
    double amount = 0.0;
    std::string attribute{};            // Attributes 键；类型化组件走 effect_apply 分派
};

struct Effect_Instance : engine::Object
{
    uint32_t owner = 0;                 // 目标实体槽位
    Entity source{};
    uint32_t effect_id = 0;
    Effect_Op op = Effect_Op::Add;
    double amount = 0.0;
    double remaining = 0.0;             // 剩余时长（秒）
    double tick = 0.0;                  // 结算周期（0 = 立即）
    uint32_t phase = 0;
    uint32_t priority = 0;
};

void effect_apply(ECS_Store& store, const Effect_Request& request);
void effect_step(ECS_Store& store, float dt);   // 持续效应 tick
```

### 4.4 效应表与碰撞交互

```cpp
class Effect_Table
{
public:
    bool config_load(const nlohmann::json& config);   // 校验后加载
    // 返回 [源类型 × 目标类型] 对应的效应定义列表（缺失返回空）
    const std::vector<Effect_Desc>* pair_seek(uint32_t source_type, uint32_t target_type) const;
};

void collision_step(ECS_Store& store, Collision_Proxy& proxy, const std::string& region,
    const Effect_Table& table, Command_Buffer& buffer);
```

`collision_step` 流程：

```text
region_detect → 碰撞对( collider_A, collider_B, contacts )
  → Collider_Link 反查 Actor
  → table.pair_seek(source.type, target.type)
  → 生成 Effect_Request / Effect_Instance
  → 即时效应直接 effect_apply；持续效应加组件
  → 按表的“销毁规则”把技能实体销毁写入 Command_Buffer
  → 循环结束后 buffer.flush(store)
```

2. 效应表 JSON 加载与 `[源类型 × 目标类型]` 查询；

4. 测试：火球命中、销毁、冲锋闭环、碰撞对缺失 Actor 时跳过。

### 阶段 4：Lua AI 最小闭环（必须）

1. `script_step` 调用每个 Actor 的 Lua `decision`；
2. Lua 绑定：`entity`、`send`（事件终端）、组件读写辅助；
3. 测试：Lua 决策发送技能事件 → 技能实体创建（用 stub event broker）。

### 阶段 5：收口（可选）
