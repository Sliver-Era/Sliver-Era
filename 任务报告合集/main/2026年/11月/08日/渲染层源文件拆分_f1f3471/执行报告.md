## 三、阶段三：门面头多接口基类

1. `渲染器类型.h`：外提全部前置声明与配置 / 统计 / 资产类型（原 `渲染器.h` 1–519 行）。
2. `渲染器实现访问.h`：新增 `Renderer_Impl_Holder`（持有 `impl` 与门面自身指针 `self_ptr`，提供 `self()`）。
3. 14 个能力接口头 `渲染器_接口_*.h`，各自声明一类方法：
   `核心 / 计算 / 输出 / 网格 / 纹理 / 材质 / 管线 / 后处理 / 文字 / 场景 / 粒子 / 光照 / 风格 / 界面`。
   所有接口 `public virtual Renderer_Impl_Holder`。
4. `Renderer` 改为多接口组合体，仅保留构造声明；公共 API 与单类时期完全一致。
5. `渲染器.cpp` 的 354 处定义按声明归属改名为对应基类；跨接口调用统一经 `self()` 转发（脚本改写 + 编译器逐处校验）。

## 四、阶段四：实现体组合化

`渲染器实现.h` 的 `Impl` 改为 8 个聚合子结构继承组合：

| 子结构 | 单元数 | 大小 |
| --- | --- | --- |

- 采用继承式聚合而非成员式组合：`impl->成员` 与函数体内的无限定成员访问（共 2619 处）**一行未改**，全部由继承解析。
- 跨子结构常量 `POST_CHAIN_MAX_STAGES`、`PRESENT_TARGET_MAX` 外提到 `实现体_常量.h`。
- 嵌套记录类型（`Point_Light` 等）与静态常量保留在 `Impl`，保证 `Impl::X` 引用不变。
- 两个跨接口辅助 `spot_shadow_tiles_ensure` / `spot_shadow_atlas_apply` 改为自由函数 `*_impl(Impl*, ...)`。

## 五、阶段二：frame_render 阶段提取（已回退）

尝试提取两块纯 `{}` 阶段（光源矩阵 139 行、描述符集填装 115 行）；提取后编译通过，但 `Renderer_Decode_Test` 在纹理图像创建后卡死（等待 GPU 永久阻塞），单独运行该套件可稳定复现。回退提取后同一套件 1.2 秒通过，确认问题由提取引入（最可能是成员访问去 `impl->` 后与块内局部量同名，静默改绑）。

**结论**：阶段二不做机械提取。`frame_render` 保留原样（约 2060 行），阶段边界在代码中以 `①/④` 注释标注，后续需按阶段逐个梳理数据流后手工拆分。
