# 渲染层源文件拆分 · 执行计划

## 一、目标

`Engine/EngineRenderer/src/render/Renderer/core/渲染器.cpp` 已达 562.8 KB / 13522 行，单文件承载 379 个函数定义（公共门面 + 实现体 + 文件内辅助），属于异常体量。本轮按功能域拆分，**行为零改动**，并同步处理两个大头文件与 `frame_render` 单函数。

## 二、范围与决策

| 项目 | 决策 |
| --- | --- |
| 拆分范围 | `渲染器.cpp`、`渲染器.h`、`渲染器实现.h`、`命令录制.cpp`、`管线.cpp` |
| 门面头拆分方式 | 类型外提 + 多接口基类继承（用户选定） |
| 实现体头拆分方式 | Impl 改为组合子结构（用户选定） |
| `frame_render` | 按帧阶段提取为 Impl 成员函数（用户选定） |
| 收尾 | 重建项目导航 + 提交推送 |

### 阶段二：`frame_render` 按帧阶段提取

目标：把单函数拆成「取图与前置 / 场景数据上传 / 阴影 pass / 主 pass / 后处理 / 提交呈现 / 回读」若干 Impl 私有成员函数，共享局部量收拢到 `Frame_Render_Context` 结构。
验收：同阶段一，另加渲染帧用例与像素回读用例重点比对。

### 阶段三：`渲染器.h` 结构拆分

1. 外提 `Renderer_Config`、`Frame_Stats`、`Renderer_Resource_Counts`、`Material_Instance_Data`、`Asset_Object`、`Asset_Scene` → `渲染器类型.h`（`渲染器.h` 继续包含它，调用方零改动）。
2. 门面按域拆为多个能力基类（`Renderer_Core` / `Renderer_Compute` / `Renderer_Mesh` / `Renderer_Texture` / `Renderer_Pipeline` / `Renderer_Post` / `Renderer_Scene` / `Renderer_Lighting` / `Renderer_Particle` / `Renderer_Text` / `Renderer_Ui` / `Renderer_Style`），`Renderer` 公开继承全部基类；`impl` 与两个私有辅助函数上移到 `Renderer_Core`；`Renderer::Impl` 改挂 `Renderer_Core::Impl`。
3. 379 处定义按所属基类改名（脚本 + 编译校验）。
验收：同阶段一。

### 阶段四：`渲染器实现.h` 组合化

Impl 内按域建立子结构（平台 / 设备 / 内存 / 交换链 / 帧 / 资源 / 场景 / 绘制 / 文字 / UI / 粒子 / 统计 / 配置），成员声明分散到 12 个内部头；2619 处 `impl->成员` 按「最长名优先」脚本改写为 `impl->子结构.成员`，由编译器逐处校验。
验收：同阶段一。

### 阶段五：收尾

1. 重建本轮版次「项目导航」（按 `项目导航合集` 书写规则）；
2. 提交本地仓库并推送远程 `https://github.com/yuxingyuzhong/SilverEra`；

## 四、风险与对策

| 风险 | 对策 |
| --- | --- |
| 纯文本搬迁丢注释 / 断函数 | 边界按空行与函数起始行机械计算，搬后逐文件编译 |
| 头文件拆分导致调用方编译失败 | 类型头被 `渲染器.h` 包含，公共 API 不变 |
| 基类改名漏改 | 编译错误逐条定位，脚本按函数名清单批量替换 |
| Impl 组合改写漏改 | `impl->` 全部改写后编译，未识别成员全部报错 |
| `frame_render` 提取改变行为 | 每提取一阶段即构建 + 全量用例，最后重点看渲染帧/回读用例 |

## 五、验证命令

各层 `cmake --preset x64-Debug|Release` + `cmake --build --preset build-*`；用例 `Application/Test/TestRenderer.exe`。
