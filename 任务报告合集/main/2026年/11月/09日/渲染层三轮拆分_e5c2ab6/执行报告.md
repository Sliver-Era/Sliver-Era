## 四、关键决策与踩坑

### 4.1 `帧上下文.h` 用类体内 `.inl` 分片

类声明无法自然拆成多个头文件。采用「类体内 `#include` 分片」，调用方零改动、编译器全程校验。

分片后缀必须是 `.inl` 而不是 `.inc`：本层头快照导出脚本只镜像 `.h` / `.hpp` / `.inl`，`.inc` 不会同步到上层快照目录，上层编译会直接报「无法打开包括文件」。

### 4.2 `init` 只抽出一段

`init` 是单函数且含约 50 处 `self().shutdown()` 回退点。只把其中最长的一段（⑦~⑭：管线 / 描述符 / 采样 / 粒子 / 文字 / 阴影 / 后处理 / 天空）抽为 `renderer_init_graphics(Renderer* owner, Impl*, const Renderer_Config&)`，段内 `self().` 改为 `owner->`。其余阶段依赖 `effective`、`instance_extensions`、`swapchain_width/height` 等函数级局部量，继续切分需要重排初始化数据流，风险高于收益。

### 4.3 机械切分的两个坑

1. **输出文件名不能与源文件同名**：脚本先写输出再检查未归属，同名会先覆盖源文件，导致未归属函数直接从磁盘丢失。本轮 `目标创建.cpp` 中招一次（析构函数丢失），已用 git 恢复源文件并改用 `目标创建_构建.cpp`。
2. **函数之间的文件级 `static`**：不属于前导区，也不会被函数正则捕获，切分后落在所有分组之外。本轮需手工补回 3 个：`instance_matrices_append`（网格绘制）、`spot_shadow_tiles_ensure_impl`、`spot_shadow_atlas_apply_impl`（聚光阴影）。

### 4.4 lambda 捕获

阶段函数由成员函数改为自由函数后，块内 `[this, ...]` 捕获会编译失败（`C3482`），必须改为 `[impl, ...]`。
