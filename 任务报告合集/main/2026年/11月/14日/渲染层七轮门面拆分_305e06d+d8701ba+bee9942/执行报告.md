## 四、成员归位与 R1–R5 判定

| 规则 | 实际归位与冲突处理 |
| --- | --- |
| R1：生命周期管理者持有 | `Platform_Context`、`Device_Context`、`Memory_Context`、`Swapchain_Context`、`Frame_Context` 归设备域；`Shader_Context`、`Pipeline_Context`、`Mesh_Context`、`Texture_Context`、`Render_Target_Context` 归资源域；粒子 GPU 资源归粒子域；UI／字体／输入状态归界面域。 |
| R2：只读消费走窄上下文或公开接口 | 设备域创建并注入 `Render_Core_Context`；其余五域只持 `const Render_Core_Context*`，不复制核心模块指针副本。`config` 本身是 const 引用；跨域写操作必须经持有域公开接口，不开放通用字段访问器。 |
| R3：同数据只保留唯一写者 | 阴影开关、质量、级联与聚光请求归场景域；阴影管线、目标、图集实际生效态、pass 统计归设备域。逐物体材质参数归资源域；全局 PBR／Toon／描边用户参数归场景域。天空盒纹理与默认资源归资源域，天空绘制编排由设备域触发。 |
| R4：生效配置集中 | `Renderer_Config` 生效副本、MSAA／SSAA、窗口与输出配置归设备域；其它域经上下文读取配置，不另存可变配置副本。 |
| R5：帧内暂存归实际录制者 | `pending_items`、推送块、实例缓冲、剔除与后处理 scratch 归设备域的 `Device_Frame_State`；资源域仅保留描述符批量写输入 `draw_set_inputs`；计算与粒子各自保留本域资源整备暂存。 |

重点边界：

1. `bound_view`／`bound_sampler`／`bound_pipeline_request` 归资源域；设备帧路径通过资源接口完成描述符绑定，不直接写资源字段。
2. `active_target`、`present_target`、`post_chain`、`post_stage_*`、SSAA 目标与呈现链归设备域；离屏目标的创建、销毁、原生视图和采样数归资源域。
3. 通用计算缓冲与 Compute／Hi-Z／Cluster 能力归计算域；粒子状态双缓冲、发射／推进／绘制资源归粒子域，计算域不反向持有粒子配置。
4. 场景域只提出 `spot_shadow_atlas_requested` 用户请求；设备域记录 `spot_shadow_atlas` 实际生效状态与图集目标，关闭流程分别清理请求和实际资源，避免把“请求”误当“已生效”。

## 五、跨域窄接口与运行链

### 5.1 窄接口分组

- 设备域：`core_context()` 注入核心上下文；`mesh_single_prepare`／`mesh_instances_prepare`／`mesh_item_push` 收编网格帧项；`particle_item_push`／`particle_item_finish`／`particle_scene_buffers_bind` 收编粒子帧项；`shadow_*_handle`、`shadow_targets_*` 提供阴影值快照；`pipeline_unloaded`、`render_target_references_release` 供资源销毁前解除设备引用。
- 资源域：初始化／关闭、场景着色器与管线构建、`scene_*_bind`、`post_stage_bind`、`frame_descriptor_sets_fill`、`pipeline_rebuild`、原生资源查询、UI／字体资源装配及文字网格生命周期。
- 场景域：`frame_stats_fill`、`scene_initial_block_fill`、`scene_frame_block_fill`、`directional_shadow_frame_build`、`spot_shadow_frame_build`，以值快照向设备帧链供数。
- 计算域：初始化／关闭、统计填充、`options_apply`、Hi-Z／Cluster 的 ensure／destroy、原生缓冲与占位资源查询。
- 粒子域：初始化／关闭、统计填充、粒子 GPU／绘制资源 ensure／destroy。
- 界面域：初始化／关闭、`input_frame_advance`、`text_frame_advance`、`ui_draw_entry`、字体资源装配。

这些接口仍可能带生命周期或跨域语义，但不再提供“取整个 Impl／状态结构”的后门；调用方只能取得完成当前协作所需的值、句柄或原生标量。

### 5.2 构造、初始化、帧与关闭

- 构造：根先建设备域并取得核心上下文，再构造其余五域并注入 `owner` 与核心上下文；域构造只建立自身状态，不提前创建其它域 GPU 资源。
- 初始化：设备域完成平台、设备、内存、交换链、帧与生效配置；资源、计算、场景、粒子、界面按依赖顺序装配。失败沿用既有逆序回退与可重初始化契约。
- 帧链：根 `frame_render` 转发设备域。设备域主序为：输入与 UI 回调准备 → 关闭／最小化处理 → 窗口尺寸与交换链 → 相机宽高比 → 阴影矩阵与阴影 pass → 帧槽等待 → Cluster 帧更新 → 相机矩阵与文字帧推进 → 场景 UBO → 后处理／SSAA／天空准备 → 实例缓冲与静态合批 → 描述符与天空项 → `frame_stage_dispatch` 分派、呈现／离屏及回读 → 帧计数。跨域调用改走显式公开接口，不改变阶段语义。
- 关闭链：停止工作线程 → 已初始化路径归还阴影管线、目标与图集并清除场景图集请求 → 场景域关闭 → 粒子域关闭 → `frame.destroy()` 收口在途帧与延迟销毁 → 界面域关闭 → 资源域关闭 → 复位设备域输出与帧暂存 → 归还场景 UBO、实例、间接命令和 Cluster 缓冲 → 读取并写回管线缓存 → 计算域关闭 → 资源域 `pipeline_shutdown()` → 销毁交换链、内存、平台和设备 → 清空待绘制项并复位 `initialized`。各关闭入口保持幂等。

## 六、MSAA 同步修复

MSAA 现行有两条必须同时成立的链：

1. `core/渲染器_初始化_内存与交换链.cpp` 先以单采样建链，取得颜色／深度格式后按设备共同支持上限钳制请求；启用 MSAA 时重建交换链，最终写入 `Device_State::msaa_samples = swapchain.sample_count_get()`。
2. `core/渲染器_资源.cpp` 在 `Render_Resource::init` 末尾补入 `render_target.sample_count_set(core->swapchain.sample_count_get())`，使离屏目标默认采样数与已择定交换链一致。此前这里会保留渲染目标默认 1×，导致交换链 MSAA 与离屏目标采样数不一致。

运行时 `Render_Device::msaa_samples_set` 除更新交换链外，还调用 `owner->resource().render_target_sample_count_set(samples)` 并重建图形管线，随后同步 `Device_State` 与生效配置、重绑默认纹理。失败语义不是统一回滚：**交换链重建失败会恢复旧采样数并返回；渲染目标或图形管线重建失败仅告警，后续仍记录新采样数。**该修复不能只记录设备域的 `state.msaa_samples` 赋值，否则遗漏资源域的关键一致性修补。
