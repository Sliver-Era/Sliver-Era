## 一、目标

补上方向九长期顺延的 AgX 算子：与逐通道算子（ACES / 胶片 / 指数）不同，AgX 的**彩色高光会去饱和**，
可避免强光下红/蓝灯变成纯色块。本轮以工程近似实现，接入 `hdr_tone_operator = 4`。

## 二、实现

- 新增 `Engine/EngineRenderer/assets/shaders/AgX色调映射.frag`：
  AgX 输入矩阵（Rec.709 → AgX 宽色域近似）→ 逐通道白点归一压缩 `x / (x + 0.9)` → 输出矩阵回 Rec.709。
- `post_pipeline_ensure` 增 `case 4`；`hdr_tone_operator` 合法范围 0..4，越界归 0。
- 着色器经 CMake 配置期编译 `.spv` 并拷贝到 Test；新增文件后**必须重配** Renderer / Test 子工程（已执行）。

## 三、实测数据（纯红四边形 + 曝光 +2，线性 4.0 红；交换链 BGR 序）

| 算子 | 中心像素（B/G/R/A） |
| --- | --- |
| 0 · ACES | **0 / 0 / 252**（纯红高光，非红通道为 0） |
| 4 · AgX | **99 / 99 / 245**（非红通道显著抬升，红通道仍为亮部） |

断言：ACES 非红通道 ≤ 5；AgX 非红通道 ≥ 60 且 `AgX[1] ≥ ACES[1] + 30`；AgX 红通道 ≥ 200。

## 五、过程教训

- 新增 `.frag` 后必须**重配**（不止构建）：Renderer 配置期编译 `.spv`，Test 主工程配置期把 `shaders/` 整体拷贝过去；否则运行期找不到 `AgX色调映射.frag.spv`。
- 交换链为 `B8G8R8A8`，测试里「红色」在像素数组的 index 2；按视觉通道断言会误判，需按实际通道序写。
- 本轮为**工程近似 AgX**（非官方 LUT 逐位一致），已在着色器头注释与导航中标注；后续如需严格对齐，可换用官方 LUT / 多项式拟合。
