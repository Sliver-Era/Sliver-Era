# HDR 默认路径 · UI 显示域混合（方向九第 758 轮）· 执行报告

## 一、目标

757 让默认路径经过 16F + 色调映射；本轮验证并**守卫**「UI 必须在色调映射之后（显示域）绘制」，
避免未来把 UI 挪进 HDR 目标导致颜色被二次映射。

## 二、用例设计（`渲染后处理链测试.cpp` 新增 `HDR默认路径UI不被色调映射`）

- UI 回调以固定色 `(0.55, 0.30, 0.12)` 清屏整帧（复用第六百三十九轮的 `ui_clear_frame`）。
- 同一场景分别以「关闭 / 开启 `hdr_targets`」各出一帧，取中心像素逐通道比较。
- 判定：若 UI 在末级之后绘制，两帧 UI 像素应一致；若 UI 被画进 16F 目标，会经 ACES 压缩产生明显偏移。

## 三、实测数据

| 配置 | UI 中心像素 |
| --- | --- |
| 关闭 `hdr_targets` | **97 / 149 / 196 / 255** |
| 开启 `hdr_targets` | **97 / 149 / 196 / 255**（逐通道完全一致） |

## 六、结论

- HDR 默认路径下 UI 仍绘制在交换链（显示域），颜色不受色调映射影响 —— 两帧逐通道完全一致。
- 该结论由用例固化为回归守卫：若后续把 UI 提前到 HDR 目标内，用例会立即失败。
