## 一、目标

756 只让「按默认格式创建离屏目标」返回 16F；本轮把 HDR 接入**默认帧路径** ——
即使调用方不设置任何目标，`hdr_targets` 开启时场景也写入内部 16F 目标，再由内置色调映射级呈现到交换链。
默认关闭时与引入前逐字节一致。

## 三、链路

1. `frame_render` 取客户区尺寸 → 若 `hdr_targets && present_target == 0 && active_target == 0`，`hdr_scene_ensure` 建立 / 复用 16F 场景目标。
2. `effective_present_target = hdr_scene_target` → 走既有「单级默认后处理路径」：场景 pass 写 16F 目标，再由内置后处理级呈现到交换链。
3. 内置后处理片元在 `hdr_targets` 开启时选 `色调映射.frag.spv`（否则维持 `后处理.frag.spv`）。
4. 场景管线按 `scene_color_format()` 烘焙（16F），动态渲染的 `colorAttachmentFormat` 取目标自身记录，二者一致。
5. 尺寸变化：`hdr_scene_ensure` 等尽在途帧后重建；建立失败置 `hdr_scene_failed` 并回落原路径。

## 六、过程教训

- `Renderer_Config::hdr_targets` 必须在**管线烘焙之前**落位（阶段函数内要读），否则场景管线仍按交换链格式烘焙，HDR 路径首帧即格式不匹配。
- `render_target_frame_full_get` 此前不填格式、分派段硬编码交换链格式；16F 目标必须改为「取目标自身记录，缺失再回落」，否则动态渲染的颜色附件格式与视图不一致。
- ACES 在 [0,1] 区间近似线性，因此「是否经过色调映射」在画面上的差异很小（4.0 时 255 → 252）；断言取方向性差值（≥2）而非大幅差，后续如需更强区分应换用暗部压缩更明显的算子。
