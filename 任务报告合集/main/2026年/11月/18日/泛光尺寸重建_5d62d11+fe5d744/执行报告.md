验证 761 的自动泛光链在窗口尺寸变化后仍完整可用。

## 三、顺带修复的真实缺陷

排查中发现每帧一条 Vulkan 校验错误：

```
vkCmdDrawIndexed(): VkRenderingInfo::pColorAttachments[0].imageView format (VK_FORMAT_B8G8R8A8_SRGB)
must match ... VkPipelineRenderingCreateInfo::pColorAttachmentFormats[0] (VK_FORMAT_R16G16B16A16_SFLOAT)
```

原因：HDR 默认路径把管线上下文的全局颜色格式设为 16F（供场景 pass 写 16F 场景目标），
而末级呈现管线（色调映射 / 直通）**始终直接写交换链**。`post_pipeline_ensure` 原先把颜色格式留空（跟随全局），
于是末级管线按 16F 烘焙却画到 8 位交换链上，属未定义行为（驱动容错才侥幸正确）。

修法：末级管线显式按 `swapchain.format_get()` 烘焙。非 HDR 路径下全局格式本就等于交换链格式，登记结果不变。

## 六、环境教训

- 构建报 `cl: 命令行 error D8050：无法执行 c1xx.dll`（连续两次）—— 原因是 `TMP/TEMP` 指向含中文的用户目录
  （`C:\Users\终焉\AppData\Local\Temp`）。构建前把 `TMP/TEMP` 指到 `C:\Temp` 即恢复。
- Release 与 Debug 主工程输出同名 `Application/Test/EngineTests.exe`；跑完 Release 后须删除该 exe 再重链 Debug，
  子测试树 `TestRenderer.exe` 同理（ninja 会因时间戳更新而认为无需重链，须先删除）。
- 泛光类用例的判读须锚定「核心亮区边界」，不能用固定像素或 < 100 扫描阈值。
