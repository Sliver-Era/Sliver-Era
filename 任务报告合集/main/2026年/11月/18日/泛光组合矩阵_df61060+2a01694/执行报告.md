## 一、矩阵用例发现的真实缺陷

六组合首跑即失败：**开泛光时主体比不开更暗**（中心 **252 → 232**，差 20）。

根因：`泛光叠加.frag` 结尾是 `clamp(scene + bloom, 0, 1)`。HDR 链路上场景高光约 4.0，
叠加后被上钳到 1.0 再送色调映射，于是 ACES(1.0) = 232，反而低于不开泛光时的 ACES(4.0) = 252 ——
**泛光把高光吃掉了**。

修法：改为 `max(scene + bloom, 0.0)`，只钳下界。线性高光保留到宿主格式：
- 16F 宿主：高光完整保留（本轮实测中心 255）；
- 8 位宿主：写入时由格式转换自然饱和，行为与原先一致。

## 五、环境教训（着色器同步）

- Renderer 的 `.spv` 是**构建期**目标（`RendererShaders`），改 `.frag` 后必须**构建** Renderer 才会重编译，仅重配不够。
- Test 主工程在**配置期**用 `file(COPY …)` 从 Renderer 构建树拷贝 `shaders/`，且优先取 Release 树 ——
  若 Release 树的 `.spv` 是旧的，会把旧着色器拷进 Test，导致「改了却看不出效果」。
- 正确顺序：改 `.frag` → 构建 Renderer（Debug / Release 都要）→ 重配 Test 主工程（拷贝）→ 构建 Test。
- 本轮首次复跑仍差 20 正是此因（Test 的 `shaders/泛光叠加.frag.spv` 时间戳停在 11-07）。
