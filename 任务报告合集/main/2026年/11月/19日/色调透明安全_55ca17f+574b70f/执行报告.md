# 逐材质色调算子 · 透明材质安全化（第 780 轮）· 执行报告

> 日期：2026-11-19
> 代码版次：Renderer `55ca17f` / Test `574b70f`（均已推送）

## 一、问题

779 的逐材质色调算子把编号写进 **16F 场景目标的 alpha**。对不透明材质无副作用（不混合、末级只读），
但对 `Blend_Mode::Alpha` / `Additive` 的材质会直接改写 alpha，破坏混合结果（近乎全透明）；
启用覆盖率写入（alpha-to-coverage）的材质同样会被改写。

## 二、实现

| 位置 | 改动 |
| --- | --- |
| `Material_Record` | 新增 `bool tone_alpha_opaque`（默认 false） |
| `material_load` | `tone_alpha_opaque = (pipeline == 0 && blend == Opaque && !alpha_to_coverage)` |
| `material_bind_set` | `material_tone_operator = tone_alpha_opaque ? record.tone_operator : 0xFF` |

即：只有「默认管线 ＋ 不透明档 ＋ 未启用覆盖率写入」的材质才把编号写进 alpha；其余材质回落继承全局默认算子，alpha 保持反照率值。

## 三、验证

新增用例 `Renderer_Scene_Test.PBR逐材质色调算子透明材质安全`：

- 半透明白纹理（alpha 128）＋ `Blend_Mode::Alpha` 四边形；
- 同一材质分别以「继承全局」与「声明 AgX（4）」各出一帧；
- 断言两帧 **逐字节一致**（修复前声明 AgX 会写 alpha ≈ 0.02，混合结果显著不同）。
