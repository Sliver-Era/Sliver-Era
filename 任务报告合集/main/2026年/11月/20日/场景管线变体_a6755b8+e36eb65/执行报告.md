## 一、根因（第 829 轮失败的复盘）

829 把材质 `Material_Data.pipeline` 指向显式登记的 16F 场景管线后，7 个 HDR 色调用例的 AgX / ACES 分裂消失。
真正的根因在 `渲染器_材质.cpp`：`record.tone_alpha_opaque = data.pipeline == 0 && …`
——**任何**自定义管线都被视为「不能借用 alpha 携带编号」，于是 `material_tone_operator` 回落 0xFF，两半都走全局 ACES。
与顶点输入 / 实例属性无关；待答疑 Q-H 的推测据此更正。

## 二、实现（Renderer `a6755b8`）

1. `Pipeline_Entry` 增 `scene_variant` 标记；`Pipeline_Context` 增 `pipeline_mark_scene_variant / pipeline_scene_variant`。
2. 门面 `Render_Resource::scene_pipeline_variant_load(handle, color_format, sample_count, depth_format)`：
   以 `场景.vert/场景.frag` ＋ 不透明档登记（背面剔除、深度测试 / 写入沿用默认口径），随后打标记；
   颜色格式 0 → `scene_color_format()`，深度格式 0 → 交换链深度，采样数 0 → 上下文。
   同时提供 `pipeline_scene_variant(handle)` 查询。
3. 材质登记条件改为「默认管线 **或** 场景管线变体」＋ 不透明 ＋ 未启用覆盖率写入。
4. 用例侧：`run_intermediate_tone_case` 与两份 HDR 色调用例改用该入口登记场景管线，并把材质 `pipeline` 指向它。
