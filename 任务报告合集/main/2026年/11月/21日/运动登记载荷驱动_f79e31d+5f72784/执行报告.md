# 执行报告：运动登记改为载荷事件驱动

## 一、任务结论

碰撞运动状态不再以原始事件 JSON 形式长期保存，改为「事件到达时一次性解析并下发，空间内持久保存解析值」：

- 新增 `ColliderMotion` 载荷时，代理器解析、校验一次，写入运动登记并下发到持有该编号的碰撞空间。
- 未收到新载荷事件时，碰撞空间直接沿用上次下发的运动量持续施加，检测链路不再回读事件、不再解析 JSON。
- 删除 `motion_reader` / `motion_reader_set` / `motion_reader_bind` / `motion_seek` 整条回调与重解析链路。

构建与测试：EngineSystem Debug/Release 构建通过；碰撞套件 Debug 与 Release 均 **64 / 64 通过**。

- 分支：main（无上游仓库，未创建 PR）
- 提交与推送：EngineSystem `f79e31d`、Application/Test `5f72784`，两仓均已推送。

## 二、行为变更摘要

1. `Collision_Proxy` 的运动存储由 `unordered_map<uint64_t, nlohmann::json>` 改为 `unordered_map<uint64_t, Motion_Record>`；
   `Motion_Record` 持有已解析的 `Motion_Event` 与作用频率。
2. `motion_register` 完成校验后直接写登记，并把运动量与频率一次性下发到碰撞空间；同编号新事件覆盖旧登记。
3. `Collision_Region` 新增 `collider_motion_set`：写入整体/部件运动总量并清零本帧施加量；
   删除运动读取回调成员与注入入口。
4. `detect_detail` 删除两处事件重读分支：未配置频率时直接施加已存运动，配置频率时仅在生效帧拆分。
5. 生命周期联动：
   - 碰撞体卸载：当已无空间持有该编号时丢弃运动登记，修复编号回收后继承旧运动的隐患；
   - 空间卸载：先登记编号，卸载后清理已无归属的运动登记；
   - 碰撞体转移：成功后按原编号把运动量与频率重新下发到目标空间；
   - 几何重建：按子部件存在性裁剪部件运动并重新下发，整体运动保留；
   - 离散步长归零：清除含旋转或部件运动的登记，并同步清空空间内运动。

## 四、关键实现细节

### 4.1 登记与下发

```cpp
//运动登记（仅随新载荷事件更新）
Motion_Record record;
record.event.body = motion;
record.event.parts = std::move(parts);
record.frequency = frequency;
motion_records[collider_ID] = std::move(record);

//下发到持有该编号的碰撞空间
backend.collider_set_dispatch(collider_ID, [collider_ID, &saved](Collision_Region& region)
{
    bool frequency_set = region.collider_frequency_set(collider_ID, saved.frequency);
    bool motion_set = region.collider_motion_set(collider_ID, saved.event);
    return frequency_set && motion_set;
});
```

### 4.2 检测链路

- 频率为零或帧率不可用：`motion_step = motion`、`part_motion_steps = part_motions`，每次检测重复施加。
- 频率非零：未到帧间隔本帧零运动；生效帧按频率拆分整体与部件运动。
- 全程不读取代理器、不解析 JSON。

### 4.3 编号归属

运动登记仍以碰撞体编号为键。同一数字编号被多个空间持有时，登记会下发到全部持有者（沿用旧口径，本次未改动）。
卸载时仅当 `collider_owner_seek` 失败才丢弃登记；空间卸载逐编号复查归属。

## 六、已知限制

1. 运动登记仍以数字编号为键，跨空间同编号碰撞体会共享同一登记（旧有口径，本次未改动）。
2. `collider_transfer` 只恢复运动与频率，检测方式、豁免标记仍不随转移携带（原有缺口）。
3. 运动量是「每周期总量」而非速度；未配置频率时实际速度取决于检测调用频率（沿用旧语义）。
