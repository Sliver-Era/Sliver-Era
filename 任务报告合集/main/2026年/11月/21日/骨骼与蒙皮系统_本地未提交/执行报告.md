# 执行报告 —— 骨骼与蒙皮系统（EngineSystem 一期）

## 一、交付范围

EngineSystem 新增骨骼与蒙皮模块，覆盖「CPU 侧语义与求值」：

- 骨骼资产：层级、绑定姿态、逆绑定矩阵、骨骼名索引、骨骼与碰撞子部件的映射模板；
- 演员姿态：`Skeleton_Pose` 组件，层级求值出骨骼世界矩阵（演员根局部空间）；
- 蒙皮求值：`蒙皮矩阵 = 骨骼世界矩阵 × 逆绑定矩阵`，输出关节调色板；
- 碰撞驱动数据：`Skeleton_Link` 计算部件相对上一帧的平移/旋转增量，输出中立运动量；
- 资产登记、演员挂载/卸载、帧求值、只读查询接口。

不在本期：动画剪辑采样、glTF 蒙皮导入、GPU 蒙皮管线、碰撞事件自动发布（运动量由调用方转投）。

## 三、实现要点

### 3.1 数据契约

- 坐标空间：骨骼姿态与蒙皮矩阵均为「演员根局部空间」；根变换由调用方通过碰撞整体运动或渲染实例模型矩阵承担。
- 矩阵布局：`float[16]` 列主序，与 glTF / 渲染层一致。
- 资产编号从 1 起，0 为无效；卸载后槽位置空且编号不回收，已挂载演员持有的共享引用继续有效。

### 3.2 骨骼资产

- JSON 结构：`{ name, bones[{ name, parent, translation, rotation, scale, inverse_bind, part{ part_ID, translation, rotation, scale } }] }`。
- 校验：父下标必须小于自身下标（保证父先于子求值）、骨骼名唯一、四元数非零、缩放非零、子部件编号唯一且不得取哨兵 0xFFFF。
- `inverse_bind` 缺省时由绑定世界矩阵求逆推导；显式提供时原样采用。
- 限制：骨骼数 ≤ 4096，文件体量 ≤ 16MB，JSON 解析不抛异常。

### 3.3 组件

- `Skeleton_Pose`：共享资产引用、逐骨骼局部 TRS、世界矩阵、蒙皮矩阵、`pose_dirty` / `skin_dirty`；提供局部写入、复位、世界矩阵读取。
- `Skeleton_Link`：碰撞体编号、逐部件绑定（骨骼下标 + `part_ID` + 相对 TRS）、上一帧部件矩阵、本帧运动量；挂载时以绑定姿态填充首帧基准，避免首帧跳变。
- 两个组件均满足 ECS 约束（可移动 + 可写 `owner`），不派生已移除的 `Object` 基类。

### 3.4 帧求值链路

1. 遍历全部姿态：脏标记置位时按骨骼下标顺序递推世界矩阵（`父世界 × 局部`）；
2. 重建蒙皮调色板（`世界矩阵 × 逆绑定矩阵`）；
3. 遍历全部链接：`部件世界矩阵 = 骨骼世界矩阵 × 相对变换`，与上一帧求逆复合得到增量，分解为平移 + 四元数，近似零增量跳过；
4. 刷新上一帧基准矩阵。

调用方须在同一逻辑帧内先 `frame_update`、再执行碰撞检测。

### 3.5 查询接口

- `pose_matrix_get`：骨骼世界矩阵；
- `skin_palette_get`：调色板指针与骨骼数（指针在下一次求值前有效）；
- `part_motions_get`：本帧部件运动量（未挂载链接返回假，空运动量时指针为空）。

## 五、遗留与后续

1. **Renderer 蒙皮管线**：顶点格式、关节属性、调色板缓冲、着色器分支均未实现；当前调色板仅可被应用层读取。
2. **蒙皮数据来源**：OBJ 无关节权重，glTF 加载器仍跳过 skins/animations；逐顶点蒙皮需先扩 Foundation 导入。
3. **碰撞转发**：骨骼系统只输出中立运动量，调用方需按 `Collision/ColliderMotion` 载荷转发；部件运动要求碰撞体已配置非零离散步长。
4. **项目导航**：当前导航 EngineSystem 部分仍为 Entity/Prop/Effect 旧口径，与 ECS 重写及本模块不一致；建议在用户提交 Foundation/对象系统重构后，以新版次重建统一更新，本轮不做半增量。
5. **提交状态**：本期骨骼文件已单独提交（EngineSystem `b0abc11`、Test `91ffb55`），用户的重构改动仍未提交。

## 六、二期增量（碰撞桥接）

- 运动量语义对齐碰撞侧：平移取部件/根部原点差，旋转取「上一帧逆 × 本帧」的旋转差；原矩阵复合增量会产生错误的旋转-平移耦合。
- `Skeleton_Link` 新增根骨骼下标、上一帧根矩阵与 `Skeleton_Root_Motion`；部件基准矩阵改为「相对根骨骼的局部矩阵」。
- `Skeleton_System` 内置 `Event_Terminal`、`attach()` 与 `event_output_set/get`；`frame_update` 每帧把根部整体运动与部件运动发布为 `Collision/ColliderMotion`（`motion` + `parts`）。
- 测试新增 `骨骼事件测试.cpp` 4 例：事件载荷（整体/部件/开关）＋ 与真实 `Collision_Proxy` 的端到端联动（整身平移、部件旋转触发碰撞）。
- 验证：骨骼 31 例全部通过；System 层全量 **161 / 161**（Debug 与 Release）。
- 版本锁：System `8e3a9e356356` / `0f78026471c0`；Renderer 已按新锁重建。
- 边界：根部运动量位于演员根局部空间，演员存在上层变换时需调用方换算为世界轴；事件发布要求碰撞体存在、部件编号存在且碰撞体离散步长非零。

## 七、三期增量（事件命令接口）

- 新增 `Common/骨骼事件.h`：类别 `Skeleton`，命令 `AssetLoad / AssetAdd / AssetRemove / Attach / Detach / BoneLocalSet / BoneRotationSet / PoseReset / EventOutput / FrameUpdate`，结果 `AssetLoadResult / ActionResult`。
- `Skeleton_System` 新增 `store_bind(ECS_Store&)`；`attach()` 绑定接收入口并登记命令订阅，`event_process` 按标签分派到既有公开接口。
- 所有 C++ 公开接口保持原签名；事件命令只是一条并行入口，调用方可在直接调用与事件驱动之间任选。
- 未绑定存储时演员类指令回告 `ActionResult.success = false`，资产类指令不受影响。
- 测试新增 2 例：全链路事件命令（加载→挂载→姿态→求值→开关→复位→卸载）与未绑定存储失败回告；骨骼 33 例、System 全量 **163 / 163**（Debug 与 Release）。
