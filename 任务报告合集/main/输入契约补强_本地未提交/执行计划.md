## 一、目标

把上一轮评估中确认的缺口全部修掉，**不动组合引擎内核**（`binding_find` 与两轮求值逻辑保持原样）。全部为增量改动。

| 编号 | 缺口 | 性质 |
| --- | --- | --- |
| F1 | 键位编号在三处手写（名称表、修饰键判定、渲染层桥） | 漂移风险 |
| F2 | `axes` 无生产者，非指针轴永远 0.0 且无提示 | 空承诺 |
| F3 | `key_repeat` 被丢弃，系统层无法表达长按连续触发 | 功能缺失 |
| F4 | `held` 缺失时组合静默退化 | 可观测性缺失 |
| F5 | `field_modifiers` 是死字段且位置错误 | 死代码 / 误导 |
| F6 | 无「当前按住某键 / 指针位置」语义查询 | 接口缺失 |
| F7 | `ModalPop` 不校验归属，任意模块可弹掉他人模态 | 既有缺陷 |

- **N1 只读帧广播**：会加剧「两套真相」，且叠加 UI 目前可直接读渲染层快照满足。推迟到叠加 UI 立项时再设计。
- **N2 同帧按键顺序抹平**：不是缺陷。物理上 Ctrl 确实是先按下的单键；改成逐边沿求值会重新引入「Ctrl 单键先于 Ctrl+S 开火」的老问题。只写进文档。

## 二、逐项设计

### F1 键位常量单一真源

现状：同一个编号事实写三遍——
[键位解析.cpp](file:///d:/代码仓库/白银纪元/Engine/EngineSystem/src/input/mapping/Input_Mapping/core/键位解析.cpp) 名称表、同文件 `modifier_mask_of` 的 `case 34..41`、[系统输入桥.cpp](file:///d:/代码仓库/白银纪元/Engine/EngineRenderer/src/render/Input/core/系统输入桥.cpp) 的 `switch`。

改法：

1. `Common/输入类型.h` 新增命名键常量（约 105 个 `inline constexpr Input_Key`）：
   - 主键盘：`INPUT_KEY_A`~`INPUT_KEY_Z`、`INPUT_KEY_0`~`INPUT_KEY_9`、`INPUT_KEY_GRAVE` / `MINUS` / `EQUALS` / `LEFT_BRACKET` / `RIGHT_BRACKET` / `BACKSLASH` / `SEMICOLON` / `APOSTROPHE` / `COMMA` / `PERIOD` / `SLASH`
   - 控制类：`INPUT_KEY_ESCAPE` / `ENTER` / `SPACE` / `TAB` / `BACKSPACE` / `LEFT` / `RIGHT` / `UP` / `DOWN`、`F1`~`F12`、`INSERT` / `DELETE` / `HOME` / `END` / `PAGE_UP` / `PAGE_DOWN`、`CAPS_LOCK` / `PRINT_SCREEN` / `SCROLL_LOCK` / `PAUSE` / `NUM_LOCK` / `MENU`、`LSHIFT` / `RSHIFT` / `LCTRL` / `RCTRL` / `LALT` / `RALT` / `LGUI` / `RGUI`
   - 小键盘：`INPUT_KEY_KP_0`~`KP_9` / `KP_DECIMAL` / `KP_DIVIDE` / `KP_MULTIPLY` / `KP_MINUS` / `KP_PLUS` / `KP_ENTER`
   - 鼠标：`INPUT_KEY_MOUSE_LEFT` / `MIDDLE` / `RIGHT` / `X1` / `X2`
   - 滚轮：`INPUT_KEY_WHEEL_UP` / `WHEEL_DOWN`
2. `键位解析.cpp` 名称表改为 `{"A", INPUT_KEY_A}` 形式，别名（`ESC` / `RETURN` / `PGUP` / `LCONTROL` / `BACKQUOTE` …）保留在解析侧。
3. `modifier_mask_of` 改为常量比对（`INPUT_KEY_LSHIFT` / `RSHIFT` → SHIFT，依此类推），删除 `case 34..41`。
4. `系统输入桥.cpp` 的 `switch` 全部改为常量；两个重复映射（`SDL_SCANCODE_APPLICATION` / `SDL_SCANCODE_MENU` → `INPUT_KEY_MENU`）加注释说明。

收益：编号一旦变动 → **编译错误**，而不是静默映射到错误键。

### F2 `axes` 空承诺

不改消费端（该通道合法：游戏层可自建 `Input/Raw` 直接投递 `axes`），只让缺口可见：

1. `轴解析.cpp`：`source` 不属于 `pointer.x` / `pointer.y` / `pointer.dx` / `pointer.dy` 时，`logger.info` 一条提示——该轴依赖上层自行投递 `Raw` 的 `axes` 字段，当前渲染层桥不提供。
2. `原始输入.cpp`：`object_axes_process` 中若某轴来源非指针且本帧 `axes` 缺失或未含该键，首次为 **(对象, 轴)** 记录并 `logger.warn`（用 `Input_Object` 内新增的 `axis_unfed_warned` 集合，避免每帧刷屏）。

### F3 `key_repeat` 透传（按绑定开启）

语义：**每个绑定独立开关**，默认关闭 → 现有全部用例行为不变。

1. `Common/输入类型.h`：`Input_Binding` 增 `bool allow_repeat = false;`
2. `Common/输入事件.h`：增 `field_repeat = "repeat"`。
3. `映射解析.cpp`：`binding_parse` 读 `repeat`（bool，缺省 false）。
4. `系统输入桥.cpp`：`raw_build` 增 `frame.key_repeat` 循环，写 `{"key":K,"pressed":true,"repeat":true}`（渲染层 `key_repeat` 已完整采集，只差投递）。
5. `原始输入.cpp`：边沿收集阶段把 `repeat:true` 的边沿放入独立的 `repeats` 列表（不进入 `presses`，避免影响组合的两轮抑制）；两轮结束后逐条查绑定，仅 `allow_repeat` 为真才产出命令，并在载荷写 `"repeat": true`。

消费方据此区分「首次按下」与「自动重复」，例如列表滚动用 repeat 绑定，跳跃用普通绑定。

### F4 `held` 缺失告警

1. `Input_Manager` 增 `bool held_warned = false;`（**实例成员，不用函数内 static**，避免多实例 / 多测试互相遮蔽）。
2. `held_update`：当本帧不含 `held` 且 `held_warned` 为假时，扫描所有对象是否存在 `modifier_mask != 0` 的绑定（含注入生效表）；存在则 `logger.warn` 一条：组合将退化为边沿 + 帧连续性推断，且 `Focus_System` 丢弃整帧时修饰键会卡死到抬起，建议每帧投递 `held`。随后置位。
3. 行为不变（仍退化为边沿推导），只增加一次可见提示——现有用例不受影响。

### F5 删死字段

1. `Common/输入事件.h` 删除 `field_modifiers`。
2. `映射解析.cpp` 保留字面量 `"modifiers"` 并加注释：这是**映射配置词汇**，不经事件总线，因此不属于事件载荷字段表。

### F6 语义状态查询

`Input_Manager` 新增公有只读接口：

- `bool key_held_get(const Input_Key& key) const` —— 全局物理按住
- `uint8_t modifier_mask_get(void) const` —— 当前规范化修饰掩码（对现有私有 `held_modifier_mask` 的公有包装）
- `Input_Cursor_Snapshot cursor_get(void) const` —— 最近一帧指针（`x` / `y` / `dx` / `dy` / `wheel_x` / `wheel_y`）

配套：

- `Common/输入类型.h` 增 `Input_Cursor_Snapshot` 结构。
- `Input_Manager` 增 `cursor` 成员；`held_update` 里顺带缓存 `raw` 的 `pointer` 字段（每帧一次，与目标对象无关）。
- 实现落在 `映射查询.cpp`（与既有 `object_*_get` 同文件）。

说明：这些查询回答的是**系统语义层**的状态（组合已消费、文本挂起、对象 enabled 等渲染层快照答不了的部分）。

### F7 `ModalPop` 归属校验

1. `焦点系统.h`：`modal_stack` 由 `vector<string>` 改为 `vector<Modal_Entry>`，`Modal_Entry{ std::string object; std::string owner; }`。
2. `模态闸门.cpp`：`modal_push_process` 记录 `evt->sender` 为 owner；`modal_pop_process` 要求 `evt->sender == owner`，不匹配则 `logger.warn` + 忽略。

**强度说明**：这是**防误用**而非防恶意——事件中转站不校验 sender 身份，任何订阅者都能伪造 sender 名。真正的归属校验需要中转站侧填写真实发送者身份，属于协议级改动，本计划不含。现有用例 `modal_push` / `modal_pop` 同为 `"UI"` 发送者，不受影响。

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| 105 个常量使 `输入类型.h` 变长 | 只放常量，名称/别名表留在解析侧；文件仍在一屏可检索范围内 |
| repeat 处理误入组合抑制 | repeat 边沿单独成表，不进入 `presses`，两轮求值逻辑零改动 |
| `axis_unfed_warned` 使 `Input_Object` 变大 | 只在需要时插入，且属对象级小集合 |
| 指针缓存被非目标对象的帧覆盖 | `held_update` 每帧只写一次，所有对象的帧共享同一快照，语义一致 |
| 模态归属校验过于严格 | 仅比对 sender 字符串；同一 UI 模块压/弹不受影响；文档标注为防误用 |
| 重建顺序错导致版本锁报错 | 按 §六 顺序，先 System 后 Renderer 两套配置 |

## 八、已确认决策

1. `repeat` 粒度：**按绑定开关**（映射项写 `"repeat": true` 才响应重复沿，缺省关闭）。
2. F7 模态归属校验：**纳入本次**（弱校验，只防误用；文档标注中转站不验 sender 身份）。
3. `cursor_get`：**包含滚轮增量**（`x` / `y` / `dx` / `dy` / `wheel_x` / `wheel_y`）。
4. N1 只读帧广播：**不做**，推迟到叠加 UI 立项。
5. N2 同帧顺序抹平：**不修**，仅写入文档与执行报告作为已知取舍。
