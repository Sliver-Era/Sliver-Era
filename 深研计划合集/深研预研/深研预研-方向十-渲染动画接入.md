# 深研预研 · 方向十 · 渲染动画接入

> 轮次：方向十阶段 A（第 1–3 轮）。
> 目的：先钉住源码现状与改动面，避免后续实现反复读码。

## 一、当前开发内容

为渲染核心接入骨骼动画：蒙皮顶点、动画片段采样、姿态合成、调色板上传与 GPU 蒙皮。

## 三、预计修改方式

1. **新增** `EngineRenderer/src/render/Animation/`：
   - `动画资产.h`（`Animation_Clip` / `Animation_Track` / `Animation_Key`，纯数据，Vulkan-free）
   - `动画采样.h/.cpp`（线性 / 阶跃、循环 / 夹紧、时间归一）
   - `动画播放器.h/.cpp`（播放状态与时间推进）
   - `骨骼姿态计算.h/.cpp`（局部 TRS → 世界矩阵 → 蒙皮矩阵）
   - 对外头 `动画系统.h`
2. **扩展** `网格加载器.h`：新增 `Skinned_Vertex` 与 `Skinned_Mesh_Data`，保留旧 `Vertex/Mesh_Data` 不动。
3. **扩展** 管线顶点布局：新增一套蒙皮布局（步长 48），`pipeline_load_ex` 增加布局选择参数；旧布局默认。
4. **扩展** 实例数据：末尾追加调色板偏移（`uint32` ＋ 3 个保留），步长 128 → 144；旧路径按 0 偏移。
5. **扩展** `场景.vert`：新增 `in_joint`（uvec4）与 `in_weight`（vec4）属性；权重和为 0 时跳过蒙皮。
6. **新增** SSBO：`mat4 palette[]`，按演员偏移索引；空绑定为单位矩阵。
7. **门面**：`Renderer::animation()` 子门面与 `mesh_draw_skinned`。
8. **测试**：新增 `渲染动画采样测试.cpp`、`渲染蒙皮测试.cpp`；静态路径回归沿用现有用例。

## 四、风险与待定

1. 实例步长变化会改变实例缓冲写入与用例断言，必须保留旧实例路径（偏移 0）。
2. SSBO binding 需在阶段 A 确认空闲位，避免与场景 UBO / 纹理 / 编号通道冲突。
3. 骨架 JSON 与动画 JSON 的 schema 是本方向自定义，需在阶段 D 固化并写错误码。
4. 与 `Skeleton_System` 的姿态口径必须一致（先缩放、再旋转、最后平移；列主序）。

## 五、落地记录（第 851–852 轮，阶段 A 已收口）

### 5.2 第 852 轮：调色板 GPU 通路

- 数据契约：`EngineRenderer/src/render/Animation/动画数据.h` ＋ `core/调色板数据.cpp`；
  容量 1024 条 mat4 / 帧槽（单条 16 浮点 / 64 字节）、单演员骨骼上限 64；
  `palette_identity_fill` 与 `palette_matrix_write`（越界整体拒绝、空写入成功）。
- 描述符：`set 0 binding 5` 只读存储缓冲（顶点阶段可见）；描述符池存储缓冲每帧槽 8 → 9。
- 绑定与生命周期：`Pipeline_Context::palette_bind`、`Render_Resource::scene_palette_bind`；
  设备域每帧槽一条 64 KB 主机可见缓冲，初始化写满单位矩阵，关闭时在内存模块销毁前归还。
- 查询：`Render_Resource::animation_palette_capacity()`（1024），供上层规划演员与骨骼数量。
- 用例：`Renderer_Animation_Palette_Test` 4 例；受影响套件 `Renderer_Mesh_Test` 20 / 20、`Renderer_Init_Test` 8 / 8。
