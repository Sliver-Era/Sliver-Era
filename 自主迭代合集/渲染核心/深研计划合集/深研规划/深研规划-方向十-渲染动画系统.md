# 深研规划 · 方向十 · 渲染动画系统

> 立项：2026-11-21（用户指定「为渲染核心引入动画系统」）。
> 预测轮数：24 轮（A–E 五阶段）。
> 依据：EngineSystem 已有 `Skeleton_System`（骨架资产 / 姿态 / 蒙皮调色板），但**没有动画片段与播放器**；渲染核心当前只有静态网格渲染。

## 一、深研背景

### 1.1 现状

- 渲染核心网格顶点 `engine::Vertex` 仅含 `position[3] / uv[2] / normal[3]`，步长 32 字节，无关节索引与权重（`EngineFoundation/src/loader/assets/Mesh_Loader/网格加载器.h`）。
- 场景顶点着色器 `场景.vert` 只有位置 / UV / 法线＋实例矩阵 / 材质 / 卡通 / PBR 特性（location 0–10），无蒙皮分支。
- 实例步长 128 字节（`INSTANCE_STRIDE_BYTES`），字段已满（矩阵 64 ＋ 材质 16 ＋ 卡通 16 ＋ 暗部 16 ＋ PBR 特性 16）。
- `Skeleton_System` 提供：`asset_add/load_file`、`actor_attach`、`bone_local_set`、`pose_apply`（批量写姿态）、`bone_seek`（按名查骨骼）、`bone_bind_get`（绑定姿态）、`pose_matrix_get`、`skin_palette_get`（每骨骼 16 项调色板）、`frame_update`。
- **缺口**：没有动画片段（关键帧）、没有采样器、没有播放器；渲染侧没有蒙皮顶点、调色板上传与蒙皮着色。

### 1.2 层次约束

- 依赖方向为 Renderer → Foundation，Renderer 不依赖 EngineSystem。
- 因此动画资产、采样与播放器放在渲染核心；骨骼层级与蒙皮矩阵在渲染侧独立实现（纯数据），
  `Skeleton_System` 的 `pose_apply / skin_palette_get` 作为**可选桥接**由调用方驱动，不新增层间依赖。

## 二、深研目标

1. 渲染核心可加载「骨架 ＋ 蒙皮网格 ＋ 动画片段」，按时间采样并在 GPU 完成 4 骨骼蒙皮。
2. 单帧可同时绘制多个动画演员，各自独立调色板；未启用蒙皮时画面与现状**逐字节一致**。
3. 提供播放器接口：播放 / 暂停 / 跳转 / 速度 / 循环 / 片段切换；采样边界（0 帧、单帧、越界时间）行为明确。
4. 与 EngineSystem 骨骼系统可桥接：同一演员的渲染姿态可回写 `Skeleton_Local_Transform`，供碰撞部件运动使用。
5. 场景 / 关卡文本可声明骨架与动画，资产加载链路贯通。

## 四、验收口径

1. 默认关闭（无动画、无蒙皮顶点）时，全量渲染用例逐字节不变。
2. 每阶段新增用例聚焦对外行为：采样值、顶点位移、调色板内容、绘制结果。
3. 蒙皮只影响声明了 joint/weight 的网格；静态网格走原管线。
4. 全量回归只在阶段收口与窗口收口各一次；每轮跑受影响套件。

## 五、风险与对策

| 风险 | 对策 |
| --- | --- |
| 实例步长变化影响既有用例与着色器 | 保留旧步长路径；新字段只在蒙皮实例使用，旧实例偏移 0 且着色器按权重为 0 跳过 |
| SSBO 容量 / 描述符集绑定冲突 | 阶段 A 先勘察，选空闲 binding；容量上限显式告警 |
| 与 EngineSystem 双份骨骼实现口径分裂 | 渲染侧算法与 `Skeleton_System` 对齐（同一 TRS 顺序、列主序）；桥接只传数据 |
| 动画采样性能 | 轨道按骨骼名预解析为下标；关键帧二分查找；每帧只重算脏播放器 |
| 资产格式无现成规范 | 自定义 JSON 并在阶段 D 固化 schema 与错误码 |
