# 8 位路径的逐材质色调 · 方案预研（第 797 轮）

> 日期：2026-11-19
> 关联：`自主迭代规则.md` §0.1 判据①（同一帧内不同物体可各自选材质特性与色调曲线）；
> 现状：逐材质色调仅在 16F 场景目标下可用（编号借 alpha 传递），8 位路径只有全局算子（794 轮已加告警）。

## 一、问题定义

- 16F 场景目标：alpha 通道可承载 `(id + 1) × 0.0005`，末级 `材质色调映射.frag` 按最近编号解码。
- 8 位场景 / 呈现目标：alpha 只有 256 级，`0.0005..0.0025` 全部量化为 0，编号不可用。
- 因此 8 位路径无法表达「同帧不同物体不同色调曲线」——这不是精度取舍，而是通道缺失。

## 二、候选方案

### 方案 A：第二颜色附件（推荐）

- 场景 pass 增加一个 `R8_UINT`（或 `R8_UNORM`）第二颜色附件，只写色调编号；
  颜色仍写 8 位或 16F 主附件，两者互不占用通道。
- 管线侧：`pipeline_load_ex` 增加第二附件格式参数；`render_target_create_format` 增加可选第二附件；
  帧模块的渲染区 / 依赖 / 布局转换增加第二条颜色路径（同时覆盖 MSAA 解析）。
- 末级：`材质色调映射.frag` 增加 `usampler2D tone_id_image`（描述符集 1 新增 binding），
  编号直接读，**不再依赖 alpha**——16F 路径同样受益（可与 alpha 携带并存，读取优先级：id 附件 > alpha > 全局）。
- 成本：每像素 1 字节带宽 + 1 次取样；8 位与 16F 路径统一口径。
- 风险：附件数量、MSAA 解析、离屏目标创建路径都要同步；用户自建目标若不带第二附件需回落 alpha / 全局。

### 方案 B：屏幕空间 id 预通道

- 场景 pass 前单独跑一个极简 id pass（只写 R8 目标），随后后处理读取。
- 成本：额外的几何提交（或复用同一实例缓冲再画一遍），对多物体场景不划算。
- 结论：不如 A（A 是同一次光栅化的 MRT）。

### 方案 C：维持现状（8 位只支持全局算子）

- 优点：零成本、零风险；缺点是 8 位路径永远无法逐物体选曲线。
- 已配套（794）：关闭 HDR 且材质声明 `tone_operator` 时告警，避免隐藏行为。

## 三、结论与拆解

- 短期（本窗口后）：保留 C，作为明确的能力边界（已告警 + 用例锁定）。
- 中期：按 A 分四段落地——
  1. 资源层：目标支持可选第二附件（R8），清理 / 布局 / 解析同步；
  2. 管线层：`pipeline_load_ex` 第二附件格式，图形管线增加第二个颜色附件状态；
  3. 场景层：`场景.frag` 有覆盖时写 id 附件（无覆盖写 0），默认关闭时逐字节不变；
  4. 末级：`材质色调映射.frag` 读 id 附件（binding 新增），无附件时回落 alpha / 全局。
- 验收（每段）：①无覆盖帧与引入前逐字节一致；②8 位路径两物体不同算子可分辨（左右通道差分裂）；
  ③16F 路径行为不变；④自建目标缺第二附件时回落全局并告警。

## 四、待定项

1. id 附件格式取 `R8_UINT`（无过滤、需 `usampler`）还是 `R8_UNORM`（可过滤、最近邻取样）——倾向前者，避免误插值。
2. 第二附件是否纳入 `render_target_create_format` 的现有签名（重载）还是新增 `..._format_ex`。
3. 描述符集 1 的 binding 编号：现有 0 = source、3 = LUT，新增取 4 以避开既有语义。

## 七、段 3 实测结论（第 807 轮：方案 A 暂缓，改走方案 B）

按 §六实现后，校验层拒绝（`VUID-vkCmdDrawIndexed-dynamicRenderingUnusedAttachments-08910`）：
**同一个渲染 pass 内的所有绘制项**都必须使用声明了第二附件的管线。目标通道 / 链呈现除了场景管线，
还有天空盒、粒子、UI、描边等管线（均单附件），要逐个准备双附件变体，成本远高于预估。

**调整**：优先实施方案 B（独立 id 预通道）：

1. 新增极简管线 `色调编号.vert / .frag`：顶点阶段复用现有实例布局（模型矩阵 ＋ location 10 的 z = 算子），
   片元写 `(id + 1) / 255` 到 `R8_UNORM`；
2. 帧链路在场景 pass **之前**增加一个 id pass：目标 = 目标记录的编号附件，清 0、只画不透明物体；
3. 主 pass 完全保持单附件（零管线变体）；末级读取仍然「id 附件 > alpha > 全局」；
4. 布局：id 附件帧间只读，id pass 内颜色附件，之后转回只读；
5. 验收：默认关闭逐字节不变；开启后同帧两物体不同算子可分辨；id 与 alpha 冲突时 id 优先。

若后续仍需零额外几何提交，再回到方案 A，并按 §六 一次性为全部管线准备双附件变体。

## 八、方案 B 落地记录（第 808 轮）

按 §七 实现，接口与链路如下（全部只在显式开启且目标带编号附件时生效）：

1. **着色器**：`assets/shaders/色调编号.vert` / `色调编号.frag`——顶点只做视图投影变换（复用场景顶点 / 实例布局，
   无管线变体），片元把实例属性 z 编码为 `1..5`（0 = 无覆盖）写入 `R8_UINT`。
2. **管线**：`tone_id_pipeline` 在初始化阶段登记——颜色格式固定 `R8_UINT`、深度格式跟随交换链、
   采样数 1、`depth_write = false` ＋ `depth_lequal = true`（`pipeline_load_ex` 新增末尾参数 `depth_lequal`）。
3. **帧链路**：`Frame_Render_Target` 增 `tone_id_image / tone_id_view / tone_id_format`；
   `command_record_target` 在场景 pass 结束后（深度仍为 `DEPTH_ATTACHMENT_OPTIMAL`）调用
   `tone_id_pass_record`：编号附件 CLEAR 0 → 重绘不透明项（跳过透明 / 粒子 / 间接项）→ 转回 `SHADER_READ_ONLY`。
   `render_to_target` 增末尾参数 `tone_id_pipeline`（默认空 = 零额外命令）。
4. **门面**：`tone_id_pass_set / tone_id_pass`（默认关闭）；`render_target_readback_tone_id` 读回编号（每像素 1 字节）。
5. **资源**：编号附件补 `TRANSFER_SRC` 用法（读回需要）。
6. **验收**（`Renderer_Offscreen_Test.逐材质色调编号预通道`）：远平面 AgX（4）＋近平面 ACES（0）——
   中心编号 1、边缘编号 5；反转绘制顺序后中心仍为 1（被遮挡物体不改写近处编号）。
7. **已知限制**：alpha 裁剪材质的透明纹素仍会写编号（编号通道不采样反照率）；MSAA 目标不建编号附件（801 既有口径）。

段 4（末级按「id 附件 > alpha > 全局」解码）仍待做：需给材质色调映射片元的采样集补编号纹理绑定。

## 九、段 4 设计（第 809 轮 · 末级按「id 附件 > alpha > 全局」解码）

1. **采样集新增 binding 10**（`COMBINED_IMAGE_SAMPLER`，片元阶段）：默认 1×1 `R8_UINT` 零图（值 0 = 无覆盖）。
2. **门面**：`post_tone_id_target_set(uint64_t render_target_handle)` 记录目标编号视图；
   后处理绘制项组装时把该视图写进 sampling 集 binding 10，未设置则写默认零图。
3. **着色器**：`材质色调映射.frag` 增 `uniform usampler2D tone_id_tex`，`texelFetch` 取 `uint` 编号：
   1..5 → `id - 1` 选曲线；0 → 回落 alpha 解码 → 全局回落。
4. **验收**：无编号附件时末级输出逐字节一致；有编号附件时逐材质算子与 16F 路径一致；中间级不读该绑定。
5. **风险**：所有采样集写出点（场景 / 后处理 / UI / 逐项）都要补 binding 10，漏写会被校验层拒绝。

第 809 轮已先用例锁定「开关开启但目标无编号附件 → 画面逐字节不变」（`Offscreen.编号通道无附件时零影响`）。

## 十一、alpha 裁剪一致性预研（第 814 轮 · 文档轮）

问题：编号预通道不采样反照率，alpha 裁剪材质（`Material_Data.d < 1` 走裁剪）的透明纹素仍会写编号，
末级据编号选曲线时，这些像素的颜色已被主 pass 丢弃，但编号残留在「背景像素」上，可能让背景选错曲线。

三个候选：

| 方案 | 做法 | 成本 | 风险 |
| --- | --- | --- | --- |
| A 采样反照率并 discard | 编号片元读取 sampler 集 binding 0（albedo）与材质 alpha 阈值，与主 pass 同式 discard | 每次编号绘制多一次采样 + 分支；需把裁剪阈值/开关带给编号着色器 | 编号管线与场景管线的采样口径必须一致（UV 变换、纹理绑定），否则编号与可见性错位 |
| B 只在编号通道跳过裁剪材质 | 门面组装编号绘制项时排除 `d < 1` 的项 | 零着色器成本 | 裁剪材质整体没有编号 → 末级回落 alpha/全局（正确但丢失逐材质曲线） |
| C 维持现状 | 记录已知限制 | 零 | 背景像素可能被错误曲线处理；仅影响裁剪材质边缘区域 |

结论（建议）：先做 **B**（正确性优先、零着色器成本、可一周内交付），把 A 作为后续「裁剪材质也要逐材质曲线」的增强；
C 仅作为不启用编号通道时的既有行为。

B 的实现清单（下一轮可直接执行）：
1. `Frame_Render_Item` 增 `bool alpha_clip`（门面按材质 `d < 1` 置位；默认 false）；
2. `tone_id_pass_record` 跳过 `alpha_clip` 项；
3. 用例：裁剪材质 + 编号通道 → 该物体像素编号 0，末级回落到全局算子；不裁剪物体编号不受影响。

## 十二、方案 A 落地记录（第 819 轮 · 编号通道逐纹素裁剪）

1. `色调编号.vert` 输出 UV；`色调编号.frag` 声明 `sampler2D albedo_image`（set 1 binding 0）
   与推送常量（offset 64 色调 / 80 材质扩展 / 96 UV 变换）。
2. 裁剪阈值（`material_extras.z`）> 0 时按「缩放 → 旋转 → 偏移」采样反照率，
   `albedo.a × tint.a < 阈值` → `discard`；阈值 0 时零采样。
3. 编号通道在绘制前推送与主通道同一批推送常量；814 轮的 `Frame_Render_Item.alpha_clip` 整体跳过被移除。
4. 验收：不透明贴图 → 编号 5；全透明贴图 ＋ 阈值 → 0；全透明无阈值 → 5；全量 902 / 902。
5. 剩余限制：仅 MSAA 目标不建编号附件（沿用 801 口径）。
