# 整改计划 · 通用引擎化（用户 2026-11-19 指示）

> 状态（2026-11-19）：阶段一（777）、阶段二（778）、阶段三（779）均已落地并通过 Debug 渲染层回归。

> 用户判定：方向八 ＋ HDR 通路「该在核心」，但方向九 PBR / 自动泛光 / 全局色调算子的**实现形式**把全局美术风格固化进了核心。
> 整改目标（口径见 `自主迭代规则.md` §0.1 修订版）：**通用渲染引擎**；场景只是能力覆盖范围，风格必须逐物体 / 逐材质 / 可组装。

## 一、三条硬判据（验收总纲）

1. 同一帧内不同物体可各自选择材质特性与色调曲线；
2. 后处理链由调用方显式组装，引擎不隐式介入；
3. 关闭任意可选能力时，画面与未引入该能力前逐字节一致。

## 二、整改项与顺序

### 阶段一：PBR 特性从全局开关 → 材质字段（最高优先）

现状：`pbr_multiscatter_set` / `pbr_fresnel_roughness_set` / `pbr_gloss_mapping_set` / `pbr_aniso_set` / `pbr_skin_sss_set` / `pbr_sheen_set` 为全局，同帧只能全选一种；只有 `pbr_specular_aa_set` 属管线口径（保留全局）。

改法：
| 项 | 位置 | 说明 |
| --- | --- | --- |
| 材质字段 | `src/render/Pipeline/材质数据.h` | 新增 `bool pbr_features_override` ＋ 掩码 `uint32_t pbr_features`（bit0 多散射 / bit1 Fresnel-roughness / bit2 各向异性 / bit3 皮肤 SSS / bit4 sheen）；默认 false = 沿用全局 |
| 材质记录 | `src/render/Renderer/core/渲染器_材质.cpp` | `record` 增字段，`material_load` 校验后登记；`material_bind_set` 写入资源域状态（逐绘制快照） |
| 实例数据 | `src/render/Pipeline/管线.h`（`INSTANCE_FLOAT_COUNT` 28 → 32）、`渲染器_网格_绘制.cpp`（多写一个 vec4）、`Instance_Material_Values` | 第 5 个 vec4：x = 覆盖标志、y = 特性掩码位、z/w 保留 |
| 顶点属性 | `assets/shaders/场景.vert` | `layout(location = 10) in vec4 in_pbr_features;` → `flat out vec2 out_pbr_features;` |
| 片元门控 | `assets/shaders/场景.frag` | 新增 `feature_on(bit, 全局值)`：覆盖时读实例掩码，否则读全局；替换 5 处门控（多散射 `lighting_extra.z`、Fresnel `pbr_aniso.x`、各向异性 `pbr_aniso.x/y`、SSS `pbr_aniso.z`、sheen `pbr_sheen.x/y`）；镜面 AA（`lighting_extra.w`）保持全局 |
| 属性登记 | `src/render/Pipeline/core/图形管线.cpp` | 实例属性新增 location 10（步长 128） |

验收用例：同一帧三枚球 —— 金属开各向异性、布料开 sheen、皮肤开 SSS；断言三球各自局部差异存在，且与「逐个单独全局开启」的参照帧一致。关闭覆盖时既有 830+ 用例逐字节不变（`pbr_features_override=false` 时实例第 5 向量全 0）。

### 阶段二：自动泛光从引擎隐式 → 显式可组装预设

现状：`Renderer_Config.hdr_auto_bloom` ＋ 4 个 `hdr_bloom_*`，引擎在「无显式目标且链/额外目标为空」时自建 3 目标 3 管线（770 已暴露隐藏分支行为不一致）。

改法：
- 删除 `hdr_auto_bloom` / `hdr_bloom_threshold/knee/radius/intensity/half_res` 与 `hdr_bloom_frame_apply` 的隐式介入；
- 提供显式预设函数：`bool post_bloom_preset_build(Renderer&, Post_Bloom_Preset&, const Bloom_Preset_Desc&)`（内部建 3 个 16F 目标 ＋ 3 条管线并返回句柄＋链顺序），由调用方 `render_target_present_chain_set` ＋ `post_chain_set` 自行装配；
- 测试改用该预设，且新增「不调用预设时链恒为空、单级路径」守卫。

### 阶段三：全局色调算子 → 材质级算子编号

现状：`hdr_tone_operator` 全帧唯一（762 实测 AgX 压灰二次元纯色，141 vs 247）。

改法（方案 B，不增第二附件）：
- `Material_Data` 增 `uint8_t tone_operator`（0xFF = 继承全局）；
- 场景 pass 把算子编号写进 16F 场景目标的 **alpha**（当前恒 1，可承载 0..255；写 `(id + 1) / 255`，0 表示继承）；
- 末级色调映射片元按 alpha 选曲线（ACES / 胶片 / 指数 / Reinhard / AgX），按像素插值边界用最近邻（`round`）避免混算子；
- 文档化：MSAA 解析会平均 alpha，边缘可能取相邻算子（可接受，或用 `sample shading` 规避）；
- 全局 `hdr_tone_operator` 降级为「无材质指定时的默认」，不再是唯一算子。

## 三、已明确不做 / 保留

- `pbr_specular_aa_set`（镜面 AA）：管线级口径，保留全局。
- 方向八（前向 32 槽、聚光阴影、接触阴影）与 HDR 通路（16F 场景目标 ＋ 中间目标 ＋ 末端色调映射）：保留在核心，不改归属。
- `hdr_tone_operator` 的 5 种曲线本体保留（阶段三后作为逐像素可选曲线库）。

## 四、执行纪律

- 每阶段独立成轮，均为「默认关闭 → 逐字节不变」；
- 每阶段跑 Debug 全量 ＋ Release 受影响套件；
- 阶段一完成前不启动阶段二，避免实例布局与后处理结构同时变更导致回归定位困难。
