# 深研预研 · 材质级色调映射与双轨（写实 / 二次元）分风格

> 日期：2026-11-18（第 769 轮，文档轮）
> 依据版次：Renderer `df61060` / Test `fb853f6`
> 相关：`深研规划_方向九_PBR写实与二次元融合.md`、`深研预研_HDR与色调映射.md`、第 762 / 764–768 轮报告

## 一、问题陈述

方向九的使命是「3D 写实场景 ＋ 二次元人物同帧共存、强光照表现」。当前 HDR 通路已经打通（16F 场景目标、
五种色调算子、自动泛光、MSAA、半分辨率泛光），但色调映射是**全帧唯一算子**：

- 第 762 轮实测：同一帧里写实侧与二次元侧（纯蓝）在 ACES / AgX 下的右半最大通道差为 **247 vs 141** ——
  AgX 为压高光做的跨通道去饱和，会把二次元平涂的纯色压灰；
- 第 768 轮实测：AgX 下白四边形中心 **233**（其余算子 246–255），说明它整体更「保守」；
- 结论：**写实适合 AgX，二次元适合保饱和的逐通道算子（ACES / 指数）**，全帧单一算子必然在两侧之一妥协。

## 二、可选方案

### 方案 A：二次元对象后置（显示域内重绘）

二次元对象在场景 pass 中额外输出一层「卡通覆盖色 ＋ 遮罩」，待色调映射之后、UI 之前按遮罩混合。

- 优点：二次元色**完全绕过色调映射**，纯度 100% 保真；写实侧可用 AgX。与现有 UI 后置结构同源（758 已验证显示域）。
- 代价：需要第二套颜色目标（或复用打包通道）、遮罩与覆盖色；透明与遮挡关系要与深度测试对齐（覆盖层只写「已通过深度测试」的像素）。
- 风险：半透明二次元材质（头发、薄纱）需要额外处理，否则会在显示域出现双份混合。

### 方案 B：材质级算子选择（逐物体 tone curve）

场景 pass 仍写 16F，但为每个像素额外输出「算子编号」，末级色调映射按编号选曲线。

- 优点：单次后处理，无额外几何 pass；口径统一（都在 HDR 域内解决）。
- 代价：末级片元要带三条曲线（ACES / 保饱和 / AgX），分支开销与寄存器压力上升；
  编号需要额外的 8 位目标或用 16F 的 alpha 通道传递（alpha 当前恒 1，可用）。
- 风险：MSAA 解析会让编号在边缘被平均，产生「混合算子」；需在解析后按最近邻选边或用粗粒度（逐物体区域）方案。

### 方案 C：局部色调映射窗口（按屏幕区域）

按屏幕矩形区域分别应用算子（左写实 / 右二次元），带软过渡带。

- 优点：实现最轻（末级片元按 uv 混合两条曲线），不动几何与材质系统。
- 代价：只能做「分屏式」双轨，无法处理同屏交错的角色与场景；过渡带内两侧都会被拉伸。
- 适用：展廊式对比展示（当前测试用例的口径），不是产品级融合。

## 三、评估与建议

| 维度 | A 后置覆盖 | B 材质级算子 | C 区域窗口 |
| --- | --- | --- | --- |
| 颜色保真 | 最好 | 好（受曲线设计限制） | 中 |
| 实现量 | 中（新目标 ＋ 遮罩 ＋ 混合） | 中（编号通道 ＋ 三条曲线） | 小 |
| 与 MSAA / 半分辨率泛光兼容 | 好（显示域不受影响） | 中（编号解析问题） | 好 |
| 透明 / 头发处理 | 需专门设计 | 自然（同一曲线内混合） | 自然 |
| 产品级同帧融合 | 推荐 | 备选 | 仅展示 |

**建议路线：先 C 后 A。**
1. 用 C 在测试侧建立「双轨分屏」回归（低成本、立即产出对比数据，口径与 762 一致）；
2. 再实现 A 的遮罩与显示域混合，把二次元角色真正放进写实场景（这是使命要求的形态）；
3. B 作为可选优化（当 A 的额外目标带宽不可接受时再评估）。

## 四、A 方案落地拆解（供后续轮次直接排期）

| 段 | 内容 | 验证口径 |
| --- | --- | --- |
| A1 | 场景 pass 增加第二个颜色目标（16F 卡通色 ＋ 遮罩打包 alpha），由逐物体标志控制写入 | 无二次元对象时该目标逐像素全 0，画面与现状逐字节一致 |
| A2 | 末级色调映射读该目标，在色调映射之后、UI 之前按遮罩混合 | 二次元纯色区域在 AgX 下仍保持原饱和度（通道差 ≈ 原色） |
| A3 | 透明 / 半透明二次元材质：遮罩按 alpha 加权，混合改为 over | 半透明发丝在深度交错处无二次混合 |
| A4 | 与自动泛光 / MSAA / 半分辨率组合矩阵 | 复用 767 / 768 的矩阵用例扩两维 |

## 五、风险与待定项

- 【待定 1】第二个颜色目标会占 16F×2 带宽，4K 下约 66 MB/帧；若不可接受，改为「打包进主目标的 alpha」。
- 【待定 2】二次元覆盖层是否需要参与泛光（自发光溢出）？若需要，应在色调映射前混合，与「保饱和」目标冲突，需单独决策。
- 【待定 3】遮罩在 MSAA 下的边缘会混入写实像素，是否接受 1 像素软边（通常可接受）。

## 六、本轮不落地的原因

方案 A 涉及第二颜色目标、逐物体标志、显示域混合三段改造，且需要与既有的自动泛光 / MSAA / 半分辨率矩阵重新做组合验证，
不适合与「HDR 链路收口」混在同一批提交里。本轮先把结论与拆解固化为文档，下一轮从 A1 开始。

## 七、773 / 774 实测回填与 A1 落点（第 775 轮，文档）

**方案 C 已落地**（hdr_tone_operator = 5）：左半 AgX / 右半逐通道 ACES，分轨位置与过渡半宽可配（hdr_dual_tone_split / hdr_dual_tone_band，默认 0.5 / 0.1）。
实测纯红四边形分居左右：左半（蓝, 红）**99 / 245**、右半 **0 / 252**；分轨 0.9 时右半蓝通道升到 **99**。
结论：**区域分轨能忠实验证两条曲线，但不能处理「同屏交错」的角色与场景** —— 方案 A 仍是主线。
