## 第 751 轮 · 导航回写：自绘控件树与 UI 事件桥

- 起因：用户询问「UI 子对象如何接入事件系统」，导航仅有 `Ui_Event_Bridge` 一行提及，无法解答。
- 回写内容：`Ui_Context`（保留模式控件树、控件不持终端）→ `Input_Frame` 每帧交互 → 唯一 `Ui_Event_Bridge`（内含唯一 `Event_Terminal`）接入 `Event_Broker`；
  出站 5 类（Raw / MouseFocus / ChildFocus / ModalPush-Pop / TextSession）、入站 4 类（FocusChanged / TextMode / Command / Text）与桥内去重、焦点确认、未消费外溢；
  并区分「ImGui 透传通道 `Ui_Channel_Context`」与「引擎自绘控件树」两套路径。
- 代码零改动；外部库无变更。

## 第 752 轮 · 16F 渲染目标浮点读回

- 新增 `render_target_readback_float`：按目标实际格式（RGBA16F / RGBA8）计算纹素大小并拷回浮点；

- 用例「HDR浮点读回」：16F 场景目标（曝光 +2）中心读回 > 1.5（实测 ≈4.0），8 位目标 ≤ 1.0。
- 后处理链 **109 / 109**；全量 **1593 / 96 / 0**（369.7 s）；Renderer `eb1d226` / Test `1df792f`；外部库无变更。

## 第 753 轮 · HDR 泛光提取保留高光

- 同一条「亮部提取 → 色调映射」链，仅中间目标格式不同：16F 中心浮点读回 ≈ **4.0**，8 位 ≈ **1.0**（写入处截断）。

- 过程教训：链式用例的 `hidden_config` 尺寸必须与 `pixel_bytes` 一致（64×36 → 9216 字节）；构建被占用文件打断时会跑到旧二进制。

## 第 754 轮 · HDR 泛光高阈值提取

- 在 753 用例内追加第二阶段：阈值抬到 **1.5 / 软膝 0.1**（高于 8 位可表示上限 1.0）。
- 结果：8 位中间目标中心 ≈ **0**（权重恒 0，泛光被完全截断）；16F 中间目标 ≈ **4.0**（权重 1，不衰减）。
- 结论：高光阈值只有 16F 链路才有意义——8 位链路在写入处已钳到 1.0，任何 >1.0 的阈值都退化为「全暗」。
- 后处理链 **110 / 110**；全量 **1594 / 96 / 0**（357.9 s）；Test `d4a0d08`；Renderer 无改动；外部库无变更。

## 第 755 轮 · HDR 泛光闭环强于 8 位

- 新增 `HDR泛光闭环强于八位`：完整「亮部提取 → 模糊（半径 4） → 泛光叠加」三级链，仅场景目标与两级中间目标格式不同。
- 测点不硬编码：先用直通参考帧扫描亮暗边界（x = 42），测边界外 2 像素 —— 参考 **88**、16F **200**、8 位 **129**。
- 结论：**泛光闭环整体**在 16F 下显著强于 8 位（+71），8 位在提取写入处即已钳到 1.0。
- 教训：`post_stage_param_set` 必须在本帧链长设置**之后**调用，否则级序越界被整次忽略（模糊半径停留默认 1）。
- 后处理链 **111 / 111**；非渲染层 **783 / 783**、渲染层其余 **701 / 701**（分片，合计 **1595 / 96 / 0**）；Test `063aa8f`；Renderer 无改动。

## 第 756 轮 · 离屏目标默认 16F 开关

## 第 757 轮 · HDR 默认路径（16F 场景目标 ＋ 内置色调映射）

- `hdr_targets` 接入默认帧路径：未显式设目标时内部建 16F 场景目标，场景写它、再由内置后处理级呈现交换链；开启时该级片元为 `色调映射.frag.spv`。
- 打通格式链路：新增 `target_format_get`，`render_target_frame_full_get` 填目标自身格式，分派段不再硬编码交换链格式；场景管线按 `scene_color_format()` 烘焙（16F）。
- 实测（曝光 +2）：关闭中心 **255**（直通饱和）、开启 **252**（ACES 压缩 ≈0.97）。
- 教训：`hdr_targets` 必须在管线烘焙前落位；ACES 在 [0,1] 近似线性，画面差异只有 2–3 级，断言取方向性差值。
- 后处理链 **113 / 113**；渲染层全套 **814 / 814**；Release 关键用例 **19 / 19**；Renderer `b6ae32a` / Test `4d6832c`。

## 第 762 轮 · HDR 双轨同帧色彩保真

- 左写实 PBR / 右二次元（纯蓝）在 `hdr_targets` 下出帧，比较 ACES 与 AgX：
  右半最大通道差 ACES **247** vs AgX **141** —— AgX 把二次元纯色高光压灰。

## 第 764 轮 · 自动泛光随尺寸重建（含末级管线格式修正）

- 修正：`post_pipeline_ensure` 的末级呈现管线（色调映射 / 直通）改为**显式按交换链格式**烘焙。
  HDR 默认路径把管线上下文的全局颜色格式设为 16F（供场景 pass 写 16F 目标），末级却直接写交换链，
  导致动态渲染附件格式与管线声明不一致（`VUID-vkCmdDrawIndexed-dynamicRenderingUnusedAttachments-08910`）；
  非 HDR 路径全局格式本就等于交换链格式，登记结果不变。
- 新增用例 `HDR自动泛光随尺寸重建`：出帧 → `window_size_set(96, 54)` → 重建帧 ＋ 重建后第二帧；`post_stages` 恒为 4。
- 判读口径修正：以「核心亮区边界（首个 < 220）」为基准测其后两个像素 —— 有泛光 **213 / 167**、无泛光直接落清屏色 **99**。
  早期用 < 100 扫描得到的是**光晕外缘**，再 +2 像素落在光晕之外，误判为「泛光失效」。
- 剖面证据：64×36（x = 38…52）与 96×54（x = 56…76）衰减形状一致（232 → 213 → 167 → 99），亮区边界分别在 x = **44** / **66**。
- 构建教训：`TMP/TEMP` 指向含中文的用户目录时 cl 报 `D8050`（无法执行 c1xx.dll），构建前须改到 `C:\Temp`。
- 后处理链 **119 / 119**；渲染层全套 **821 / 821**（323.3 s）；非渲染层 **783 / 783**；Release 后处理链 **119 / 119**、渲染层 **821 / 821**、非渲染层 **783 / 783**；Renderer `5d62d11` / Test `fe5d744`。

## 第 765 轮 · 自动泛光半分辨率

- 新增 `Renderer_Config::hdr_bloom_half_res`（默认关闭）：开启后「亮部提取 / 模糊」两个中间目标取 1/2 边长，
  「泛光叠加」仍按场景尺寸输出（避免直边块状），三级管线仍为 16F。
- 半分辨率下模糊半径按纹素折算（`radius × 0.5` 钳回 1..4），否则泛光带会因纹素变大而翻倍。

- 后处理链 **120 / 120**；渲染层全套 **822 / 822**（363.6 s）；非渲染层 **783 / 783**；Release 后处理链 **120 / 120**（59.8 s）、渲染层 **822 / 822**、非渲染层 **783 / 783**；Renderer `111c0f4` / Test `218caa8`。

## 第 766 轮 · HDR 默认路径 MSAA 组合

- 缺陷：`hdr_scene_ensure` 固定按单采样建立 16F 场景目标，`msaa_samples > 1` 时 HDR 默认路径下 MSAA 静默失效。
