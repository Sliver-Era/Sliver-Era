## 第 751 轮 · 导航回写：自绘控件树与 UI 事件桥

- 起因：用户询问「UI 子对象如何接入事件系统」，导航仅有 `Ui_Event_Bridge` 一行提及，无法解答。
- 回写内容：`Ui_Context`（保留模式控件树、控件不持终端）→ `Input_Frame` 每帧交互 → 唯一 `Ui_Event_Bridge`（内含唯一 `Event_Terminal`）接入 `Event_Broker`；
  出站 5 类（Raw / MouseFocus / ChildFocus / ModalPush-Pop / TextSession）、入站 4 类（FocusChanged / TextMode / Command / Text）与桥内去重、焦点确认、未消费外溢；
  并区分「ImGui 透传通道 `Ui_Channel_Context`」与「引擎自绘控件树」两套路径。
- 代码零改动；外部库无变更。

## 第 752 轮 · 16F 渲染目标浮点读回

- 新增 `render_target_readback_float`：按目标实际格式（RGBA16F / RGBA8）计算纹素大小并拷回浮点；
  16F 目标返回原始线性值（可 >1），8 位目标按 /255 归一。
- 用例「HDR浮点读回」：16F 场景目标（曝光 +2）中心读回 > 1.5（实测 ≈4.0），8 位目标 ≤ 1.0。
- 后处理链 **109 / 109**；全量 **1593 / 96 / 0**（369.7 s）；Renderer `eb1d226` / Test `1df792f`；外部库无变更。

## 第 753 轮 · HDR 泛光提取保留高光

- 同一条「亮部提取 → 色调映射」链，仅中间目标格式不同：16F 中心浮点读回 ≈ **4.0**，8 位 ≈ **1.0**（写入处截断）。
- 证明泛光提取本身不钳制，强光照下的泛光强度取决于中间目标格式；为后续 HDR 泛光阈值参数化定基线。
- 过程教训：链式用例的 `hidden_config` 尺寸必须与 `pixel_bytes` 一致（64×36 → 9216 字节）；构建被占用文件打断时会跑到旧二进制。
- 后处理链 **110 / 110**；全量 **1594 / 96 / 0**（362.8 s）；Test `5597b44`；Renderer 无改动。

## 第 754 轮 · HDR 泛光高阈值提取

- 在 753 用例内追加第二阶段：阈值抬到 **1.5 / 软膝 0.1**（高于 8 位可表示上限 1.0）。
- 结果：8 位中间目标中心 ≈ **0**（权重恒 0，泛光被完全截断）；16F 中间目标 ≈ **4.0**（权重 1，不衰减）。
- 结论：高光阈值只有 16F 链路才有意义——8 位链路在写入处已钳到 1.0，任何 >1.0 的阈值都退化为「全暗」。
- 后处理链 **110 / 110**；全量 **1594 / 96 / 0**（357.9 s）；Test `d4a0d08`；Renderer 无改动；外部库无变更。
