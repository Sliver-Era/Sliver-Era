## 二、边界（明确不支持或需自建）

| 边界 | 现状 | 触发 / 兜底 |
| --- | --- | --- |
| 8 位路径逐材质色调 | 编号通道已具备（808，默认关闭）；末级解码（段 4）未接 | 开关关闭时按 794 口径告警；开启后编号可读回，末级仍需显式装配采样 |
| 编号通道与 alpha 裁剪 | 已逐纹素一致（819） | 编号片元采样反照率并按阈值 / UV 变换 discard；阈值 0 时零采样 |
| 多重采样目标的编号附件 | 已支持（821 / 822 / 827） | 单采样解析图 ＋ msaa 编号图；样本 0 解析，边缘不插值 |
| 编号附件的 MRT 写法（同 pass 双附件） | 未采用 | 807 实测：同 pass 全部管线须声明第二附件（天空盒 / 粒子 / UI / 描边都要变体）；改走独立 id 预通道 |
| 重采样级的编号精度 | 双线性会混编号（桶形畸变等） | 末级按最近编号解码；仅影响畸变边缘像素的曲线选择 |
| MSAA 场景边缘的编号 | 已按样本 0 解析（822 / 823） | 边缘像素取某一侧完整编号，不做平均 |
| 引擎隐式泛光 | 已删除（778） | 需显式 `post_bloom_preset_*` ＋ `post_chain_set` |
| 色调映射家族片元 | 恒写 alpha 1（解码后清编号） | 798 守卫脚本白名单；放在链末 |
| 全局材质特性开关 | 仅镜面 AA 保留全局（管线口径） | 其余六项已材质化（777） |

## 三、守卫

- `检查/后处理alpha守卫.ps1`：后处理片元不得把输出 alpha 写死为 1（当前 0 处）。
- `检查/源码行数统计.ps1`、`检查/测试辅助重复检查.ps1`：每窗口收口运行。
- 用例守卫：`Post_Chain.HDR*`（32）、`Scene.PBR*`（32）、`Offscreen.*`（13）。

## 四、下一窗口优先级

1. 8 位路径逐材质色调 → **方案 B（独立 id 预通道）**：极简 `色调编号.vert/.frag` ＋ 场景后退场 pass（同深度附件 `LOAD`、比较 `EQUAL`、不写深度）写编号附件，主 pass 保持单附件；
2. 段 4（末级读取编号附件，回落顺序 id 附件 > alpha > 全局）；
3. 期间持续用三条判据验收：逐物体可选、链由调用方装配、关闭即逐字节一致。

## 五、补充守卫（第 809 轮）

- `Offscreen.编号通道无附件时零影响`：`tone_id_pass` 开启但目标不带编号附件时，回读画面与关闭时逐字节一致，
  锁定「通道开关本身不改变既有渲染」。

## 六、补充能力（第 812 轮）

- 8 位路径逐材质色调 **已闭环**：编号附件（808）＋ 末级解码（812）。入口：目标 `tone_id_format = R8_UINT`、「`tone_id_pass_set(true)`」、`post_tone_id_target_set(target)`，末级使用 `材质色调映射.frag`；未设定来源时 binding 10 = 默认零图，画面逐字节不变。用例：`Offscreen.逐材质色调编号*`、`Post_Chain.编号附件驱动逐材质色调`。
- 编号通道覆盖离屏与「场景目标 ＋ 后处理链」两条路径；链级中间级仍按 alpha 透传口径工作。

## 七、补充能力（第 819–828 轮 · 2026-11-20 窗口）

- **编号通道多重采样闭环**：逐纹素 alpha 裁剪（819）→ 合批逐实例（820）→ msaa 编号附件（821 / 822）→
  解析边界（823）→ 1× / 4× 一致（824）→ 链路径 4×（825）。
- **格式契约可自检**：`device().scene_color_format()`（826）与 `Render_Target_Native_Info.color_format / depth_format`（828）。
- **布局修复**（827）：msaa 编号图常驻颜色附件，屏障只作用于实际读写图；离屏套件校验噪声 34 → 0。
- **HDR 中间级管线格式**（829）：后处理链 HDR 用例的中间级按 16F 登记，校验条数 56 → 51；
  余下 7 条来自场景绘制使用交换链格式管线（需要「可承载实例属性的 16F 场景管线」，列为下一窗口候选）。
- 用例守卫更新：`Offscreen.*` 25 例（含编号通道 10 例）。
