# 下轮迭代方向（第 12 轮）

> 书写时间：2026-11-21 ｜ 方向：游戏框架搭建（方向深研轮） ｜ 上一轮终态：工作区 `491155e77bd1a3e60483b3f9cf8d0f8dcb84a2e7`，阶段 C 第 11 轮区块网格与体素地面完成。

## 一、方向

「游戏框架搭建」阶段 C 第 12 轮：**实体与组件注册表**。

世界已经有区块与网格，但还没有任何「对象」概念。本轮建立最小实体/组件模型与注册表，
使玩家、生物、掉落物等后续对象有统一的生命周期与更新入口，并固定更新顺序。

## 二、工作内容

1. `组件` 接口：`名称()`、`更新(float dt)`、`启用设置/启用查询`；不依赖渲染器。
2. `实体`：
   - `实体编号`（`uint64_t`，注册表递增分配，不复用）；
   - 启用标记；
   - `组件挂载`（返回是否成功，容量上限 8）、`组件获取`（按名称）、`组件数量`；
   - `更新(dt)`：按挂载顺序调用启用组件的更新。
3. `实体注册表`：
   - `实体创建`（`new (std::nothrow)`，容量上限 256）、`实体销毁`、`实体获取`、`实体数量`；
   - `更新(dt)`：按实体编号升序更新；
   - `清空`；编号只增不减。
4. 接入 `游戏应用`：
   - 持有 `实体注册表 实体表`；
   - 固定更新在模块调度之后调用 `实体表.更新(dt)`，形成 输入 → 世界 → 实体 → 资源 → 实体组件 的顺序；
   - `shutdown` 清空实体表。
5. 自检 `--entity-test`：
   - 空表数量为 0；
   - 创建两个实体编号递增且不同；
   - 组件挂载顺序即更新顺序（用记录组件验证）；
   - 禁用组件不更新；
   - 组件容量上限拒绝第 9 个组件；
   - 销毁实体后查询为空、数量减少；
   - 实体容量上限拒绝第 257 个实体；
   - 清空后数量为 0。
   - 纯数据，不初始化渲染器。

## 三、验收口径

- Debug / Release 双配置构建零错误。
- `--entity-test` 与既有十条自检（meshgen / chunk / voxel / self / state / module / config / path / resource / log）均返回 0。
- 实体与组件不依赖渲染器、文件 IO 与全局状态。
- 更新顺序约定写入文档：实体按编号升序，组件按挂载顺序。

## 四、风险与回退

- 本轮不实现玩家与碰撞，只提供容器与调度；第 13 轮再加入玩家实体。
- 组件按名称查找为线性扫描（上限 8），足够首版；不引入反射或类型索引。
- 实体销毁立即释放组件，持有组件指针的代码必须在销毁前失效。
