## 一、方向

「游戏框架搭建」阶段 D 第 17 轮：**键位配置热重载与手柄输入占位**。

当前键位硬编码在 `游戏输入` 里，改键必须重编译。本轮把键位/轴映射外置到
`assets/config/输入映射.json`，运行中修改文件即可热重载，并预留手柄状态占位。

## 二、工作内容

1. `输入映射配置`：
   - `键位映射 { 键, 命令 }` 与 `轴映射 { 轴, 来源, 缩放, 钳制 }`；
   - `默认填充`：W/S/A/D/SPACE/ESCAPE + 鼠标 X/Y；
   - `映射配置加载`：JSON 解析，失败保留旧值并返回假；
   - `映射配置默认路径`：`<exe>/assets/config/输入映射.json`；
   - `映射配置转JSON`：供 `Input/Create` 与 `Input/Reload` 共用。
2. `游戏输入` 改造：
   - 初始化时先填默认，再尝试加载外部配置；
   - 对象创建改用配置转 JSON；
   - `热重载更新(dt)`：每 1 秒检查文件修改时间，变化则重新加载并发送 `Input/Reload`（对象「玩家」）；
   - 记录上次文件时间；文件缺失不重复告警。
3. 手柄占位：
   - `手柄状态 { 是否连接, 左摇杆[2], 右摇杆[2], 扳机[2] }`；
   - `手柄状态获取()` 固定返回未连接，后续接入引擎手柄事件时替换实现。
4. 自检 `--binding-test`（纯数据）：
   - 默认配置包含 6 条键位与 2 条轴；
   - 缺失文件加载返回假且不破坏默认值；
   - 合法夹具文件加载成功并覆盖默认值；
   - 非法 JSON 夹具返回假且保留旧值；
   - JSON 转换后 mapping / axes 数量一致；
   - 纯数据，不初始化渲染器。

## 三、验收口径

- Debug / Release 双配置构建零错误。
- `--binding-test` 与既有十五条自检（interact / camera / input / player / entity / meshgen / chunk / voxel / self / state / module / config / path / resource / log）均返回 0。
- `--input-test` 仍通过，主对象「玩家」。
- 热重载每秒最多检查一次；文件缺失只告警一次。

## 四、风险与回退

- 热重载依赖文件修改时间，某些编辑器保存方式可能不更新时间；以重新加载失败保留旧配置兜底。
- 映射配置解析失败必须保留旧配置，不得清空输入。
- 手柄仅占位，不实现真实读取；不引入平台相关代码。
