# 下轮迭代方向（第 2 轮）

> 书写时间：2026-11-21 ｜ 方向：游戏框架搭建（方向深研轮） ｜ 上一轮终态：工作区 `da48bf6a`，Debug / Release 双配置与自检通过。

## 一、方向

继续「游戏框架搭建」阶段 A：把第 1 轮的粗粒度主循环升级为**固定步长更新 ＋ 可变渲染**，并补齐运行时观测与命令行配置。

## 二、工作内容

1. 主循环拆分：
   - 固定步长 `update(固定 dt)`（建议 1/60 s），带最大追赶步数上限；
   - 可变帧渲染 `frame_draw()` 与 `frame_render()`；
   - 退出时输出更新次数与渲染帧数，验证二者解耦。
2. 配置：
   - `--title`、`--vsync on|off`、`--fps N`、`--msaa N`；
   - 非法值归一并记录警告。
3. 帧统计：
   - 退出时输出 `frames`、`frame_ms`、`draw_items`、`drawn_items`、`gpu_frame_ms`；
   - 用于后续性能回归基线。
4. 自检：
   - `--frames 120 --hidden` 返回 0；
   - 固定步长累计接近 `120 × 1/60` 秒。

## 三、验收口径

- Debug / Release 双配置构建零错误。
- `--self-test`、`--frames 120 --hidden` 均返回 0。
- 固定步长更新次数与渲染帧数的关系在日志中可读、可复核。
- 不改变 `external/Engine` 版本锁；不引入新外部库。

## 四、风险与回退

- 固定步长引入累加器后可能出现「死亡螺旋」；必须设置最大追赶步数（建议 5 步）并在超限时丢弃余量。
- 帧率上限与垂直同步同时开启时以垂直同步为准，避免双重限速导致输入延迟。
- 若帧统计字段不可用，退化为仅输出帧数与主机耗时。
