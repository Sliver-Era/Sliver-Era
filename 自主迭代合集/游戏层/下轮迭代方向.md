# 下轮迭代方向（第 3 轮）

> 书写时间：2026-11-21 ｜ 方向：游戏框架搭建（方向深研轮） ｜ 上一轮终态：工作区 `dca8a80c`，固定步长与帧统计落地，双配置自检通过。

## 一、方向

「游戏框架搭建」阶段 A 第 3 轮：**应用状态机与统一退出路径**。

第 1–2 轮已经具备初始化、固定步长更新、渲染与退出统计，但运行期只有「跑 / 关窗口」两种状态。
本轮建立启动、游戏中、暂停、退出四态，并把退出、暂停、恢复收敛到单一入口，为后续菜单与输入接入打底。

## 二、工作内容

1. 新增 `应用状态` 枚举：`启动`、`游戏中`、`暂停`、`退出`。
2. `游戏应用` 增加：
   - `state_set(应用状态)`：统一状态切换入口，非法切换拒绝并记录警告；
   - `state_get()`：只读查询；
   - 各状态的分派：启动 → 游戏中（首帧后）、游戏中 → 暂停 / 退出、暂停 → 游戏中 / 退出。
3. 主循环改为按状态分派：
   - 暂停时仍渲染（保持画面），但不推进固定更新；
   - 退出状态立即结束循环，统一走 `shutdown`。
4. 自检：新增 `--state-test`，按固定序列切换状态并校验最终状态与更新次数。
5. 日志：状态切换记录旧态 → 新态。

## 三、验收口径

- Debug / Release 双配置构建零错误。
- `--self-test`、`--updates 120 --hidden`、`--state-test` 均返回 0。
- 暂停期间固定更新次数不增长；恢复后继续增长。
- 非法状态切换被拒绝且不改变当前状态。

## 四、风险与回退

- 状态机若与后续输入/UI 强耦合，容易变成全局开关堆叠；本轮只做纯状态与分派，不引入输入依赖。
- 暂停不推进更新但继续渲染，可能与后续「暂停菜单」重复；菜单接入时复用该状态，不新增并行开关。
- 若状态测试与固定步长冲突，保留固定步长为唯一时间源，状态测试只切换分派标志。
