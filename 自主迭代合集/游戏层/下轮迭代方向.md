# 下轮迭代方向（第 10 轮）

> 书写时间：2026-11-21 ｜ 方向：游戏框架搭建（方向深研轮） ｜ 上一轮终态：工作区 `be62360791e37460fbf8b082baf6e0007e13ea38`，阶段 C 第 9 轮体素数据模型完成。

## 一、方向

「游戏框架搭建」阶段 C 第 10 轮：**区块管理器与加载/卸载边界**。

第 9 轮已有单区块数据，但世界还没有「多区块」概念。本轮建立区块坐标到区块数据的映射、
水平加载半径内的按需创建与越界卸载，为第 11 轮区块网格生成提供可遍历的区块集合。

## 二、工作内容

1. `区块坐标` 结构：`int32 x / y / z`，提供相等比较与哈希（用于 `unordered_map` 键）。
2. `区块管理器`：
   - 固定容量上限（默认 512），超限拒绝并记录警告；
   - `区块获取(x,y,z)`：命中返回指针，未命中返回空；
   - `区块确保(x,y,z)`：按需创建并返回指针，超过容量返回空；
   - `区块卸载(x,y,z)`：移除并释放；
   - `半径更新(中心区块, 水平半径)`：加载圆/方形范围内的区块，卸载范围外的区块；
   - `区块数量()`、`区块列表()`（只读遍历，供网格生成与调试面板使用）。
3. 世界模块接入：`游戏应用` 初始化时创建区块管理器，固定加载原点周围半径 1 的区块（9 个），
   `shutdown` 时清空；不生成网格、不改动渲染。
4. 纯数据自检 `--chunk-test`：
   - 空管理器计数为 0；
   - 确保/获取/重复确保句柄一致；
   - 卸载后获取为空；
   - 半径更新后数量正确、范围外区块被移除；
   - 容量上限拒绝第 N+1 个区块；
   - 区块坐标哈希与相等比较自洽。
5. 自检不初始化渲染器，直接从主程序返回。

## 三、验收口径

- Debug / Release 双配置构建零错误。
- `--chunk-test` 与既有八条自检（voxel / self / state / module / config / path / resource / log）均返回 0。
- 区块管理器不依赖渲染器与文件 IO；卸载后不残留悬空指针。
- 加载半径语义（水平方形范围）写入文档，后续视距配置直接复用。

## 四、风险与回退

- `unordered_map` 迭代顺序不稳定：对外只提供只读列表，不假设顺序。
- 区块数据较大（约 4 KB），容量上限必须显式限制，避免半径配置误设导致内存暴涨。
- 本轮不生成网格、不做邻接更新回调；邻接区块更新在第 11 轮随网格生成一起接入。
