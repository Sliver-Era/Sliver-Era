# 下轮迭代方向（第 6 轮）

> 书写时间：2026-11-21 ｜ 方向：游戏框架搭建（方向深研轮） ｜ 上一轮终态：工作区 `c419450a`，配置 JSON 加载与配置自检落地。

## 一、方向

「游戏框架搭建」阶段 B 第 6 轮：**资产目录与路径规范**。

第 5 轮已能把配置从 JSON 读入，但路径仍由主程序手写拼接，且只覆盖配置一类资产。
本轮建立统一的资产路径模块与目录规范，后续网格、材质、纹理、字体、关卡、存档都走同一套解析，
避免中文路径、可执行文件目录与当前工作目录不一致等问题。

## 二、工作内容

1. 新增 `资产路径` 模块：
   - `可执行文件目录()`：用 Win32 宽字符 API 取真实 exe 目录，不依赖 CWD；
   - `资产路径(相对路径)`：`<exe目录>/assets/<相对路径>`；
   - `存档目录()`、`日志目录()`：`<exe目录>/saves`、`<exe目录>/logs`，启动时按需创建；
   - UTF-8 文本与 `std::filesystem::path` 的双向转换。
2. 目录规范（首版）：
   ```
   assets/
   ├── config/     配置
   ├── meshes/     网格
   ├── materials/  材质
   ├── textures/   纹理
   ├── fonts/      字体
   └── levels/     关卡
   ```
3. 主程序与 `应用配置` 改用 `资产路径`，移除手写路径拼接。
4. 新增 `--path-test`：
   - 可执行文件目录存在且为绝对路径；
   - `资产路径("config/游戏配置.json")` 命中默认配置；
   - 缺失资产返回不存在的明确结果；
   - 中文文件名往返转换后仍可打开。
5. CMake 继续复制 `assets/`；`saves/`、`logs/` 由程序启动时创建，不入库。

## 三、验收口径

- Debug / Release 双配置构建零错误。
- `--path-test`、`--config-test`、`--self-test`、`--state-test`、`--module-test` 均返回 0。
- 从任意当前工作目录启动，配置与资产路径仍解析到可执行文件目录。
- `saves/`、`logs/` 在启动后存在。

## 四、风险与回退

- `GetModuleFileNameW` 在路径过长时需扩容重试；实现按长度循环扩容，失败则回退当前路径。
- 中文路径必须全程走 `std::filesystem::path` 与宽字符 API，禁止把 `std::string` 直接传给 Win32。
- 若 exe 目录不可写（安装目录权限），`saves/logs` 创建失败只记录警告，不阻断启动。
