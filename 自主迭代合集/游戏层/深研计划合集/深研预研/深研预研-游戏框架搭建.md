# 深研预研-游戏框架搭建

> 方向：游戏框架搭建 ｜ 记录方式：每轮开发前预研，开发后回填实测

## 第 1 轮：应用骨架与主循环

### 一、当前迭代轮开发内容

建立游戏侧最小应用骨架：
1. 应用配置结构与命令行覆盖。
2. `游戏应用` 生命周期：初始化渲染器、构建场景基线、主循环、关闭。
3. 场景基线：地面细分网格 ＋ 基准立方体，确认渲染链路可用。
4. `--self-test` / `--frames` / `--hidden` 自检入口。

### 二、当前源码实现

本轮前工作区仅有 `src/主调/主程序.cpp` 的占位实现：设置日志根目录、输出一行日志后返回。
引擎侧可用能力（来自 `external/Engine` 公共头）：
- `engine::Renderer::init(Renderer_Config)`、`frame_render()`、`close_requested()`、`frame_stats_get()`。
- `Renderer::scene()`：相机位置/注视/视场角/近远平面、清屏色、方向光。
- `Renderer::resource()`：`mesh_ground_grid_load`、`mesh_cube_load`、`mesh_draw`、`mesh_unload`。

### 三、预计修改方式

新增文件：
- `src/框架/应用配置.h`：配置结构与 `配置解析`。
- `src/框架/游戏应用.h`：应用类声明。
- `src/框架/core/应用配置.cpp`：命令行解析实现。
- `src/框架/core/游戏应用.cpp`：初始化、场景基线、主循环、绘制、关闭与变换矩阵。
修改文件：
- `src/主调/主程序.cpp`：改为解析配置 → 构造应用 → 初始化 → 运行 → 关闭。
- `CMakeLists.txt`：为 `src/` 与 `src/框架/` 增加包含根（保持引擎快照在前）。

风险与回退：
- 渲染器初始化依赖 Vulkan 设备；失败时记录错误并返回非 0。
- 场景基线只使用程序化网格，不依赖资产文件；若网格接口不可用，回退为仅清屏并保留框架。

## 第 9 轮：体素方块数据模型

### 一、当前迭代轮开发内容

建立世界侧最小体素数据结构：
1. 六类方块枚举。
2. 16³ 区块数据：坐标、读写、填充、计数。
3. 线性索引约定与三维坐标互转。
4. 纯数据自检 `--voxel-test`。

### 二、当前源码实现

本轮前工作区只有框架层（应用配置、路径、资源缓存、日志）与 `src/框架/游戏模块.h` 的空壳世界模块，没有任何世界数据结构。
`游戏应用` 的场景基线仍为程序化地面与单个立方体，不与世界数据关联。

### 三、预计修改方式

新增：
- `src/世界/体素类型.h` / `core/体素类型.cpp`：`方块类型`（`uint8_t` 底层）与名称。
- `src/世界/区块数据.h` / `core/区块数据.cpp`：`std::array` 固定存储、越界安全接口、索引互转。
- `src/世界/core/体素自检.cpp`：纯数据自检。
修改：
- `src/框架/应用配置.h/.cpp`：`体素自检` 与 `--voxel-test`。
- `src/主调/主程序.cpp`：日志初始化后直接执行体素自检并返回。

风险与回退：
- 索引顺序一旦进入存档就难改，首版固定 `x + z * 16 + y * 256` 并写入用例。
- 纯数据层不得引入渲染或文件 IO，网格生成顺延至第 11 轮。

## 第 10 轮：区块管理器与加载卸载边界

### 一、当前迭代轮开发内容

把单区块扩展为多区块世界：
1. 区块坐标与哈希。
2. 区块管理器：按需创建、查询、卸载、容量上限。
3. 水平方形半径更新与换层卸载。
4. 纯数据自检 `--chunk-test`。

### 二、当前源码实现

第 9 轮已有 `区块数据`（16³ 固定数组、越界安全读写、索引互转），但没有跨区块容器。
`游戏应用` 只持有渲染器、资源缓存与四个空壳模块，世界模块尚未接触任何区块数据。

### 三、预计修改方式

新增：
- `src/世界/区块坐标.h` / `core/区块坐标.cpp`：坐标结构与 FNV-1a 哈希。
- `src/世界/区块管理器.h` / `core/区块管理器.cpp`：`unordered_map` 容器与半径更新。
- `src/世界/core/区块管理器自检.cpp`：容量、卸载、半径与哈希自检。
修改：
- `src/框架/应用配置.h/.cpp`：`区块自检` 与 `--chunk-test`。
- `src/框架/游戏应用.h/.cpp`：持有区块管理器，初始化加载 9 个区块，关闭清空。
- `src/主调/主程序.cpp`：区块自检直接返回。

风险与回退：
- `unordered_map` 迭代顺序不稳定，对外只提供只读表，不假设顺序。
- 每区块约 4 KB，容量必须显式限制；半径配置误设不得绕过容量检查。
- 本轮不做网格与邻接回调，留到第 11 轮。

## 第 11 轮：区块网格生成与渲染接入

### 一、当前迭代轮开发内容

把区块数据转成可见几何体：
1. 六向面剔除与面片顶点/索引生成。
2. 区块网格集（句柄 + 脏标记）。
3. 体素地面场景基线与逐区块绘制。
4. 纯数据自检 `--meshgen-test`。

### 二、当前源码实现

第 10 轮已有 `区块管理器`（9 个已加载区块），但没有任何绘制调用；`frame_draw` 仍绘制程序化地面与立方体。
引擎网格接口（`external/Engine` 公共头）：
- `Render_Resource::mesh_load(Mesh_Handle&, const Mesh_Data&)` 上传顶点/索引并返回句柄；
- `mesh_unload` 卸载；`mesh_draw(handle, transform, color)` 登记绘制项；
- `engine::Mesh_Data { std::vector<Vertex> vertices; std::vector<uint32_t> indices; }`；
- `engine::Vertex { position[3], uv[2], normal[3] }`。

### 三、预计修改方式

新增：
- `src/世界/区块网格生成.h` / `core/区块网格生成.cpp`：面表、剔除、顶点与索引输出。
- `src/世界/区块网格集.h` / `core/区块网格集.cpp`：句柄管理与脏标记。
- `src/世界/core/区块网格自检.cpp`：面数、剔除、绕序与空区块。
修改：
- `src/世界/体素类型.h/.cpp`：`方块类型是固体`。
- `src/框架/应用配置.h/.cpp`：`网格自检` 与 `--meshgen-test`。
- `src/框架/游戏应用.h/.cpp`：体素地面、世界坐标查询、网格生成与绘制。
- `src/主调/主程序.cpp`：网格自检直接返回。

风险与回退：
- 网格创建失败记录错误并中止初始化，不保留半成品。
- 面剔除一旦关闭跨区块邻居会露出内壁，必须保留世界查询回调。
- 体素地面替换程序化地面可随时回退到旧 `scene_build` 路径。

## 第 12 轮：实体与组件注册表

### 一、当前迭代轮开发内容

引入对象容器与更新入口：
1. 组件接口与实体组件集合。
2. 实体注册表（编号、容量、销毁、升序更新）。
3. `游戏应用` 固定更新接入实体表。
4. 纯数据自检 `--entity-test`。

### 二、当前源码实现

工作区已有 `游戏模块`、`模块注册表`（固定四个空壳模块）与区块/网格系统，
但没有任何对象级容器；方块交互与玩家实体都缺少承载结构。

### 三、预计修改方式

新增：
- `src/实体/组件.h`：名称与更新接口。
- `src/实体/实体.h` / `core/实体.cpp`：组件挂载、获取、启用与顺序更新。
- `src/实体/实体注册表.h` / `core/实体注册表.cpp`：容量、编号、销毁与升序更新。
- `src/实体/core/实体自检.cpp`：顺序、开关与容量自检。
修改：
- `src/框架/应用配置.h/.cpp`：`实体自检` 与 `--entity-test`。
- `src/框架/游戏应用.h/.cpp`：持有实体表并在固定更新中调度。
- `src/主调/主程序.cpp`：实体自检直接返回。

风险与回退：
- 组件按名称线性查找（上限 8），足够首版；不引入反射。
- 实体销毁立即释放组件，外部指针必须提前失效。
- 玩家实体与碰撞留到第 13 轮。

## 第 13 轮：玩家实体与基础移动

### 一、当前迭代轮开发内容

用组件落地玩家状态与移动：
1. 玩家状态（位置、朝向、速度、着地）。
2. 水平阻尼、重力、位置积分、地面钳制。
3. 玩家创建与场景占位立方体联动。
4. 纯数据自检 `--player-test`。

### 二、当前源码实现

第 12 轮已有 `组件`、`实体`、`实体注册表`，但没有任何实体实例；`frame_draw` 中立方体仍按累计模拟时间自转。
世界地面为 9 个区块各一层草方块，顶面 y = 1。

### 三、预计修改方式

新增：
- `src/实体/玩家.h` / `core/玩家.cpp`：状态、组件、创建函数。
- `src/实体/core/玩家自检.cpp`：移动、重力、朝向与禁用自检。
修改：
- `src/框架/应用配置.h/.cpp`：`玩家自检` 与 `--player-test`。
- `src/框架/游戏应用.h/.cpp`：创建玩家、立方体按玩家绘制、关闭置空指针。
- `src/主调/主程序.cpp`：玩家自检直接返回。

风险与回退：
- 地面钳制是占位碰撞，高度常量集中定义，第 27 轮替换为真实碰撞。
- 玩家更新依赖固定步长；实体或组件禁用时不得移动。
- 立方体不再自转，但更新与帧统计仍可验证固定步长。

## 第 14 轮：输入层接入焦点与映射系统

### 一、当前迭代轮开发内容

把引擎输入链路接入游戏：
1. 事件中转器 + 渲染层输入事件桥接入。
2. 焦点系统与输入管理器接入。
3. 「玩家」映射对象与焦点转移。
4. WASD/空格/鼠标驱动玩家，`--input-test` 自检。

### 二、当前源码实现

引擎侧能力（`external/Engine` 公共头）：
- `Render_Ui::input_event_terminal()` / `input_system_attach()` / `input_system_detach()`；
- `Event_Broker`：`attach(name, acl_key, receiver)` 与 `receive(evt)`；
- `Event_Terminal`：`key()` / `attach()` / `build()` / `send()`；
- `Focus_System::attach()` / `frame_begin()` / `current_main_get()`；
- `Input_Manager::attach()` / `key_held_get()` / `object_axis_value_get()`。
注意：`Input_Manager` 构造时已生成密钥，外部无法再取；必须用游戏侧自己的终端发送 `Input/Create` 与 `Input/MouseFocus`。

### 三、预计修改方式

新增：
- `src/输入/游戏输入.h` / `core/游戏输入.cpp`：四件套接入、对象创建、焦点转移、查询接口。
修改：
- `src/框架/应用配置.h/.cpp`：`输入自检` 与 `--input-test`。
- `src/框架/游戏应用.h/.cpp`：初始化接入、固定更新顺序、玩家控制、关闭顺序。
- `src/主调/主程序.cpp`：无需新增入口（输入自检在游戏应用内）。

风险与回退：
- 终端端口绑定顺序必须先绑定后 attach，否则订阅事件发送失败。
- 焦点在首帧前不生效，初始化末尾必须 `frame_begin()`。
- 隐藏窗口下无真实键位；自检只校验接入与主对象，不模拟按键。

## 第 15 轮：第一/第三人称相机与切换

### 一、当前迭代轮开发内容

把固定机位替换为玩家驱动相机：
1. 相机模式与状态。
2. 第一人称与第三人称跟随。
3. F5 切换与渲染器接入。
4. 纯数据自检 `--camera-test`。

### 二、当前源码实现

第 14 轮已有玩家位置/偏航/俯仰与输入；`frame_draw` 尚未写入相机，渲染器相机仍是初始化时配置的固定值。
渲染器相机接口：`renderer.scene().camera_position_set / camera_target_set / camera_fov_set`。

### 三、预计修改方式

新增：
- `src/相机/游戏相机.h` / `core/游戏相机.cpp`：状态、模式、更新与钳制。
- `src/相机/core/相机自检.cpp`：方向、第三人称与平滑自检。
修改：
- `src/框架/应用配置.h/.cpp`：`相机自检` 与 `--camera-test`。
- `src/框架/游戏应用.h/.cpp`：相机成员、F5 切换、每帧写入渲染器。
- `src/主调/主程序.cpp`：相机自检直接返回。

风险与回退：
- 第三人称不做遮挡回缩，可能穿方块；留到方块交互轮次。
- 平滑只插值位置，不插值旋转，避免额外状态。
- 异常时可回退到配置固定机位路径。

## 第 16 轮：方块射线拾取与破坏放置

### 一、当前迭代轮开发内容

让世界可交互：
1. DDA 体素射线检测。
2. 方块破坏/放置请求。
3. 鼠标左右键接入与网格重建。
4. 纯数据自检 `--interact-test`。

### 二、当前源码实现

第 15 轮已有相机眼点/注视与区块/网格系统；世界仍只读，没有射线与修改接口。
区块层提供 `区块管理器::区块获取` 与 `区块数据::方块获取/方块设置`；网格层提供 `区块网格集::网格重建`。

### 三、预计修改方式

新增：
- `src/世界/方块射线.h` / `core/方块射线.cpp`：DDA 步进与命中结果。
- `src/世界/方块交互.h` / `core/方块交互.cpp`：破坏/放置与命中版本、自检。
修改：
- `src/框架/应用配置.h/.cpp`：`交互自检` 与 `--interact-test`。
- `src/框架/游戏应用.h/.cpp`：鼠标边沿、射线调用、区块网格刷新。
- `src/主调/主程序.cpp`：交互自检直接返回。

风险与回退：
- 只做体素级命中，不做三角形级检测。
- 放置不检查玩家碰撞，可能放入身体；碰撞完善前只做单点放置。
- 边界重建若性能异常，可先只重建目标区块。
