## 第 1 轮 · 游戏框架搭建：应用骨架与主循环

- 轮次：1
- 类型：方向深研轮（游戏框架搭建 / 阶段 A）
- 开发内容：
  1. 应用配置结构（窗口、渲染、相机、清屏色、光照）与命令行覆盖。
  2. `游戏应用` 生命周期：init / run / shutdown。
  3. 场景基线：地面细分网格 ＋ 基准立方体。
  4. 自检入口：`--self-test`、`--frames`、`--hidden`。
- 预修改文件：
  - 新增 `src/框架/应用配置.h`、`src/框架/游戏应用.h`
  - 新增 `src/框架/core/应用配置.cpp`、`src/框架/core/游戏应用.cpp`
  - 修改 `src/主调/主程序.cpp`、`CMakeLists.txt`
- 验收口径：Debug / Release 构建零错误；`--self-test` 返回 0；正常模式可开窗并持续渲染。

## 第 2 轮 · 游戏框架搭建：固定步长与帧统计

- 轮次：2
- 类型：方向深研轮（游戏框架搭建 / 阶段 A）
- 开发内容：
  1. 主循环拆分固定步长 `update(dt)` 与可变渲染，限制最大追赶步数。
  2. 窗口尺寸、标题、帧率上限的命令行/配置覆盖。
  3. 退出时输出帧统计（帧数、主机耗时、绘制项、GPU 耗时）。
  4. 自检扩展：`--frames 120 --hidden` 返回 0。
- 预修改文件：`src/框架/core/游戏应用.cpp`、`src/框架/应用配置.*`、`src/主调/主程序.cpp`。
- 验收口径：双配置构建通过；固定步长下更新次数与帧数解耦；自检返回 0。

## 第 3 轮 · 游戏框架搭建：应用状态机与统一退出路径

- 轮次：3
- 类型：方向深研轮（游戏框架搭建 / 阶段 A）
- 开发内容：
  1. 新增 `应用状态`：启动 / 游戏中 / 暂停 / 退出。
  2. `state_set` 统一状态切换入口，非法迁移拒绝并记录警告。
  3. 主循环按状态分派：暂停只渲染不更新，退出统一走 `shutdown`。
  4. `--state-test` 时间脚本自检（0.10 s 暂停、0.30 s 恢复、0.60 s 退出）。
- 预修改文件：`src/框架/应用配置.*`、`src/框架/游戏应用.h`、`src/框架/core/游戏应用.cpp`。
- 验收口径：双配置构建通过；`--state-test`、`--self-test`、`--updates 120 --hidden` 均返回 0；暂停期间更新不增长。

## 第 4 轮 · 游戏框架搭建：模块注册与更新顺序

- 轮次：4
- 类型：方向深研轮（游戏框架搭建 / 阶段 A）
- 开发内容：
  1. 新增 `游戏模块` 接口（名称 / init / update / shutdown）。
  2. 建立模块注册表，`游戏应用` 只负责按序调度。
  3. 四个空壳模块：输入、世界、实体、资源；更新顺序固定为 输入 → 世界 → 实体 → 渲染。
  4. `--module-test` 自检：验证注册数量、初始化顺序、更新顺序与关闭逆序。
- 预修改文件：新增 `src/框架/游戏模块.h`、`src/框架/core/游戏模块.cpp`；修改 `游戏应用.*`。
- 验收口径：双配置构建通过；模块自检返回 0；主循环不直接持有业务模块细节。
