# 项目导航合集

> 文件索引：[报告汇总索引](../自主迭代合集/渲染核心/索引/索引_001-500.md) ｜ [计划汇总索引](../自主迭代合集/渲染核心/索引/索引_001-500.md)

本目录按**分支隔离**存储各版次「项目导航」：每个分支单独一个目录，分支目录下每个代码版次一个子目录（以该版次「代码推送哈希值」命名）。

---

## 存储规则

1. 分支目录：`main/`（主分支）；其余分支按分支名单独建立。
2. **每次开发窗口建立一次版次目录**，窗口内各轮**就地增量**；窗口收口时按上限淘汰最旧。
3. 版次上限：**main 最多 4 个**，其余分支最多 2 个。
4. 每个分支目录下维护文件 `分支提交历史`，记录代码提交哈希顺序与每版次新增功能。

---

## 版次目录结构

```
<版本哈希>/
├── 项目架构.md              # 目录架构图、各模块功能与交互关系
├── 导航清单.md              # 模块级版本台账（供 导航体检.ps1 读取）
├── 模块架构/                # 各模块单一文件（含文件内目录、接口、实现细节、运行链路）
│   ├── Renderer/…
│   ├── Test/…
│   ├── EngineCore/…
│   └── EngineSystem/…
└── 待答疑清单.md            # 设计疑问 / 候选方案 / 临时做法（附编号与结案状态）
```

单文件规模建议 25 KB–500 KB（源码单薄的模块可低于 25 KB）。

---

## 新鲜度体检

- 每个版次目录维护一份 `导航清单.md`，记录“模块 → 源码范围 → 依据层 → 依据版次 → 更新日期”。
- 每份模块文档首部有一行 `> 依据版次：… ｜ 依据：… ｜ 更新：…`，由清单生成。
- 在工作站根运行 `.\导航体检.ps1`，脚本按源码 git 变更与更新日期输出“新鲜 / 源已变更 / 有未提交改动 / 路径缺失 / 无法比对”。
- `-StampHeaders` 按清单重写文件头；`-NoFail` 仅查看不返回失败码。
- 层版次（git 短哈希）不一致只作提示，不单独判过期；判定以模块源码范围的变更为准。
