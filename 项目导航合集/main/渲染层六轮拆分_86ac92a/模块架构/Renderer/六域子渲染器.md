## 二、模块功能介绍

### 2.1 模块定位

现行 `Renderer` 是六域容器与生命周期转发门面，不再以共享 `Renderer::Impl` 聚合全部上下文和通用字段。六个域分别为：

- `Render_Device`：设备、核心上下文、输出与整帧生命周期；
- `Render_Resource`：网格、纹理、材质、管线与渲染目标资源；
- `Render_Scene`：相机、场景装配、光照、雾、阴影请求与风格参数；
- `Render_Compute`：通用计算、GPU 剔除/压缩、Hi-Z 与 Cluster；
- `Render_Particle`：粒子数据源绑定、GPU 推进、紧凑索引与绘制；
- `Render_Ui`：UI 通道、原生 UI、输入、字体与文字。

“六域子渲染器”是导航对本组六个域对象的合称，不表示存在六个彼此独立、可各自完成初始化的渲染器。上层仍从 `engine::Renderer` 进入；根类公开面与六组访问器见[《门面》第〇章](门面.md#〇现行根门面305e06d)。

### 2.2 六域职责

| 域 | 公共头 / 私有状态头 | 核心职责 | 不负责 |
| --- | --- | --- | --- |
| 设备域 | `渲染设备.h` / `core/设备域状态.h` | 独占五个核心上下文与生效配置；执行 `init`、`shutdown`、`frame_render`；管理窗口/采样、离屏输出、后处理、SSAA/MSAA、阴影实际资源、剔除/合批/并行配置和整帧编排 | 不把场景用户参数、资源登记表或粒子/UI 专属状态收回自身 |
| 资源域 | `渲染资源.h` / `core/资源域状态.h` | 网格及程序化网格、纹理与天空盒、材质与逐物体覆盖、图形管线、渲染目标；提供场景描述符、原生资源快照、文字网格和 UI/粒子资源接线 | 不决定整帧输出路径，不持有五个核心上下文的所有权 |
| 场景域 | `渲染场景.h` / `core/场景域状态.h` | 相机与场景数据、方向光/补光/点光/聚光、雾与曝光、PBR/卡通/描边用户参数、方向光与聚光阴影用户配置；生成场景初始块和逐帧块 | 不持有聚光图集实际渲染目标，不直接执行整帧分派 |
| 计算域 | `渲染计算.h` / `core/计算域状态.h` | 计算能力与回读、计算缓冲/管线/调度、GPU 剔除与实例压缩、Hi-Z、Cluster 光源整备、粒子计算辅助 | 不拥有场景光源主数据，不代替粒子域持有粒子绘制资源 |
| 粒子域 | `渲染粒子.h` / `core/粒子域状态.h` | 应用粒子源绑定、开关/容量/发射器/参数、GPU 单步与常驻推进、billboard、紧凑索引、GPU/间接绘制与统计 | 不拥有应用传入的 `states/alive` 存储，不复制一套通用计算上下文 |
| 界面域 | `渲染界面.h` / `core/界面域状态.h` | UI 通道、原生 UI 与 UI 渲染、输入聚合、系统事件桥、字体、文字布局/缓存/绘制和文字描边 | 不代管上层 UI 库，不把字体图集、文字网格和管线改放到设备域 |

### 2.3 职责边界

1. **设备域只共享“核心底座”，不共享整棵实现状态。** 其余五域可取得 `Render_Core_Context`，但其中只有平台、设备、内存、交换链、帧和生效配置，没有任何其它域的私有字段。
2. **跨域动作按语义命名。** 需要其它域协作时，经 `owner->resource()`、`owner->compute()`、`owner->scene()`、`owner->particle()`、`owner->ui()`、`owner->device()` 调用明确接口，不读取对方 `state_ptr`。
3. **用户配置与运行时资源分离。** 典型例子是场景域保存阴影/描边用户参数，设备域保存实际阴影目标、管线和逐帧推送状态；粒子应用源与界面文字缓存也不进入共享核心上下文。
4. **域对象不是所有权 flattening。** 根 `Renderer` 拥有六个域；每个域拥有自己的状态分配。`owner` 与 `core` 都是非拥有观察指针，不用于延长根或设备域生命周期。

### 3.2 `Render_Core_Context`：核心底座窄上下文

`core/渲染上下文.h` 的完整数据面为：

```cpp
struct Render_Core_Context
{
    Platform_Context& platform;
    Device_Context& device;
    Memory_Context& memory;
    Swapchain_Context& swapchain;
    Frame_Context& frame;
    const Renderer_Config& config;
};
```

设备域构造时创建该对象，引用自己 `Device_State` 中的五个核心上下文与 `config`。资源、计算、场景、粒子、界面域构造时各保存一个 `const Render_Core_Context* core`。

- 它只暴露底层五上下文和只读配置，不包含六域指针、六域状态或通用绘制字段。
- `core` 指针本身为 const；五个上下文字段按声明为引用，`config` 为 const 引用。它不代表其它域可以绕过命名接口读取场景、资源等私有状态。
- 生命周期由设备域控制。其它域只观察，不销毁、不重置该对象。

## 五、模块内部架构介绍

### 5.1 对象与所有权关系

```text
engine::Renderer
├── device_domain   → Render_Device
│                     ├── Device_State（独占五个核心上下文、配置、帧/阴影/输出状态）
│                     └── Render_Core_Context（引用 Device_State 的五上下文与 config）
├── resource_domain → Render_Resource → owner + core + Resource_State
├── compute_domain  → Render_Compute  → owner + core + Compute_State
├── scene_domain    → Render_Scene    → owner + core + Scene_State
├── particle_domain → Render_Particle → owner + core + Particle_Domain_State
└── ui_domain       → Render_Ui       → owner + core + Ui_State
```

- 根到六域：`std::unique_ptr` 独占拥有。
- 设备域到 `Device_State`、`Render_Core_Context`：独立分配并持有；`Render_Core_Context` 不复制五个上下文。
- 其它五域到各自状态：`std::unique_ptr` 独占拥有；到根和核心上下文：非拥有裸指针观察。
- `Device_State` 继承 `Device_Frame_State` 与 `Device_Shadow_State`，继承只是设备域内部的状态分组，不形成新的跨域共享层。

### 5.2 私有状态归属

| 状态类型 | 归属与主要内容 |
| --- | --- |
| `Device_State` | 值持有 `Platform_Context`、`Device_Context`、`Memory_Context`、`Swapchain_Context`、`Frame_Context`、`Renderer_Config config` 和 `initialized`；继承帧录制状态与阴影状态；另持输出目标选择、后处理链/参数、SSAA、MSAA、渲染目标引用及相关运行配置 |
| `Resource_State` | 独占 `Shader_Context`、`Pipeline_Context`、`Mesh_Context`、`Texture_Context`、`Render_Target_Context`；具名管线、材质记录与共享管线、默认纹理、天空盒、LUT、逐物体材质覆盖、当前绑定视图/采样器/管线及默认着色器模块 |
| `Scene_State` | `Camera`、清屏色、方向光/补光、点光/聚光数组与计数、衰减/高光、环境光、雾、曝光、PBR、卡通、描边用户参数、方向光/级联/聚光阴影用户配置，以及 `spot_shadow_atlas_requested` 请求态 |
| `Compute_State` | `Compute_Context`、计算缓冲/管线登记、能力与统计、GPU 剔除/压缩、`HiZ_Context` 与生成管线、Cluster 开关/网格/管线；继承 `Cluster_Frame_State`，持有逐帧槽光源/计数/偏移/列表/占位缓冲及复用暂存 |
| `Particle_Domain_State` | 应用绑定的 `Particle_State* states` 与 `uint8_t* alive` 非拥有指针、源容量与 GPU 容量、发射器/参数、双缓冲、力场/控制/紧凑索引/间接命令缓冲、绘制网格与管线、常驻配置、临时复用数组及统计 |
| `Ui_State` | `Ui_Channel_Context`、`Ui_Context`、`Ui_Renderer`、UI 管线、`Ui_Event_Bridge`、`Font_Context`、`Text_Renderer`、`Input_Aggregator`、文字绘制回调标记与文字描边状态 |

补充所有权约束：粒子的 `states/alive` 由应用层提供，渲染层只保存观察指针；通常只读，GPU 推进回读时可写 `states`。界面域的 UI 通道仍只负责接线，不拥有上层 UI 库实例。

### 5.3 内部状态聚合头

`core/渲染器内部状态.h` 先包含层内各模块完整类型，再包含六个域状态头，供 `.cpp` 获得完整类型。它不声明通用状态对象，也不改变 §5.1 的所有权关系。

`core/帧录制状态.h`、`core/阴影域状态.h` 是设备域内部进一步拆分的状态分组；`core/渲染器_帧内部.h`、`core/渲染器内部工具.h/.cpp`、`core/结果检查.h` 分别承载帧内部契约、内部工具与统一 `VkResult` 检查。它们均不是旧共享 `Impl` 的替身。

## 六、模块设计/实现细节

### 6.1 关键行为约束

1. **有效性收口**：各域公开操作普遍以 `owner != nullptr && owner->device().valid()` 为运行前提；设备域的 `initialized` 是整帧生命周期的生效标记，而不是各域共享字段。
2. **分配方式**：根构造和域状态分配使用 `new(std::nothrow)`。构造阶段只建立对象与观察关系，不创建窗口或 GPU 资源；具体失败分支见 §7.1。
3. **窄依赖**：底层五上下文经 `core` 获取，高阶跨域动作经 `owner` 的命名接口完成。不得为省事新增通用字段包、重新开放对方状态或恢复共享 `Impl`。
4. **设备域编排而非包办**：初始化、帧和关闭主序由设备域决定，但资源、场景、计算、粒子、界面的具体状态仍由各自域方法处理。
5. **场景请求与实际效果分离**：描边用户参数在场景域，实际管线/推送在设备域；聚光图集请求在场景域，实际目标与生效状态在设备域。
6. **计算能力可降级**：设备不支持计算路径时，计算域可处于不支持状态，GPU 路径保持关闭；这不等价于整个渲染器初始化失败。
7. **粒子外部存储不转所有权**：应用替换绑定源或容量时，由粒子域按其公开契约处理缓冲重建与绘制，不把外部指针并入 `Render_Core_Context`。
8. **UI 边界不变**：界面域负责 UI/文字与渲染资源的接线，上层 UI 库的对象、后端初始化和业务控件生命周期仍由上层负责。

### 6.2 聚光阴影图集请求态

`Scene_State::spot_shadow_atlas_requested` 只表示用户是否请求聚光阴影图集。实际 `spot_shadow_atlas_target`、相关目标和生效状态由设备域持有。

- 场景应用路径读取请求值；仅当请求值相对上次发生变化时，才调用场景域自身 `spot_shadow_atlas_set`。该方法更新场景请求态后调用 `owner->device().spot_shadow_atlas_apply()`，由设备域应用实际资源变更，避免把请求写入误当作资源已经生效。
- 设备域帧/阴影路径经 `owner->scene().spot_shadow_atlas_requested()` 读取请求，再结合设备域实际目标执行图集创建、分块和绑定。
- `spot_shadow_atlas_request_clear()` 只把场景域请求布尔值置假，不销毁设备域目标。
- 设备域关闭链中，该清除调用位于 `if (state_ptr->initialized)` 分支内，与原有关闭路径语义一致；未进入已初始化关闭路径时不执行此调用。实际目标归还由设备域关闭逻辑负责，两者不可混写。

### 6.3 MSAA 采样数修复

初始化以已经创建的交换链为采样数真源，并同步设备域、资源域和生效配置三处：

1. `core/渲染器_初始化_内存与交换链.cpp` 先以单采样建链，取得颜色/深度格式后按设备共同支持能力钳制 2/4/8 请求，需要时重建交换链，最后直接读取实际交换链：

   ```cpp
   state.msaa_samples = state.swapchain.sample_count_get();
   ```

   初始化阶段不能依赖受 `initialized` 守卫的公开采样数 getter，否则可能仍得到默认 1×。

2. `core/渲染器_资源.cpp` 在 `Render_Resource::init` 末尾把同一实际值交给资源域渲染目标上下文：

   ```cpp
   (*state_ptr).render_target.sample_count_set(core->swapchain.sample_count_get());
   ```

   这一步是离屏目标与交换链采样数一致的必要修复；只写设备域状态或配置仍会留下渲染目标默认 1× 的不一致。

3. `core/渲染器_初始化.cpp` 收尾把设备域已择定值写入生效配置：

   ```cpp
   state_ptr->config.msaa_samples = state_ptr->msaa_samples;
   ```

运行时 `core/渲染器_采样与尺寸.cpp` 的 `Render_Device::msaa_samples_set` 先归一并按设备能力钳制请求，等待在途帧后设置并重建交换链，再调用 `owner->resource().render_target_sample_count_set(samples)` 和资源域 `pipeline_rebuild(...)`，随后同步 `Device_State::msaa_samples` 与 `config.msaa_samples` 并重绑默认纹理。失败语义必须分开记录：**交换链重建失败会恢复旧采样数并返回；渲染目标或图形管线重建失败只告警，不沿同一回滚分支返回。**

## 七、模块运行链路详例

### 7.1 构造链

入口：`Renderer::Renderer(void)`，实现于 `core/渲染器_生命周期.cpp`。

1. 以 `new(std::nothrow) Render_Device(this)` 创建 `device_domain`；为空则直接返回。
2. 设备域构造内部分配 `Device_State` 与 `Render_Core_Context`，并把核心上下文引用绑到设备域状态。
3. 根调用 `device_domain->core_context()`；为空则直接返回。
4. 依次以 `new(std::nothrow)` 创建：
   `Render_Resource(this, *core)` → `Render_Compute(this, *core)` → `Render_Scene(this, *core)` → `Render_Particle(this, *core)` → `Render_Ui(this, *core)`。
5. 每个非设备域保存 `owner`、`core` 并分配自己的状态对象。构造链结束时尚未执行平台、设备或交换链初始化。

因此设备域是核心上下文的创建者，资源域是首个消费者；计算、场景、粒子、界面随后获得同一份核心上下文观察指针。

### 7.2 初始化链

入口：上层 `Renderer::init(config)` → `device().init(config)`。设备域主入口完成校验与编排，六阶段主链如下：

```text
renderer_init_platform
  → renderer_init_memory_swapchain
  → renderer_init_frame_shader_pipeline
  → renderer_init_graphics
  → renderer_init_services
  → renderer_init_ui
```

| 阶段 | 主要动作与跨域关系 |
| --- | --- |
| 平台 | 创建平台窗口、实例扩展、Vulkan 实例、表面和逻辑设备；把平台窗口经 `owner->ui().input_window_bind` 交给界面域输入聚合 |
| 内存与交换链 | 创建 VMA 与交换链，按交换链能力钳制在途帧数；从实际交换链读取 MSAA 采样数，见 §6.3 |
| 帧与着色器/管线基础 | 创建帧上下文；资源域预留帧输入、加载场景着色器并建立管线基础设施和缓存 |
| 图形资源 | 资源域建立场景管线；计算域 `init`；场景域生成初始场景块；资源域建立/绑定 UBO、Cluster 占位描述符并执行资源初始化；准备描边、后处理、天空等图形资源 |
| 服务 | 资源域 `mesh_resource_build`；界面域 `font_resource_build`；粒子域 `init`；按交换链范围刷新场景相机宽高比 |
| 界面 | 界面域 `init`，完成 UI 通道、事件桥、输入与文字相关接线 |
| 主入口收尾 | 计算域应用配置；设备域按场景域阴影配置经资源域创建/绑定实际阴影资源；记录生效配置与 MSAA 采样数，置 `initialized` |

任一阶段失败时，由阶段实现经 `owner->device().shutdown()` 走统一回退；主入口返回假，不再用旧共享 `Impl` 做整棵字段清理。

### 7.3 帧链

入口：上层 `Renderer::frame_render(...)` → `device().frame_render(...)`。设备域主链顺序为：

1. 泵平台事件，推进界面域帧输入；处理关闭请求或最小化挂起。
2. 消费窗口尺寸变化，按需重建交换链并重建资源域管线。
3. 按交换链有效范围刷新场景相机宽高比。
4. 由场景域构建方向光/聚光阴影矩阵；设备域按需执行阴影 pass。
5. 取得并等待当前帧槽。
6. 调 `compute().cluster_frame_update(slot, frame_count)` 整备本帧 Cluster 数据。
7. 读取场景相机矩阵，推进界面域文字帧缓存。
8. 由场景域 `scene_frame_block_fill` 生成场景块并写入本帧槽 UBO。
9. 准备后处理、SSAA 与天空所需状态和实际资源。
10. 上传/更新实例缓冲，执行静态合批。
11. 资源域填装本帧描述符集，并准备天空绘制项。
12. `frame_stage_dispatch` 按设备域输出状态分派离屏、后处理呈现或交换链路径；必要时处理呈现后的交换链重建。
13. 完成帧计数与统计。

帧链中的核心时序约束是：**阴影矩阵/pass 在帧槽等待前完成其编排，Cluster 在场景帧块前整备，实例/描述符/天空项在最终分派前就绪**。不要仅按文件名把各阶段重新拼接成另一套顺序。

### 7.4 关闭链

入口：上层 `Renderer::shutdown()` 或析构兜底 → `device().shutdown()`。

1. 停止并行工作线程。
2. 在原 `initialized` 关闭路径中归还方向光/聚光阴影管线、目标与图集资源，并调用场景域 `spot_shadow_atlas_request_clear`。
3. 场景域 `shutdown`，复位场景用户状态。
4. 粒子域 `shutdown`，归还粒子计算与绘制资源。
5. 销毁帧上下文，收口在途帧与延迟销毁。
6. 界面域 `shutdown`，归还文字/UI 资源并复位界面状态。
7. 资源域 `shutdown`，归还字体、网格、纹理、目标和域内资源。
8. 复位设备域输出/后处理/SSAA、MSAA、剔除和帧暂存状态。
9. 归还场景 UBO、实例、间接绘制和 Cluster 等内存缓冲。
10. 在管线缓存销毁前读取缓存字节并按配置写盘；该可选步骤不中断后续关闭。
11. 计算域 `shutdown`，归还计算、Hi-Z 与 Cluster 私有资源。
12. 执行资源域 `pipeline_shutdown`，归还管线与具名管线着色器资源。
13. 销毁交换链与内存上下文。
14. 解除平台事件桥，依次销毁平台与设备上下文。
15. 清空设备域待绘制项并复位 `frame_count` 与 `initialized`。

关闭顺序体现跨域依赖：粒子、界面先于其依赖的资源域收尾；帧与延迟销毁先于底层内存/设备回收；管线缓存读取先于计算域关闭，计算与管线资源又在交换链、内存、平台、设备之前完成归还。

### 7.5 Cluster 跨域链

1. 设备域在帧槽等待后调用 `owner->compute().cluster_frame_update`。
2. 计算域通过 `core` 使用帧/设备等底座，通过 `owner->scene()` 的相机 getter 与 `light_records_get` 取得只读场景快照。
3. 计算域用自己的 `Compute_State` 与 `Cluster_Frame_State` 完成光源记录、计数、前缀偏移、列表写入和逐帧槽缓冲复用。
4. 设备/资源域经 `cluster_placeholder_native`、描述符绑定等命名接口取得需要绑定的计算资源，不读取 `Compute_State` 字段。
5. 场景域随后生成包含 Cluster 开关/网格信息的帧场景块，最终由设备域统一分派。

该链说明 `core` 与 `owner` 的分工：前者提供底层上下文，后者提供高阶语义协作，两者都不暴露他域私有状态。
