统一约定：自由函数、首参 `Renderer_Impl_Holder::Impl*`、函数体保留原始 `impl->` 前缀。**不要改成成员函数**——去前缀后块内同名局部量会静默接管成员访问（曾导致纹理创建永久阻塞）。抽取时还需注意：

- 块内 lambda 若写 `[this, ...]`，必须改为 `[impl, ...]`；
- `Impl::常量` 必须补成全限定名。

## 四、拆分脚本的工作方式（便于重开发）

`Frame` / `Pipeline` / `RenderTarget` 的拆分按「函数定义 + 花括号配对」机械搬运，不重排、不改函数体。已知两个坑：

1. 输出文件名**不能与源文件同名**，否则会先覆盖源文件再报「有函数未归属」，导致函数丢失（本轮 `目标创建.cpp` 踩过一次，已从 git 恢复）。
2. 文件级 `static` 辅助函数位于两个成员函数之间，不属于前导区，机械切分时会落在所有分组之外——必须在切分后手工补回（本轮 `instance_matrices_append`、`spot_shadow_tiles_ensure_impl`、`spot_shadow_atlas_apply_impl` 均属此类）。
