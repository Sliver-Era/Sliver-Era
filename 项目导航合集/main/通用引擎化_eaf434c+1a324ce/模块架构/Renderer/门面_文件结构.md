## 一、现行目录与公共头

```text
Renderer/
├── 渲染器.h                  ← 根六域容器、六组 const/非 const 访问器、十四项生命周期转发
├── 渲染设备.h                ← Render_Device：生命周期、输出、帧与设备域窄接口
├── 渲染资源.h                ← Render_Resource：网格/纹理/材质/管线/渲染目标
├── 渲染场景.h                ← Render_Scene：相机/光照/雾/阴影请求/风格
├── 渲染计算.h                ← Render_Compute：计算/剔除/Hi-Z/Cluster
├── 渲染粒子.h                ← Render_Particle：粒子推进/紧凑/绘制
├── 渲染界面.h                ← Render_Ui：UI/输入/字体/文字
├── 渲染器类型.h              ← 配置、统计与公共语义类型
├── 渲染器_UI通道.h           ← 含 Vulkan/SDL3 类型的 UI 通道公共扩展头
├── 局部命名空间使用.h
└── core/
    ├── 渲染上下文.h           ← 五核心上下文引用 + const Renderer_Config&
    ├── 设备域状态.h           ← Device_State；另继承帧录制/阴影状态
    ├── 资源域状态.h           ← Resource_State
    ├── 场景域状态.h           ← Scene_State
    ├── 计算域状态.h           ← Compute_State / Cluster_Frame_State
    ├── 粒子域状态.h           ← Particle_Domain_State
    ├── 界面域状态.h           ← Ui_State
    ├── 渲染器内部状态.h        ← 完整类型与六域状态头的聚合包含头，非共享 Impl
    ├── 帧录制状态.h / 阴影域状态.h
    ├── 渲染器_帧内部.h / 渲染器内部工具.h,.cpp / 结果检查.h
```

六个公共域头与根头的关系见[《六域子渲染器》§2、§3](六域子渲染器.md#二模块功能介绍)；私有状态头的归属见[《六域子渲染器》§5](六域子渲染器.md#五模块内部架构介绍)。

### A.4 拆分脚本的工作方式（便于重开发）

`Frame` / `Pipeline` / `RenderTarget` 的拆分按「函数定义 + 花括号配对」机械搬运，不重排、不改函数体。已知两个坑：

1. 输出文件名**不能与源文件同名**，否则会先覆盖源文件再报「有函数未归属」，导致函数丢失（本轮 `目标创建.cpp` 踩过一次，已从 git 恢复）。
2. 文件级 `static` 辅助函数位于两个成员函数之间，不属于前导区，机械切分时会落在所有分组之外——必须在切分后手工补回（本轮 `instance_matrices_append`、`spot_shadow_tiles_ensure_impl`、`spot_shadow_atlas_apply_impl` 均属此类）。
