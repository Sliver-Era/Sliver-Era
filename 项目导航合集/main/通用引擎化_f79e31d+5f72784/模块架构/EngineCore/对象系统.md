# 对象系统 · 模块架构

> 模块路径（相对源码根）：`Engine/EngineFoundation/src/object/`
> 本模块为 EngineFoundation 的**对象槽位托管层**，对外唯一产物是对象池模板 `Object_Pool<T, Key>`。
> 本文件按当前工作区源码重写：`Object` 基类已删除，对象池不再要求 `T` 派生自任何基类，也不自行分配对象编号。
> 定位键由调用方提供，对象池负责把键写入对象并维护「键 → 槽位索引」映射。

## 二、模块功能介绍

### 2.1 模块定位

本模块提供**连续槽位存储 + 键定位**的对象托管能力：

- 以 `std::vector<T>` 连续存放对象，避免逐对象堆分配；
- 以索引分配器回收/复用槽位，避免频繁扩容；
- 以「定位键 → 槽位索引」映射提供 O(1) 查找（哈希模式）或 O(log n) 查找（排序模式）；
- 由对象池在构建时把定位键写入对象，保证映射与对象内键字段始终一致。

对象池**不分配对象编号**，也不拥有任何业务语义。定位键完全由调用方定义（如实体编号、实体槽位索引、字符串名称）。

### 2.2 职责边界

| 归属 | 内容 |
| --- | --- |
| **属于本模块** | 槽位分配/回收、有效区前缀维护、构建与卸载、单/批量构建、键写入与判重、哈希/排序两种定位模式、槽位预分配、有效区迭代 |
| **不属于本模块** | 对象编号分配（由调用方自持 `Number_Pool` 或其他编号源）、对象生命周期之外的业务状态、线程同步、持久化 |

### 2.3 解决的问题

1. **大量短生命周期对象的分配抖动**：槽位复用替代逐对象 new/delete。
2. **编号与存储解耦**：编号策略归调用方，对象池只负责「键对应的槽位」。
3. **一致定位**：构建时强制写键，避免「调用方忘记同步键字段」导致映射失效。
4. **两种访问口径**：默认哈希定位适合高频点查；排序模式适合按键有序遍历与二分查找。

### 2.4 在整体架构中的位置

- **下行依赖**：
  - `Engine/EngineFoundation/common/前置头文件包含.h`（标准库）；
  - `Engine/EngineFoundation/src/detail/class/Number_Pool/数值池.h`（索引分配器 `Number_Pool<uint64_t>`，`get()` 返回 `std::optional<uint64_t>`）；
  - `Engine/EngineFoundation/src/detail/methods/二分查找.h`（排序模式点查）。
- **上行消费方**：
  - `EngineSystem::Input_Manager`：`Object_Pool<Input_Object>`，键为对象编号，编号由 `Input_Manager` 自持的 `Number_Pool<uint64_t>` 分配；
  - `EngineSystem` ECS 组件存储：`Object_Pool<C, uint32_t>`，键为组件 `owner`（实体槽位索引）；
  - `Application/Game/星屑弹幕`：敌人/投射物/掉落物三池，键为实体编号，编号由 `Entity_Store` 自持的 `Number_Pool<uint64_t>` 分配。

### 2.5 文件清单

| 文件 | 形态 | 对外产出 |
| --- | --- | --- |
| `src/object/对象系统运行包.h` | 聚合头 | 统一引入 PCH 与 `Object_Pool/对象池.h` |
| `src/object/Object_Pool/对象池.h` | 纯头文件模板 | 枚举 `Object_Order`、类模板 `Object_Pool<T, Key>` |

> `Object/对象.h` 与 `Object_Pool/core/对象池实例化.cpp` 已删除：前者随「删除 Object 基类」移除，后者因模板改为严格按需实例化而不再需要显式实例化。

### 2.6 与相邻模块的职责分界

- 与**工具集**：对象池复用 `Number_Pool<uint64_t>` 做槽位分配/回收，复用 `detail::binary_search` 做排序模式点查；工具集不感知对象语义。
- 与**事件系统**：对象池不持有事件终端，也不参与事件路由；消费方自行把事件终端放进 `T`。
- 与**ECS**：组件存储把对象池包成 `Component_Storage_Impl<C>`，对象池本身不知道「实体」「组件」概念。
- 与**渲染层**：对象池不产出任何渲染结构；渲染层只消费上层给出的快照。

## 三、模块公开接口介绍

### 3.1 枚举 `Object_Order`

```cpp
enum class Object_Order
{
    Unorder,   // 哈希定位：键 → 槽位索引 的 unordered_map
    Sorted     // 排序定位：有效区按键有序，点查走二分查找
};
```

### 3.2 类模板 `Object_Pool<T, Key>`

```cpp
template <typename T, typename Key = uint64_t>
class Object_Pool
{
public:
    explicit Object_Pool(std::function<Key&(T&)> proj);
    ~Object_Pool();

    void mode_set(Object_Order mode,
        std::function<bool(const Key&, const Key&)> cmp = {});

    typename std::vector<T>::iterator find(const Key& key);
    typename std::vector<T>::const_iterator find(const Key& key) const;

    uint64_t build(const Key& key, T object = {});
    std::vector<uint64_t> build(const std::vector<Key>& keys);
    std::vector<uint64_t> build(const std::vector<Key>& keys, std::vector<T> object_set);

    bool sort(void);

    bool try_unload(const Key& key);
    void unload(const Key& key);
    void unload(const std::vector<Key>& keys);

    void clear(void);
    bool reserve(const uint64_t& num);
    uint64_t capacity(void) const;
    uint64_t size(void) const;

    typename std::vector<T>::iterator begin(void);
    typename std::vector<T>::const_iterator begin(void) const;
    typename std::vector<T>::iterator end(void);
    typename std::vector<T>::const_iterator end(void) const;
};
```

#### 3.2.1 模板参数与前置约束

| 项 | 约束/含义 |
| --- | --- |
| `T` | 可默认构造（`build(key)`、`reserve`）、可移动；不再要求派生自 `Object` |
| `Key` | 可哈希（`std::unordered_map`）且满足 `std::totally_ordered_with`（排序模式的 `std::ranges::less`） |
| 投影器 | `std::function<Key&(T&)>`，返回对象内**可写**的键字段引用；构造函数强制注入 |

#### 3.2.2 构造 / 析构

| 接口 | 行为 |
| --- | --- |
| `explicit Object_Pool(std::function<Key&(T&)> proj)` | 记录投影器；索引分配器设为 `LIFO`，起点 `0` |
| `~Object_Pool()` | 空体；`objects` 由自身析构 |

#### 3.2.3 定位模式

| 接口 | 行为 |
| --- | --- |
| `mode_set(Object_Order::Sorted, cmp)` | 首次进入时清空映射；记录比较器（缺省 `std::ranges::less`）；对有效区排序 |
| `mode_set(Object_Order::Unorder)` | 若当前为排序模式：标记回到哈希模式、按有效区重建映射、比较器复位；若已是哈希模式：只告警「当前已为目标模式」 |

#### 3.2.4 查找

| 接口 | 行为 |
| --- | --- |
| `find(key)` | 哈希模式走 `mapping`；排序模式走 `detail::binary_search`（比较器作用于投影键）。未命中返回 `end()` |
| `find(key) const` | 转调非常量重载，迭代器隐式转常量 |

#### 3.2.5 构建

| 接口 | 返回 | 行为 |
| --- | --- | --- |
| `build(key, T object = {})` | 槽位索引 | 键已存在则告警并返回 `UINT64_MAX`；否则分配槽位、写入键、登记映射（哈希模式），排序模式下末尾重排 |
| `build(const std::vector<Key>& keys)` | 成功构建的索引集合 | 转调「键 + 实参」重载，实参集合为 `std::vector<T>(keys.size())` |
| `build(const std::vector<Key>& keys, std::vector<T> object_set)` | 成功构建的索引集合 | 键与实参数量不一致时告警并按较小规模处理；重复键逐个跳过；槽位分配失败即终止批量构建 |

构建返回的槽位索引在**下一次构建/卸载前**可用；`UINT64_MAX` 是失败哨兵。

#### 3.2.6 排序

| 接口 | 行为 |
| --- | --- |
| `sort()` | 仅排序模式有效；对有效区 `[begin(), end())` 按投影键与比较器排序；非排序模式返回 `false` |

#### 3.2.7 卸载

| 接口 | 行为 |
| --- | --- |
| `try_unload(key)` | 目标不存在返回 `false`；存在则移除映射、把目标与无效区边界交换、回收槽位索引、`min_valid_index++`，排序模式下重排 |
| `unload(key)` | 转调 `try_unload`，失败时告警 |
| `unload(const std::vector<Key>& keys)` | 去重后收集槽位索引，升序排序后逐个执行「与无效区边界交换 + 回收」；排序模式下末尾重排 |

#### 3.2.8 清空 / 预分配 / 容量

| 接口 | 行为 |
| --- | --- |
| `clear()` | 清空对象集合；索引分配器 `reset` 后恢复 `LIFO` 与起点 `0`；`min_valid_index=0`；哈希模式下清空映射 |
| `reserve(num)` | 仅当池为空时可用；预创建 `num` 个默认对象并把整个前缀划入无效区；否则返回 `false` |
| `capacity()` | 物理槽位数（含无效区） |
| `size()` | 有效对象数 `capacity() - min_valid_index` |

#### 3.2.9 迭代

`begin()/end()` 只覆盖**有效区** `[min_valid_index, objects.size())`。哈希模式下有效区不保证按键有序；排序模式下按键有序。

## 四、模块私有方法介绍

| 私有成员 | 作用 |
| --- | --- |
| `key_get(const T&) const` | 常量上下文读键；投影器需要可写引用，故内部 `const_cast` 后调用 |
| `slot_build(const Key&, T&&)` | 分配槽位、构造/重建对象、交换到无效区边界、写入键、登记映射；返回槽位索引或 `UINT64_MAX` |
| `keys_collect() const` | 遍历有效区收集全部定位键，供批量构建判重 |

`slot_build` 的索引分配失败处理：`Number_Pool::get()` 返回 `std::nullopt` 时记录 `logger.error` 并返回 `UINT64_MAX`，不构造对象、不写键。

## 五、模块内部架构介绍

### 5.1 数据成员

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `index_pool` | `Number_Pool<uint64_t>` | 槽位索引分配/回收（LIFO，起点 0） |
| `min_valid_index` | `uint64_t` | 有效区起点；前缀 `[0, min_valid_index)` 为无效区 |
| `objects` | `std::vector<T>` | 对象槽位（无效区对象仍保留在容器中） |
| `projector` | `std::function<Key&(T&)>` | 键字段的可写投影 |
| `is_sorted` | `bool` | 是否排序模式 |
| `mapping` | `std::unordered_map<Key, uint64_t>` | 哈希模式的键 → 槽位索引 |
| `compare` | `std::function<bool(const Key&, const Key&)>` | 排序模式的键比较器，缺省 `std::ranges::less` |

### 5.2 有效区不变量

1. `[0, min_valid_index)` 为无效区，`[min_valid_index, objects.size())` 为有效区；
2. 无效区对象仍处于构造状态，但不可被查找/迭代；
3. 有效区对象数量恒等于 `size()`；
4. 哈希模式下，有效区每个对象的 `projector(obj)` 键都在 `mapping` 中有且仅有一条映射，且映射索引落在有效区内。

### 5.3 两种定位模式的切换

```
Unorder --mode_set(Sorted)--> 清空 mapping + sort(有效区)
Sorted  --mode_set(Unorder)--> 按有效区重建 mapping + 比较器复位
```

排序模式下 `mapping` 为空，`find` 完全依赖二分查找；因此排序模式的正确性依赖「有效区始终有序」，构建/卸载末尾的 `sort()` 负责维持该不变量。

### 5.4 类关系

- `Object_Pool<T, Key>` **组合** `Number_Pool<uint64_t>`（索引来源）；
- **组合** `std::vector<T>`、`std::unordered_map<Key, uint64_t>`、两个 `std::function`；
- **依赖** `detail::binary_search`（排序模式点查）；
- 与 `Object` 已无关系（该类已删除）。

## 六、模块设计/实现细节

### 6.1 键由调用方定义，对象池强制写键

`build` 的键是调用方提供的「身份」，对象池在槽位构建完成后执行：

```cpp
projector(objects[slot_index]) = key;
```

因此外部传入的 `T object` 即使键字段是旧值，也会被覆写为目标键。该设计消除了「映射键」与「对象内键字段」不一致的可能。

### 6.2 键唯一性

- 单对象构建：`find(key) != end()` 即判为重复，告警并返回 `UINT64_MAX`；
- 批量构建：先用 `keys_collect()` 收集既有键，再用局部集合去重，重复键逐个跳过。

对象池不提供「同键覆盖」语义；替换对象必须先 `unload` 再 `build`。

### 6.3 槽位分配与回收

- 构建时向 `Number_Pool::get()` 申请索引；返回 `nullopt` 即分配失败（容量耗尽），记录错误并返回失败哨兵；
- 获得索引后：若索引越界则 `push_back`，否则销毁旧对象并原地重建；
- 若无效区非空，把新对象与 `objects[--min_valid_index]` 交换，使其落入有效区头部；
- 卸载时把目标与 `objects[min_valid_index]` 交换，然后回收 `min_valid_index` 并自增。

### 6.4 卸载的搬移语义

卸载会把无效区边界的有效对象换入目标槽位。由此产生两条调用约定：

1. **槽位引用/指针不稳定**：卸载任意对象后，先前取得的 `T*`/迭代器可能已指向另一对象；
2. **遍历中不得卸载**：边遍历边卸载会导致重复处理或漏处理。

现有消费方均采用「先收集键，遍历结束后统一卸载」的方式规避（如星屑弹幕的 `advance` / `reset`）。

### 6.5 投影键字段不得外部改写

哈希模式的 `mapping` 只在构建/卸载/模式切换时维护。若调用方在对象存活期间直接修改键字段，映射会与对象失配。键字段应在 `build` 后视为只读；需要换键时应卸载后重建。

### 6.6 失败哨兵

- 槽位索引从 `0` 起，`0` 是**合法**索引（与旧版「0 为非法对象 ID」不同）；
- 构建失败统一返回 `UINT64_MAX`；
- 批量构建遇到分配失败立即终止，不把失败哨兵写入返回数组。

### 6.7 容量与预分配

- `capacity()` 统计物理槽位，包含无效区；
- `reserve(num)` 只在空池时可用，预创建的槽位全部划入无效区，后续构建优先复用；
- 预分配不与索引分配器同步推进，构建时按分配器给出的索引原地重建。

### 6.8 异常与线程

- 模块不使用异常路径；容器自身的分配失败按标准库语义抛出（由外层决定是否兜底）；
- 模块不含任何同步原语，同一对象池的并发构建/卸载/查找均属数据竞争；约定由单一所有者线程持有。

### 6.9 排序模式的键约束

`compare` 缺省为 `std::ranges::less`，要求 `Key` 满足 `std::totally_ordered_with`。当前实际键类型（`uint64_t`、`uint32_t`、`std::string`）均满足。

## 七、模块运行链路详例

### 7.1 单对象构建（哈希模式）

1. `build(key, object)` → `find(key)` 判重；
2. `slot_build(key, std::move(object))`：
   - `index_pool.get()` 取索引（`nullopt` → 错误日志 + `UINT64_MAX`）；
   - 越界则 `push_back`，否则销毁并原地重建；
   - 无效区非空则与边界交换；
   - `projector(obj) = key`；
   - `mapping.insert_or_assign(key, index)`；
3. 排序模式下追加 `sort()`；
4. 返回槽位索引。

### 7.2 查找（哈希模式）

`find(key)` → `mapping.find(key)` → 命中则 `objects.begin() + index`，否则 `end()`。

### 7.3 查找（排序模式）

`find(key)` → `detail::binary_search(begin(), end(), key, compare, key_get投影)` → 命中返回 `begin() + index`，否则 `end()`。

### 7.4 卸载（单对象）

1. `find(key)`；未命中返回 `false`；
2. 记录目标索引与目标键；
3. 哈希模式移除映射；
4. 目标不在无效区边界则与 `objects[min_valid_index]` 交换，并更新被交换对象的映射索引；
5. `index_pool.recycle(min_valid_index)`，`min_valid_index++`；
6. 排序模式追加 `sort()`。

### 7.5 批量卸载

1. 去重键并逐个 `find`，收集槽位索引（未命中仅告警）；
2. 索引升序排序；
3. 逐个执行「交换到无效区边界 + 回收索引 + 前缀自增」；
4. 排序模式追加 `sort()`。

### 7.6 消费方编号链路（示例：星屑弹幕）

1. `Entity_Store` 自持 `Number_Pool<uint64_t> id_pool`（起点 1）；
2. `spawn_*`：`id_pool.get()` 取编号（`nullopt` → 返回 0）→ `pool.build(id)`；
3. `unload_*`：`pool.unload(id)` → `id_pool.recycle(id)`；
4. 遍历使用 `pool.begin()/end()` 的有效区；需要卸载时先收集 `.id`，遍历结束后统一卸载。
