# 世界数据（粒子 / 场景）· 模块架构

> 模块路径（相对源码根）：`Engine/EngineSystem/src/world/data/`
> 本模块只提供**图形 API-free 的纯数据与文本解析**：粒子状态/参数、场景清单、关卡数据与关卡文本。
> 不创建 GPU 资源、不持有渲染句柄；渲染层只消费这些类型与数据。

## 二、模块功能介绍

### 2.1 粒子（`particle/`）

- `Particle_Data/粒子数据.h`：
  - `Particle_State`：32 字节（位置 12 + 速度 12 + 年龄 4 + 寿命 4），与 GPU std430 布局一致；
  - `Emit_Shape`：点 / 盒 / 球壳；
  - `Force_Type`：引力点 / 涡流 / 风；
  - `Particle_Force_Field`：力场（40 字节，与 GPU 布局逐字段一致）；
  - `Particle_Emitter`：发射器（位置、范围、方向、速度/寿命区间、计数等）；
  - `Particle_Params`：模拟参数（重力、阻尼等）。
- `Particle_Pool/粒子系统.h`：`Particle_System`，图形 API-free 的粒子池与 CPU 参考模拟。

### 2.2 场景（`scene/`）

- `scene/Manifest/场景清单.h`：`Scene_Manifest` / `Scene_Mesh_Ref` / `Scene_Mtl_Ref` / `Scene_Place` 与文本解析；
- `scene/Level/场景数据.h`：`Camera_Data` / `Light_Data` / `Fog_Data` 等纯数据类型；
- `scene/Level/关卡数据.h`：`Level_Data`、`Level_Material`（材质实例声明）；
- `scene/Level/关卡文本.h`：关卡文本读写（`level_text_read` / `level_text_write` / 材质实例查表）；
- `scene/Level/core/关卡变换.cpp`：关卡内变换计算。

## 三、模块公开接口介绍

### 3.1 `Particle_System`

| 接口 | 行为 |
| --- | --- |
| `capacity_set(capacity)` / `capacity_get()` | 容量设置（钳制到 `[1, PARTICLE_CAPACITY_MAX]`，收缩时丢弃超出容量的粒子）/ 查询 |
| `active_count_get()` | 当前活跃粒子数 |
| `spawn(index_out)` | 分配一个粒子（不初始化状态）；池满返回假；LIFO 复用回收索引 |
| `recycle(index)` | 回收指定索引；非法/重复回收返回假 |
| `clear()` | 清空全部粒子并复位回收栈（保留容量） |
| `step(params, dt)` | 推进一个固定步：`v += gravity·dt` → `v *= damping` → `p += v·dt` → `age += dt`；`age ≥ lifetime` 即回收；返回本步死亡数 |
| `emit(emitter, budget)` | 按发射器形状采样位置与速度；`budget` 为本帧最多发射数；池满即停止 |
| `seed_set(seed)` | 重置确定性随机种子 |
| `data_get()` / `alive_get()` | 状态数组 / 逐索引活跃标记（长度 = 容量，供 GPU 上传） |

### 3.2 场景清单

- `Scene_Manifest{ meshes, materials, places }`；
- 文本行格式：`mesh <网格ID> <OBJ路径>`、`mtl <材质ID> <MTL路径>`、`place <网格ID> [材质ID] <x y z> <sx sy sz> [<rx ry rz>]`；
- 路径相对清单文件目录；`#` 起首为注释；仅解析，不建资源。

### 3.3 关卡数据与文本

- `Level_Data` 聚合相机 / 光照 / 雾三组 + 资产声明 + 材质实例声明；
- `Level_Material`：实例名、模板材质名，以及 tint / emissive / toon / pbr / clearcoat 可选覆盖；
- `level_text_read(path, out)` / `level_text_write(level, path)`：行式文本读写，浮点按 `%.9g` 写出，保证 32 位浮点往返逐位一致；
- 材质实例查表：按实例名在 `Level_Data.materials` 中查找并复制。

## 四、模块设计/实现细节

1. **布局契约**：粒子状态与力场字段顺序、大小严格对齐 GPU `std430`，由静态断言守住；系统层与渲染层共用同一份类型。
2. **纯数据**：所有结构不含 GPU 句柄、不含虚函数；系统层不反向依赖渲染层。
3. **CPU 参考模拟**：`Particle_System::step` / `emit` 与 GPU 推进同公式，便于确定性对照；默认固定 LCG 种子。
4. **文本层职责**：清单/关卡解析只做「文本 ↔ 数据结构」，不校验资产文件存在、不建资源、不做场景应用。
5. **失败即清空**：关卡文本读取失败时返回假并清空输出，避免半成品。
6. **线程**：粒子池与解析器均无内部同步，由调用方保证单线程或外部加锁。

## 五、模块运行链路详例

### 5.1 粒子帧推进

1. `emit(emitter, budget)`：按形状采样位置与速度，`spawn` 取索引并写入状态；
2. `step(params, dt)`：对活跃粒子推进速度/位置/年龄，死亡即 `recycle`；
3. `data_get()` / `alive_get()` 交给渲染层上传；
4. 渲染层按自身管线完成模拟或直接绘制。

### 5.2 场景清单装载

1. 读取清单文本 → 解析为 `Scene_Manifest`；
2. 应用层按 `meshes` / `materials` 装载资产；
3. 按 `places` 逐条装配实例（位置 / 缩放 / 可选旋转）。

### 5.3 关卡装载

1. `level_text_read` → `Level_Data`（相机、光照、雾、资产行、材质实例）；
2. 应用层按资产行装载网格/材质，按 `Level_Material` 覆盖实例参数；
3. 渲染层消费纯数据快照完成场景应用。
