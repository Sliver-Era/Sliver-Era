## 二、模块功能介绍

### 2.1 模块定位

以「实体句柄 + 组件池 + 组件掩码」构成纯数据 ECS：

- `Entity_Table` 负责槽位分配、代际推进与组件掩码；
- `Component_Storage_Impl<C>` 以 `Object_Pool<C, uint32_t>` 按实体槽位索引存储组件；
- `ECS_Store` 作为统一入口，注册组件类型并派发增删查与遍历；
- `Command_Buffer` 在遍历期间收集结构变更，遍历结束后统一提交。

### 2.2 职责边界

| 归属 | 内容 |
| --- | --- |
| **属于本模块** | 实体句柄编解码、槽位/代际管理、组件存取、组件掩码、单/双组件遍历、延迟命令 |
| **不属于本模块** | 系统调度、业务规则、碰撞/输入/骨骼语义、渲染资源 |

### 2.3 文件清单

| 文件 | 产出 |
| --- | --- |
| `entity/Entity/实体.h` | 实体句柄 `Entity`（代际 + 槽位）与 `entity_make` |

## 三、模块公开接口介绍

### 3.1 `Entity`

```cpp
struct Entity
{
    uint64_t value = 0;          // 高 32 位代际，低 32 位槽位
    uint32_t index() const;
    uint32_t generation() const;
    bool empty() const;          // value == 0
    bool operator==(const Entity&) const;
    bool operator!=(const Entity&) const;
};
```

槽位 0 预留、代际从 1 起，故 `value == 0` 为无效句柄。

### 3.2 `Entity_Table`

| 接口 | 行为 |
| --- | --- |
| `entity_create()` | 从 `Number_Pool<uint32_t>` 取槽位（起点 1）；扩展记录、置存活、重置掩码；代际为 0 时修正为 1 |
| `entity_destroy(entity)` | 校验句柄存活；置非存活、清掩码、代际加一（回绕到 0 修正为 1）；回收槽位索引 |
| `entity_alive(entity)` | 句柄非空、槽位不越界、记录存活且代际一致 |
| `entity_from_index(index)` | 由槽位取当前代际句柄；不存活返回空句柄 |
| `mask_get` / `mask_bit_assign` / `mask_bit_get` | 64 位组件掩码读写（位 ≥ 64 拒绝） |
| `size()` / `clear()` | 存活数量；清空记录并把分配器复位到起点 1 |

### 3.3 `Component_Storage` / `Component_Storage_Impl<C>`

- `Component_Type` 约束：可移动，且可写 `component.owner`。
- `Component_Storage` 为类型擦除基类：`erase(uint32_t)`、`clear()`、`size()`、`bit_get()`。
- `Component_Storage_Impl<C>` 内部：
  - `Object_Pool<C, uint32_t> pool`，投影器返回 `component.owner` 的可写引用；
  - `add(entity_index, C)`：已存在返回空；否则 `pool.build(entity_index, std::move(component))` 并返回组件指针；
  - `find(entity_index)`、`erase(entity_index)`、`clear()`、`size()`、`pool_get()`。

### 3.4 `ECS_Store`

| 接口 | 行为 |
| --- | --- |
| `entity_create()` / `entity_destroy()` / `entity_alive()` / `entity_size()` | 转发实体表；销毁时先逐组件池 `erase(index)` |
| `component_add<C>(entity, args...)` | 校验句柄；按需注册组件类型；已存在返回空；构造并添加组件、置掩码位 |
| `component_get<C>` / `component_has<C>` | 句柄存活且类型已注册时查组件 |
| `component_remove<C>` | 删除组件并清掩码位 |
| `component_size<C>` | 组件池有效数量 |
| `component_each<C>(fn)` | 遍历组件池，按 `owner` 还原实体句柄，跳过不存活实体 |
| `each<C1, C2>(fn)` | 以较小池驱动，按 `owner` 查另一组件，二者都存在才回调 |
| `clear()` | 清空全部组件池与实体表，保留组件类型注册 |

### 3.5 `Command_Buffer`

| 接口 | 行为 |
| --- | --- |
| `entity_destroy(entity)` | 延迟销毁实体 |
| `component_add<C>(entity, C)` | 延迟添加组件 |
| `component_remove<C>(entity)` | 延迟删除组件 |
| `flush(ECS_Store&)` | 按入队顺序执行并清空 |
| `clear()` / `size()` | 清空 / 命令数量 |

`entity_create` 不进入缓冲：创建需要立即返回句柄。

## 四、模块内部架构介绍

### 4.1 数据结构

- `Entity_Table::records`：`std::vector<Entity_Record>{generation, mask, alive}`，下标即槽位；
- `index_allocator`：`Number_Pool<uint32_t>`，LIFO，起点 1；
- `ECS_Store::storages`：`type_index → unique_ptr<Component_Storage>`；
- `ECS_Store::bits`：`type_index → 掩码位`；`next_bit` 从 0 递增，超过 64 拒绝注册。

### 4.2 组件归属

组件的 `owner` 字段既是对象池定位键，也是「组件 → 实体槽位」的唯一关联。组件池不感知实体代际；遍历时统一用 `entity_from_index(owner)` 还原句柄并丢弃已死实体。

### 4.3 类型擦除

`Component_Storage` 只暴露与类型无关的操作，`ECS_Store` 通过 `type_index` 找到存储后在模板接口内 `static_cast` 回 `Component_Storage_Impl<C>*`。

## 五、模块设计/实现细节

1. **代际防悬垂**：槽位复用后旧句柄因代际不一致而失效。
2. **槽位 0 预留**：`Entity::value == 0` 恒为空句柄；分配器起点为 1。
3. **组件池键**：`Object_Pool<C, uint32_t>` 的键为 `owner`，构建时由对象池强制写入，避免调用方漏写。
4. **遍历安全**：遍历期间禁止直接增删；使用 `Command_Buffer` 延迟到遍历结束后提交。
5. **组件类型上限**：掩码为 64 位，最多注册 64 种组件。
6. **线程**：不含同步原语，由调用方保证单线程访问。

## 六、模块运行链路详例

### 6.1 创建实体并挂组件

1. `entity_create()` → `Entity_Table` 分配槽位、置存活、返回句柄；
2. `component_add<C>(entity, args...)` → 注册/获取存储 → 构造组件 → `pool.build(entity.index(), component)` → 置掩码位；
3. 返回组件指针。

### 6.2 遍历中销毁实体

1. 遍历 `component_each` / `each`；
2. 需要销毁时调用 `Command_Buffer::entity_destroy(entity)` 入队；
3. 遍历结束后 `flush(store)` → 逐个 `entity_destroy` → 逐组件池 `erase(index)` → 实体表回收槽位并推进代际。

### 6.3 双组件遍历

`each<C1, C2>` → 取两个存储 → 以较小池为驱动 → 对每个组件用 `owner` 还原实体句柄并查另一组件 → 二者都存在才回调。
