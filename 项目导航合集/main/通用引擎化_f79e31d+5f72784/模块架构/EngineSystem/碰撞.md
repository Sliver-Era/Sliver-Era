## 一、模块功能介绍

碰撞模块位于 `Engine/EngineSystem/src/collision/`，是引擎的**纯检测层**：负责碰撞空间、碰撞体、运动推进与碰撞结果输出，不做物理求解，也不隐式创建或销毁任何逻辑对象。

模块分为三层：

| 子模块 | 职责 |
| --- | --- |
| `Collider/` | 碰撞体前端数据与 `Collider_Backend`；后端持有 Bullet 碰撞对象、几何形状与子部件对象 |
| `Collision_Region/` | 一个空间一个独立 `btCollisionWorld`；持有静态三角网格边界，执行扫掠/离散检测、跨越状态判定 |
| `Collision_Proxy/` | 对外门面：空间与编号编排、运动登记与下发、检测入口、事件协议收发 |

配套的 `Common/` 提供零 Bullet 的公共类型与事件词表。

设计边界：

- **Bullet 只允许出现在 `*/backend/**` 与 `Common/数学转换.h`**，前端与公共头不出现任何 `bt*` 类型。
- 碰撞结果既可由公共 API 同步取回（`Collision_Detail`），也可经事件发布（`DetectResult`）；后者默认开启，可按空间关闭。
- 引擎不自动销毁逻辑对象：碰撞体卸载、空间卸载全部由外部显式调用。

### 2.3 `Collider` 与公共类型

- `Collider`：`ID`、`backend`、`motion`、`part_motions`、`motion_frequency`、`motion_frame`、`motion_step`、`part_motion_steps`、`detection_mode`、`exemption_flag`、`geometry`。
- `Detection_Mode`：`is_swept_volume`、`step_length`。
- `Motion`：`translation` ＋ `rotation`（四元数）；`Part_Motion`：`part` ＋ `Motion`；`Motion_Event`：`body` ＋ `parts`。
- `Collision_Result` / `Collision_Contact` / `Collision_Detail`：碰撞对与接触点（含 `part_A` / `part_B`、世界点、世界法线、穿透深度、扫掠比例）。
- `Cross_State` / `Cross_Notice` / `Cross_State_Entry`：跨越状态、通知与查询快照。

```
    ├── 碰撞代理器.h                  ← 运动登记、结果事件开关、事件终端
    ├── core/事件交互.cpp、运动管理.cpp、碰撞体管理.cpp、碰撞体配置.cpp、
    │        空间管理.cpp、空间边界与配置.cpp
    └── backend/                      ← 空间集合、编号归属、编排
```

所有权与地址稳定性：

- `Collider`、`Collision_Region`、`Collider_Backend`、`Region_Backend` 都以 `unique_ptr<Impl>` 持有实现体；句柄搬移不改变实现体地址，Bullet 回调中的 `userPointer` 始终有效。
- 每个几何部件分配独立 `Geometry_Part_Object`（堆上 `unique_ptr`），`object.setUserPointer(this)`；禁止放入可扩容容器。
- `Region_Backend::Impl` 持有 `set<Collider_Backend*> attached`，析构时先逐个摘除再释放世界；`Collider_Backend` 析构若仍有 `owner` 会主动摘除，两种析构顺序均有测试覆盖。

## 五、模块设计与实现细节

### 5.1 几何与子部件

- 支持形状：`box`、`sphere`、`capsule`、`cylinder`、`cone`、`mesh`。
- 几何配置可为单个对象，也可为 `geometries` 数组；数组形式下顶层 `position` / `rotation` 为碰撞体基准变换，元素内为相对变换。
- 每个几何元素可带 `part_ID`（`uint16_t`，`0xFFFF` 为无子部件哨兵）；缺省按未占用最小值分配，重复或越界整条配置拒绝。
- `part_ignore` 为子部件对称忽略对，内部按 `(较小号 << 16 | 较大号)` 归一化。

### 5.2 宽阶段豁免

`Region_Overlap_Filter` 替换默认重叠过滤：

- 先保留 Bullet 内置的过滤组 / 掩码检查；
- 同一碰撞体：命中 `part_ignored` 对称忽略对则返回 `false`；
- 不同碰撞体：两侧 `exemption_flag` 非零且相等则返回 `false`；
- 豁免在窄阶段之前生效，被过滤的配对不进入流形；豁免标记变更后通过重挂对象强制重建配对。

### 5.3 检测执行

`Collision_Region::detect_detail`：

1. 空间无效或未激活直接返回 `nullopt`；先 `updateAabbs()`。
2. 读取逻辑帧号与逻辑帧率，对每个碰撞体计算本帧运动：
   - `motion_frequency == 0` 或帧率不可用：本帧施加量 = 已存运动总量；
   - 已配置频率：未到 `frame_rate / frequency` 间隔时本帧零运动；生效帧按频率拆分整体与部件运动。
3. 组织移动清单：
   - `all_moves`：所有本帧有运动的碰撞体；
   - `swept_moves`：仅纯平移、无部件运动且 `is_swept_volume` 的移动体。
4. `swept_collect`：对每个凸包部件按 `step_length` 分段扫掠；三角网格部件不参与扫掠；命中边界只登记 `swept_contacts`。
5. `discrete_run`：取最大段数，逐段就地推进整体与部件运动，每段执行 `performDiscreteCollisionDetection()`；从流形提取接触点。
6. 不再做后置豁免过滤（已前移）。
7. `cross_state_update` 更新跨越状态并收集通知。

结果约定：

- 碰撞对编号归一化为较小号在前；同一对复用一条 `Collision_Detail`。
- 法线统一为「由碰撞体 B 指向碰撞体 A」；编号交换时自动翻转。
- 穿透深度取 `-m_distance1` 并钳零；扫掠无穿透深度，`fraction` 为命中比例；离散 `fraction` 恒为 1。
- 同一碰撞体允许自碰，此时 `collider_A == collider_B`，两侧 `part` 不同。

### 5.4 空间边界与跨越

- 边界是编号 0 的静态 `Collider_Backend`，几何为世界坐标三角网格；不参与碰撞对输出。
- 包含性判定：从探针点沿固定斜方向发射射线，统计与边界对象的交点数，奇数为内。
- 跨越判定：
  - 与边界接触时取包围盒中心 ＋ 八顶点共九探针：全内 `inside`、全外 `outside`、混合 `crossing`；
  - 未接触时以包围盒中心射线奇偶判定。
  - 未移动、未穿越、未标脏且已有基准时沿用旧状态。
  - 扫掠穿越边界会补报 `cross`；最终在外补 `exit`、最终在内补 `return`。
  - 首次判定只建立基准，不发通知。
- 空间停用、边界重建会清空跨越状态与待发通知；几何重建把该碰撞体标脏。

### 5.5 运动登记（本版次重点）

运动状态由两处数据构成：

1. **代理器登记**：`Collision_Proxy::motion_records`，键为碰撞体编号，值为 `Motion_Record{ Motion_Event event; uint64_t frequency; }`。
2. **空间缓存**：`Collider` 内的 `motion` / `part_motions` / `motion_frequency` / `motion_frame` / 本帧施加量。

更新规则：

- **只有新的 `ColliderMotion` 载荷才会更新运动**：`motion_register` 解析、校验一次后写入 `motion_records`，并一次性下发到持有该编号的空间。
- **未收到新载荷时持续沿用**：检测链路不读取代理器、不解析 JSON，直接使用空间内已存的运动量；`frequency` 决定每个逻辑帧间隔施加多少。
- 同编号新事件覆盖旧登记；不做队列、不做超时。
- 几何重建后按子部件存在性裁剪部件运动并重新下发，整体运动保留。
- 离散步长归零时，含旋转或部件运动的登记被清除，并同步清空空间内运动。
- 碰撞体卸载且已无空间持有该编号时丢弃登记，避免编号回收后被新碰撞体继承；空间卸载后逐编号复查归属并清理。

运动语义：

- `motion` / `parts` 至少提供一项，可同时出现；`rotation` 为零四元数非法。
- 含旋转或部件运动时，目标碰撞体必须显式配置 `step_length > 0`，否则整条拒绝。
- `parts[].part` 必须是已存在的子部件编号，越界整条拒绝；同编号后者覆盖前者。
- `frequency` 可选，必须整除逻辑帧率；非法值退回 0（每次检测施加全量运动）。
- 运动量是「每周期总量」而非速度：未配置频率时，实际速度取决于 `region_detect` 的调用频率。

### 5.6 事件与配置

- `attach()` 订阅：`Config/Load` ＋ 上述全部入站碰撞标签；模块名 `Collision_Proxy`。
- `Config/Load` 的载荷为 `regions` 数组，逐空间执行：构建空间 → 活跃性 → 结果事件开关 → 边界 → `colliders` 数组逐个构建并应用配置。
- 边界配置文件为数组，元素含 `region` 与 `mesh_path`。
- 碰撞体配置字段：`geometry`、`detection_mode{ is_swept_volume, step_length }`、`exemption_flag`。

## 六、模块运行链路详例

### 6.1 事件驱动的构建与检测

```
ColliderBuild(region)
  → Collision_Proxy::collider_build
  → Proxy_Backend::collider_build
  → Collision_Region::collider_build（Number_Pool 分配编号、登记映射）
  → 发布 ColliderBuildResult{ region, collider_ID }

ColliderSet{ geometry, detection_mode, exemption_flag }
  → Collision_Proxy::collider_config_apply
  → Collision_Region::collider_set(geometry)
      → Collider_Backend::geometry_build（暂存装配）
      → geometry_mount（替换当前几何）
      → 留档 geometry、标脏跨越状态、挂入世界
  → 按子部件存在性裁剪运动登记并 motion_apply
  → 应用到持有该编号的全部空间

ColliderMotion{ collider_ID, frequency?, motion?, parts? }
  → Collision_Proxy::motion_register
  → 解析/校验 → motion_records[ID] = {event, frequency}
  → collider_set_dispatch：先 collider_frequency_set，再 collider_motion_set

RegionState{ active: true } 后 RegionDetect（公共 API）
  → Collision_Proxy::region_detect
  → Region_Backend::region_detect
  → Collision_Region::detect_detail
      → 运动门控（频率拆分）
      → swept_collect / discrete_run
      → cross_state_update
  → 取走跨越通知并发布 RegionCrossNotice
  → 若结果事件开启，发布 DetectResult{ region, frame, results[] }
  → 返回 vector<Collision_Detail>
```

### 6.2 无新事件时的持续运动

1. 第一次 `ColliderMotion` 写入 `motion_records` 并下发到空间，`Collider::motion` 保存运动总量。
2. 第一次 `region_detect`：按 `frequency` 计算本帧施加量并推进碰撞体。
3. 第二次 `region_detect` 之前没有新事件：检测直接复用 `Collider::motion`，再次施加同一运动量。
4. 只有新的 `ColliderMotion` 才会覆盖空间内的运动；卸载/步长归零/几何裁剪是仅有的清理路径。

### 6.3 跨越通知

```
边界接触/扫掠穿越 → cross_state_update
  → 九探针或射线奇偶得到当前状态
  → 与旧状态比较：cross / return / exit
  → Cross_Notice{ collider_ID, kind, previous, position, frame, sequence }
  → region_detect 取走并发布 RegionCrossNotice
```

## 七、已知限制与待确认

1. 九探针取世界 AABB 顶点，旋转盒体或球形碰撞体在凹角处存在极小概率误判。
2. 同一检测帧可能产生两条通知（`cross` + `exit` / `cross` + `return`），外部不得假设一帧一条。
3. 首次判定静默建立基准；初始即在空间外的碰撞体不会主动发事件，需外部主动查询一次。
4. `RegionCrossStateQuery` 的同步语义依赖事件中转站的同步派发实现。
5. 扫掠只覆盖凸包部件；三角网格部件只能走离散推进。
6. 每个碰撞空间是独立 `btCollisionWorld`，空间之间不互相检测，只能经转移/镜像搬移。
7. 运动登记以数字编号为键；不同空间可能持有同一数字编号，此时登记会下发到全部持有者。
8. 转移会复制几何、检测方式、豁免标记、运动量与作用频率；镜像会复制几何、检测方式与豁免标记，但不复制运动（新编号从静止开始）。镜像的新编号经公共 API 出参或 `ColliderBuildResult` 事件回告；转移/镜像失败均已回滚占位碰撞体。
