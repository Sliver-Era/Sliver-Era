# 骨骼与蒙皮 · 模块架构

> 模块路径（相对源码根）：`Engine/EngineSystem/src/world/skeleton/`
> 本模块按「共享资产 + 每演员姿态 + 骨骼碰撞链接 + 求值系统」四层拆分，挂载到 ECS。
> 坐标空间统一为演员根局部空间；世界变换由调用方通过碰撞整体运动或渲染实例矩阵承担。

## 二、模块功能介绍

| 子模块 | 文件 | 定位 |
| --- | --- | --- |
| `Skeleton_Asset` | `骨骼资产.h` | 多演员共享的只读骨骼资产（骨骼表、绑定姿态、逆绑定矩阵、部件绑定模板） |
| `Skeleton_Pose` | `骨骼姿态.h` | 每演员一份的 ECS 组件：资产引用、逐骨骼局部变换、世界矩阵、蒙皮矩阵 |
| `Skeleton_Link` | `骨骼链接.h` | 每演员一份的 ECS 组件：目标碰撞体、逐部件绑定、上一帧矩阵、本帧运动量 |
| `Skeleton_System` | `骨骼系统.h` | 资产登记、演员挂载、姿态写入、帧求值与只读查询 |
| `Common` | `骨骼数学.h` | 矩阵/四元数等骨骼数学工具 |

## 三、模块公开接口介绍

### 3.1 `Skeleton_Asset`

- `Skeleton_Bone`：骨骼名、父下标、绑定局部变换、逆绑定矩阵、`Bone_Part_Binding`（`part_ID == 0xFFFF` 表示不绑定碰撞部件）；
- 静态入口：`load_file(path, asset)` 从 JSON 文件加载，`build(config, asset)` 从 JSON 内容构建；失败时清空输出并返回假；
- JSON 键：顶层 `name` / `bones`；骨骼项 `name` / `parent` / `translation` / `rotation` / `scale` / `inverse_bind` / `part`；
- 校验：父下标必须小于自身下标、骨骼名唯一、四元数非零、缩放非零、`part_ID` 唯一且不取哨兵；骨骼数 ≤ 4096、文件体量 ≤ 16MB；
- `inverse_bind` 缺省时由绑定世界矩阵求逆推导，显式提供时原样采用；
- 资产编号由系统分配（从 1 起，0 无效）。

### 3.2 `Skeleton_Pose`

- 字段：`owner`（对象池写入的实体槽位）、`asset`（共享只读资产）、逐骨骼局部平移/旋转/缩放、`world_matrix`、`skin_matrix`、`pose_dirty` / `skin_dirty`；
- 接口：`build(asset)`、`bone_count()`、`reset()`、`local_set` / `translation_set` / `rotation_set` / `scale_set`、`world_get(bone, out)`；
- 局部变换按「先缩放、再旋转、最后平移」作用于父骨骼空间。

### 3.3 `Skeleton_Link`

- 字段：`owner`、`collider_ID`（0 表示只做姿态/蒙皮）、`links`（`Skeleton_Part_Link`：部件编号、骨骼下标、相对变换）、`previous_matrix`、`motions`（`Skeleton_Part_Motion`：部件编号、平移/旋转增量）；
- 接口：`build(asset, collider_ID, pose)`、`link_count()`。

### 3.4 `Skeleton_System`

| 接口组 | 行为 |
| --- | --- |
| 资产 | `asset_add` / `asset_load_file` / `asset_remove` / `asset_get` / `asset_count`；资产编号不回收，槽位可置空 |
| 演员 | `actor_attach(store, entity, asset_ID, collider_ID = 0)`：创建姿态组件，必要时创建链接组件；`actor_detach`：移除组件，不销毁实体 |
| 姿态写入 | `bone_local_set` / `bone_rotation_set` / `pose_reset` |
| 事件 | `store_bind(store)` 绑定命令用存储；`attach()` 接入事件中转站并订阅命令；`event_output_set/get` 控制运动发布；发布 `Collision/ColliderMotion`（根部 `motion` ＋ 部件 `parts`） |
| 帧求值 | `frame_update(store)`：姿态 → 蒙皮 → 部件运动 → 事件发布；仅在脏标记置位时重算姿态 |
| 查询 | `pose_matrix_get` / `skin_palette_get` / `part_motions_get`（指针在下一次帧求值前有效） |

### 3.5 事件命令协议

类别 `Skeleton`，外部经事件中转站驱动，模块以 `AssetLoadResult` / `ActionResult` 回告；所有命令与直接 C++ 接口一一对应，二者可混用。

| 命令标签 | 必要字段 | 结果 |
| --- | --- | --- |
| `AssetLoad` | `path`（`request_ID` 可选） | `AssetLoadResult`：`asset_ID`、`success`、`request_ID` |
| `AssetAdd` | `config`（资产 JSON；`request_ID` 可选） | `AssetLoadResult`：`asset_ID`、`success` |
| `AssetRemove` | `asset_ID` | `ActionResult` |
| `Attach` | `entity`、`asset_ID`（`collider_ID` 可选） | `ActionResult` |
| `Detach` | `entity` | `ActionResult` |
| `BoneLocalSet` | `entity`、`bone`、`translation[3]`、`rotation[4]`（`scale[3]` 可选） | `ActionResult` |
| `BoneRotationSet` | `entity`、`bone`、`rotation[4]` | `ActionResult` |
| `PoseReset` | `entity` | `ActionResult` |
| `EventOutput` | `enabled` | `ActionResult` |
| `FrameUpdate` | 无（`request_ID` 可选） | `ActionResult` |

- `entity` 为实体句柄打包值（`Entity::value`）；除资产类命令外均要求先 `store_bind`，未绑定则回告 `success = false`。

## 四、模块内部架构介绍

### 4.1 资产槽位

`assets` 为 `vector<shared_ptr<const Skeleton_Asset>>`，下标 = 资产编号 - 1；卸载只置空槽位，编号不再复用。已挂载演员持有的共享指针继续有效。

### 4.2 ECS 组件

- `Skeleton_Pose` 与 `Skeleton_Link` 都是 `Component_Type`：含 `owner` 字段、可移动；
- 通过 `ECS_Store::component_add<C>` 挂载，`owner` 由组件池写入；
- 查询时用 `component_get<C>` 取组件，再按演员根局部空间读取矩阵/运动量。

### 4.3 求值顺序

```
frame_update
  → pose_evaluate（脏标记置位时重算世界矩阵）
  → skin_evaluate（脏标记置位时重建调色板）
  → link_evaluate（根部与部件增量）
  → motion_publish（已接入中转站且开关开启时发布 Collision/ColliderMotion）
```

同一逻辑帧内必须先 `frame_update`，再执行碰撞检测；顺序颠倒会使用上一帧骨骼位置。

## 五、模块设计/实现细节

1. **三层拆分**：共享资产、每演员姿态、骨骼-碰撞映射分离；不把整块骨骼系统作为单一组件。
2. **粗粒度部件**：仅为关键部位创建碰撞子部件，避免窄相位开销失控。
3. **碰撞系统无感知**：骨骼系统只产出 `Skeleton_Part_Motion` 中立数据，碰撞系统不引用骨骼类型。
4. **根局部空间**：所有矩阵与运动量都在演员根局部空间；系统不感知世界变换。
5. **脏标记**：姿态与蒙皮各自维护脏标记，未变化时不重复求值。
6. **线程**：与 ECS 存储一致，不做内部加锁，由调用方保证单线程访问。
7. **运动量语义对齐碰撞侧**：平移取「本帧原点 − 上一帧原点」，旋转取「上一帧逆 × 本帧」的旋转差；碰撞侧按「绕自身原点旋转、再按轴平移」施加，直接用矩阵复合增量会产生旋转-平移耦合错误。
8. **根部与部件分离**：根部增量走 `motion`，部件局部矩阵相对根骨骼计算并走 `parts`，避免根运动在整体与部件上被重复施加。
9. **事件开关**：未接入中转站或开关关闭时不发布；`frame_update` 内的发送失败只告警，不影响姿态与蒙皮求值。
10. **双入口**：公开 C++ 接口与事件命令复用同一实现；事件入口只做字段解析与结果回告，不复制业务逻辑，调用方式不被卡死。

## 六、模块运行链路详例

### 6.1 演员挂载

1. `asset_load_file(path)` → 资产编号；
2. `actor_attach(store, entity, asset_ID, collider_ID)`：
   - 创建 `Skeleton_Pose` 并 `build(asset)`；
   - `collider_ID != 0` 且资产含部件绑定时创建 `Skeleton_Link` 并 `build(asset, collider_ID, pose)`；
   - 绑定姿态在挂载时完成首次求值，作为部件运动基准。

### 6.2 逐帧驱动

1. 调用方写入骨骼局部变换（`bone_local_set` / `bone_rotation_set`）；
2. `frame_update(store)`：姿态求值 → 蒙皮求值 → 部件运动求值 → 运动事件发布；
3. 已 `attach()` 且开关开启时，运动量自动以 `Collision/ColliderMotion` 发布；未接入时可用 `part_motions_get` 手动转投；
4. `skin_palette_get` 取蒙皮调色板，转交渲染层。

### 6.3 事件命令路径

1. `store_bind(store)` 与 `attach()`；
2. 发送 `Skeleton/AssetLoad{path}` → 收 `AssetLoadResult{asset_ID}`；
3. 发送 `Skeleton/Attach{entity, asset_ID, collider_ID}` → 收 `ActionResult`；
4. 发送 `BoneLocalSet` / `BoneRotationSet` / `PoseReset` 写入姿态；
5. 发送 `FrameUpdate`（或直接调用 `frame_update`）→ 姿态、蒙皮与运动事件一并刷新。

## 八、边界与后续

1. **仅 CPU 求值**：GPU 蒙皮管线（顶点关节索引/权重、调色板缓冲、着色器顶点变换）未实现；System 只产出调色板。
2. **蒙皮数据来源**：OBJ 顶点不含关节权重，glTF 加载器仍跳过 skins / animations；逐顶点蒙皮需先扩 Foundation 导入。
3. **动画剪辑**：本期不提供剪辑采样，姿态由调用方逐骨骼写入。
4. **碰撞转发**：已内置 `attach()` 自动发布 `Collision/ColliderMotion`；未接入中转站时仍可用 `part_motions_get` 手动转发。要求碰撞体存在、部件编号存在且碰撞体离散步长非零；根部运动量位于演员根局部空间，演员存在上层变换时需调用方换算为世界轴。
5. **事件命令前提**：演员与姿态类命令要求先 `store_bind`；资产类命令不依赖存储。事件命令与直接 API 可混用，不存在单一路径限制。
5. **资产格式**：一期为 JSON；glTF 蒙皮/骨架扩展留待资产导入轮次。
